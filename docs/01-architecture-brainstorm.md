# OpenTAP Architecture Brainstorm 01

Date: 2026-10-12. Lead architect: Fable 5.1. Workers: Opus-Network, Opus-Storage, Opus-Consensus, Opus-Security.

How this was produced: the four personas brainstormed independently, then each cross-examined the other three, then 32 load-bearing technical claims were fact-checked by independent skeptics with web access (8 confirmed, 24 confirmed with corrections, 0 refuted), then each persona revised its position, then two critics (a completeness critic and an ONTAP veteran) mapped gaps and conflicts. 46 agents in total. The full record, including every critique, every fact-check with sources, and every rebuttal, is in `01-architecture-brainstorm-record.md`. The personas ran as workflow subagents on the session model; "Opus" is the role name.

Status of the plan after this round: the architecture's bones survive (N-Blade/D-Blade split, log plus Consistency Point, Raft control plane, Rust daemons, abstracted transport). Three premises of the brief do not survive as written: a RAM mirror is not RPO=0, node-local disks cannot do ONTAP-style takeover, and Fibre Channel cannot be the primary interconnect on a stock Rocky kernel and buys no latency. Each is detailed in the synthesis, with the decisions the project owner must make.

## Part 1. Opus-Network (Transport and Replication Specialist)

### Executive take
Build the mirror as an idempotent, slot-addressed append into a fixed ring in the partner's NVLOG memory, with sequencing, epoch fencing and redelivery above the transport, so that TCP, FC and RDMA are all "put these bytes at this ring offset and tell me when they are there". Phase 1 ships two transports: a busy-polled TCP ring, and a "BlockRing" that writes the partner's ring through an in-box NVMe-oF target namespace backed by a DAX file on the partner's persistent memory. The BlockRing is the FC path: the same code runs over nvmet-tcp today and over nvmet-fc on an Emulex HBA later. The thing the brief gets most wrong is treating FC as the performance goal: through any Linux target stack an FC mirror write lands at 50 to 150 us, slower than busy-polled 10GbE TCP and roughly ten times slower than 25GbE RoCE. FC buys isolation and distance, not speed.

### Proposed libraries and subsystems
Kernel, verified against the Rocky r9 and r10 kernel configs:
- `nvmet` with FC, TCP, RDMA, loop and fcloop as modules on both Rocky 9 and 10. The `lpfc` driver builds its NVMe target when `NVME_TARGET_FC` is enabled (`lpfc_enable_nvmet=<WWPN list>`); a port is target or initiator, never both.
- `tcm_qla2xxx` is **not built** on Rocky 9 or 10, and neither is `efct` (Emulex SCSI target). The QLogic target core is compiled into `qla2xxx.ko`, so an out-of-tree `tcm_qla2xxx` is a small module, but its symbols are not kABI-stable: rebuild and Secure Boot signing on every kernel update.
- `target_core_user` (TCMU) is in-box on both; `ublk` is Rocky 10 only; `io_uring` is built on both but `kernel.io_uring_disabled=2` by default on 9.4+ and on 10.x.
- pmem/DAX (libnvdimm, devdax, fsdax) on both; `memmap=16G!64G` emulates pmem from DRAM on dev boxes; `mlx5_ib` plus rdma-core for RoCE; NVMe native multipath for dual paths at zero code.

Rust: `io-uring` 0.7 (raw SQ/CQ; `UringCmd80` for NVMe passthrough) as the data-path primitive; `tokio` for control plane only; `socket2` for `TCP_NODELAY`, `SO_BUSY_POLL`, `TCP_QUICKACK`, `SO_INCOMING_CPU`; `zerocopy` 0.8 for 64-byte headers; `bytes`; `crc32c` 0.6 (hardware, over 10 GB/s); `memmap2` for DAX; `libublk` 0.4.7 for the front door; RDMA via `rdma-sys` plus a 1K-line in-house wrapper (PD, MR, RC QP, CQ, rdma_cm) or `sideway` 0.4.3 (MPL-2.0); avoid `async-rdma` (GPL). RPC: custom framing on the data path; `tarpc` 0.36 or `tonic` 0.13 for admin; `capnp-rpc` is single-threaded and unusable on the data path; `iceoryx2` is a credible same-node zero-copy IPC if we do not own the ring. `spdk-rs` only if SPDK's experimental FC transport (which needs Broadcom's out-of-tree userspace driver) is ever chosen.

Hardware: Emulex LPe32002/35002 for the in-box nvmet-fc path; QLogic QLE2692/2772 only with an out-of-tree module. 16GFC is 1,600 MB/s per port, 32GFC 3,200 MB/s, max frame payload 2,112 B. Mellanox ConnectX-5/6 25GbE for RoCE; Intel X710 for TCP. NVDIMM-N on the R740xd: 12 x 16 GB = 192 GB maximum, battery mandatory, two CPUs, 12 RDIMMs minimum, ADR only (no eADR).

### Proposed architecture
One abstraction, a remote ring rather than a stream. The partner reserves a fixed byte ring per owner in its NVLOG arena. The owner appends self-describing records at ring offsets it chooses; the transport's only job is to put bytes at an offset and complete when they are there. Nothing is in-order or exactly-once: a record is valid when its header and payload CRCs verify, so duplicates and reordering are harmless, which is what lets FC (commands complete out of order), RDMA and multipath fit without special cases.

```rust
pub struct Caps { pub ack: AckLevel /* Placed | Durable */, pub max_msg: u32, pub max_inflight: u32, pub can_reject: bool }
pub enum Done { Ok { tag: u64 }, Rejected { tag: u64, partner_epoch: u64 }, Failed { tag: u64 }, LinkDown }
pub trait RemoteRing: Send {
    fn caps(&self) -> Caps;
    fn put(&mut self, slot: Slot, iov: &[IoSlice<'_>], tag: u64) -> Result<(), Busy>;
    fn kick(&mut self);
    fn poll(&mut self, out: &mut Vec<Done>, max: usize) -> usize;
    fn fail_all(&mut self) -> Vec<u64>;   // fate unknown: quarantine the slots, redeliver to fresh ones
}
```
`MirrorLog` owns seq, epoch, slot allocation, timer-free batching, deadlines, the link set and the state machine; it never sees sockets, LBAs, rkeys or fds.

Three implementations. TcpRing: a pinned thread per link, blocking `sendmsg` with iovecs straight from the arena, receiver `readv`s into the inbound ring, `clwb` plus `sfence`, acks `{upto_seq, consumed}`; busy-poll sysctls; io_uring multishot and `SEND_ZC` later on Rocky 10. BlockRing: the partner exposes its inbound ring as an nvmet file-backed namespace on an fsdax file; the sender writes with io_uring `pwritev` O_DIRECT plus FUA at `offset = slot`; the kernel DAX copy path lands the bytes in the persistence domain with no userspace receiver; dual paths come from NVMe native multipath; exported over nvmet-tcp now, nvmet-fc or nvmet-rdma later. VerbsRing: RC queue pair per link, arena registered as one memory region, `RDMA_WRITE_WITH_IMM` to the slot, receiver flushes the range and posts a SEND ack.

Semantics: ack levels `Placed` (partner DRAM) and `Durable` (partner pmem or PLP log after flush), a cluster-wide logged setting. Every record and RPC carries the owner epoch. Flow control is bytes of ring space. Group commit is driven by in-flight count, not timers. Partner unreachable: Mirrored to Stalled (no acks) to Unmirrored only on a control-plane decision, never on the data path's own authority.

Phase 3 RPC: same-node N to D over a `memfd` hugepage arena and an SPSC ring with an eventfd doorbell (2 to 5 us); cross-node over a dedicated link multiplexed by request id; every RPC carries the volume's owner generation and a stale answer returns `StaleOwner` for a safe retry; mirror and RPC share the framing layer but never a connection, so a slow RPC consumer cannot stall mirror acks.

### Bottlenecks, with numbers
Wire serialization for 4 KiB: 32.8 us on 1GbE, 3.3 us on 10GbE, 1.3 us on 25GbE, 2.3 us on 16GFC. Round trip for one 4 KiB mirror write at QD1: 1GbE TCP 90 to 110 us; 10GbE TCP interrupt-driven 40 to 55 us; busy-polled 20 to 30 us; 25GbE RoCE write-with-immediate 5 to 7 us; 16GFC through nvmet-fc to a DAX file 50 to 100 us; 16GFC through tcm_qla2xxx plus TCMU 80 to 300 us. FCP writes cost two fabric round trips (command, XFER_RDY, data, response). Queue depth to saturate 10GbE with 4 KiB at 40 us is about 12 records, but 4 KiB at line rate is 305k messages per second, so batching to 64 to 256 KiB is mandatory. A single 10GbE mirror link carries about 1.1 to 1.2 GB/s of payload, which is at or below a tuned 12-drive array's flush rate: the pair's write ceiling is min(front-end link, mirror link, tuned flush rate). NVLOG ring sizing: ingest x (CP interval plus maximum CP duration) plus quarantine. One busy-polled core per link per node is the price of a 20 us round trip. ADR-only platform: every receive path must `clwb` and `sfence` before claiming Durable (about 1 to 2 us per 64 KiB).

### Creative solutions
- The DAX file as the mirror target: the partner's persistent memory becomes addressable over FC, TCP and RDMA with in-box kernel targets and no userspace receive path. It is FC-VI's "remote DMA into NVRAM" without NetApp's firmware. The same path mirrors to a third site over NVMe/TCP for asynchronous DR later.
- `memmap=` pmem emulation on every dev box, so the fsdax plus flush code path is exercised long before NVDIMM parts arrive.
- Slot-idempotent records make multipath, mixed transports and redelivery free: two FC links, or FC primary plus NVMe/TCP standby, are just two rings in the link set.
- Timer-free group commit: batch only while a batch is in flight; one round trip at idle, line rate under load, no tunables.
- Skip raw verbs at first in Tier 3: nvmet-rdma to the DAX file is the same BlockRing at 15 to 25 us; raw `RDMA_WRITE_WITH_IMM` is a further 2 to 3x that costs a verbs wrapper and a receiver hot loop.
- `IORING_OP_URING_CMD` NVMe passthrough to skip the block layer once the BlockRing works.

### Holes poked in the plan
- FC is not the fast path, and the implied QLogic plus LIO route is out-of-tree on Rocky. Decide now: Emulex nvmet-fc in-box but Red Hat-unsupported, or ship our own kernel module, or demote FC.
- RAM-only write caching has a common-mode failure: two nodes on one PDU lose up to one CP interval of acknowledged writes. Define the ack against NVDIMM-N or a PLP NVMe log, and downgrade acks when the battery or device is not armed, as ONTAP does.
- Two-node Raft cannot elect after one failure. Add a witness vote.
- Node-local disks break takeover: the partner holds the last CP interval of writes, not the volumes. The choice between shared shelves and full replication must precede Phase 1's flow-control design, because the partner-side consumer differs.
- "Stateless N-Blade" is coherent only as "no durable state": sessions die with the N-Blade and initiators re-login; persistent reservations, LUN maps and ALUA state must live in the D-Blade or cluster database.
- Roadmap ordering: Phase 1 cannot be tested end to end without a front door and a minimal RPC, and the record format is shared by Phases 1 and 2. Define the record and RPC headers in Phase 1.
- 1GbE prototyping hides the real problems: at 125 MB/s and 100 us round trips, batching, queue depth and core pinning never matter.
- Direct-connect FC target mode between two stock HBAs is the biggest unknown in this area; budget a pair of used FC switches as the fallback.
- Replay after takeover applies logical records through the partner's allocator, so the record must be logical (volume, LBA, data), never physical extents.

### What cross-examination and fact-checking changed
Conceded: dense packed records misalign every payload after the first for O_DIRECT and `WRITE_FIXED`, which would turn every CP flush into a memcpy, so payloads are 4 KiB-aligned with a parallel descriptor ring. fsdax mappings cannot be long-term pinned (io_uring buffer registration and RDMA memory regions fail with EOPNOTSUPP on both 5.14 and 6.12), so the owner's NVLOG lives on devdax and only the kernel-written inbound ring is an fsdax file. Ring capacity must include CP duration, since space is reusable only after the superblock FUA. "Unmirrored only after the partner is fenced" was wrong: mirror link down with Ethernet up is two healthy nodes, and the precondition is a quorum-committed grant that disables takeover. BlockRing fencing was wrong twice: removing a host from nvmet `allowed_hosts` only changes discovery and leaves live controllers writing (only unlinking the subsystem from the port tears them down), and a record epoch cannot separate a zombie's late writes from the legitimate owner's earlier writes under the same epoch, so the fence is lease-at-ack plus port unlink, and epoch is replay cleanup. Slot reuse has an ABA hazard: a delayed duplicate can land on a reallocated slot and verify, so unknown-fate slots are quarantined until the carrying link's command lifetime expires. The data-path failure detector drives redelivery only, never takeover. lpfc ports are target or initiator, so bidirectional dual-path FC is four ports per node, and a write-only ring cannot carry Raft. Rocky 10 also disables io_uring by default. The quoted TCP bands were tuning artifacts (9 to 21 us tuned, up to 100 us with adaptive coalescing). lpfc point-to-point NVMe is a Broadcom-maintained path, so Emulex direct-connect is a comparable bet, not a worse one. NVDIMM-N is end-of-life, so pmem must be optional. The dual-use Rust TCMU handler was withdrawn (SBC/SPC emulation with ESXi and Windows interop is a product, not 1.5K lines). The zero-copy-through-ublk criterion was dropped (two kernel copies on 6.12).

Held: the slot-addressed, receiver-optional ring is the only contract under which in-box FC, NVMe multipath and RDMA write-with-immediate are one thing. Lazy CRC verification on the BlockRing is acceptable. FC is not the latency tier. Emulex nvmet-fc over QLogic tcm_qla2xxx. Rocky 10 and 10GbE from day one with a fixed tuning profile. Timer-free group commit, per-record crc32c, receive-side flush, and Placed/Durable as a logged cluster setting.

### Revised Phase 1 recommendation
Build `MirrorLog` over the shared record, `TcpRing`, `BlockRing` over nvmet-tcp with FUA on a pre-written fsdax file, the ublk front door behind LIO, the same-node SPSC ring and RPC header, and (if the owner confirms FC) a two-week spike on an LPe32002 pair in point-to-point mode. Prove on two R740xd-class nodes over 10GbE with 9000 MTU and fixed tuning: mirror 4 KiB QD1 TcpRing p50 at or under 35 us and p99 under 100 us; BlockRing with FUA p50 under 100 us; client 4 KiB QD1 through ublk and LIO p50 under 200 us (150 us target) and p99 under 500 us; 64 KiB QD8 at or above 1.1 GB/s mirrored; 4 KiB QD32 at or above 200k records per second with one core per side; CP flush from the devdax arena with zero staging copies; 10,000 fault iterations with zero acknowledged-but-unreplayed writes under a checker; mirror down with Ethernet up enters Stalled within 200 ms with no acks and no initiator session drop through a 10 s stall; link cut mid-stream redelivers over the surviving link with a clean seq audit.

Top risks: FC may be unsupportable as a product promise; NVLOG capacity versus CP duration; BlockRing fencing correctness rests on an unmeasured nvmet association teardown time; the 15 s stall-plus-takeover ceiling; latency is tuning-dominated and nobody has summed pinned cores for a two-socket SKU.

## Part 2. Opus-Storage (Block / Log-Structured Storage Specialist)

### Executive take
The D-Blade is three things in this order: a persistent, HA-mirrored, append-only NVLOG of operation records that carry the data, which is the only durability mechanism in the system; an in-RAM extent index over those records for read-your-writes and sorted CP assembly; and a log-structured segment store on md RAID6 written only as full stripes, with a copy-on-write extent map persisted as checkpoint plus deltas, and an NVMe tier that is not optional (NVLOG, hot map pages, read cache). The brief's throughput premise is wrong: 2 x 10GbE ingests about 2.2 GB/s, a 12-HDD RAID6 absorbs about 1.4 GB/s on older drives or about 2 GB/s on 16 TB-class CMR drives with tuned md, and 0.7 to 1.4 GB/s after garbage collection; 12 to 24 HDDs deliver only 1 to 6K random read IOPS. The write cache buys latency and about a minute of burst absorption, not sustained "network speed". The durability and HA framing is also wrong: a RAM mirror is neither RPO=0 under dual power loss nor useful on takeover with node-local disks.

### Proposed libraries and subsystems
- `io-uring` 0.7 with `WRITE_FIXED`, `FSYNC`, `IOPOLL` for the NVLOG NVMe, optional `SQPOLL`; hand-roll a thread-per-core reactor rather than adopt a runtime. `rustix`/`libc` for mmap, mlock, madvise, `pwritev2`, `BLK*` ioctls. `memmap2` for devdax and fsdax.
- Persistence instructions: stable Rust has no `_mm_clwb` and `_mm_clflushopt` is nightly-only; use non-temporal stores (`_mm_stream_si128`) plus `_mm_sfence` for bulk payload, and `asm!("clwb")` gated on CPUID (with `_mm_clflush` as the stable fallback) for the 8-byte header. Cascade Lake is ADR only: CPU caches are outside the persistence domain.
- `crc32c` (or `crc-fast`) per 4 KiB block and per record; `xxhash-rust` XXH3 or `blake3` for metadata pages and scrub digests.
- `parking_lot`, `crossbeam` (SPSC/MPSC queues, epoch), `arc-swap` for swapping active and frozen dirty sets.
- `BTreeMap<u64, Extent>` keyed by start LBA with split-on-overlap (`rangemap` as reference): ordered range scans dominate (CP assembly, overlap resolution); ART/radix structures win point lookups only; interval trees are unnecessary because normalized extents never overlap.
- `zerocopy`/`bytemuck` for `repr(C)` records and superblocks. Not `slab` or `bytes` on the data path: slots must be page-aligned, pinned, io_uring-registered memory.
- `hdrhistogram`, `metrics`/`prometheus`; `proptest`, `loom`, `cargo-fuzz`, Miri, `cargo-careful` on the arena and index crates.
- md raid456 tunables: `stripe_cache_size` up to 32768 (default 256 starves large sequential writes), `group_thread_cnt`, `skip_copy`. PPL is RAID5-only with up to a 30 to 40% write penalty; the md journal is the only md-native RAID6 write-hole closure and is a bandwidth single point of failure.
- Hardware: NVDIMM-N 12 x 16 GB (end of life); Optane PMem 100 (Cascade Lake only, end of life); Optane P4800X/P5800X (used market; 30 and 100 DWPD); NAND PLP NVMe (Micron 7450 MAX, Kioxia CD8/CM7, Samsung PM9A3; 1 to 3 DWPD); HBA330 is internal-only; MD1400/MD1420 shelves need an HBA355e or 12Gb SAS HBA, never a PERC, and take SAS/NL-SAS only.

### Proposed architecture
Principle: the NVLOG is the source of truth until a CP commits; the DRAM arena and the dirty index are a cache of it, rebuildable by replay.

Write flow: ingest arrives with per-4 KiB CRC32C computed at the edge; take the 1 GiB LBA-shard lock; assign a per-volume monotonic seq; copy into arena slots (4 KiB slots, 64 KiB slabs); build the record. Local persist and mirror append are issued concurrently (PMem: non-temporal copy, fence, header with seq last; NVMe: O_DIRECT with IOPOLL). When both complete, insert into the dirty index (superseded extents release their slots, so overwrite coalescing is free) and ACK. Visibility only after durability, so a read can never observe a write that a takeover would lose. The partner validates and indexes its inbound ring continuously on one core (a standby index, about 0.4 GB per CP), so takeover admits I/O after a residual scan of under a second rather than a 15 to 30 s cold replay.

Memory: per-socket pinned arenas (mlock, 2 MiB pages, registered with io_uring); generation-checked slot handles; the arena crate is the only `unsafe` crate. Active and frozen dirty generations swapped at CP start. Budget at 2 x 10GbE: 22 GB per 10 s CP, active plus frozen 44 to 66 GB, index about 0.4 GB per CP. Backpressure: CP at 10 s, or dirty at 50% of budget, or NVLOG ring at 50%; at 90% the ingest cores delay completions with a token bucket set to the measured flush rate; never fail a write; keep stalls under 5 s. Partial 4 KiB writes carry a sector mask and are filled from disk at CP time in a batched, sorted read pass.

CP commit: swap active and frozen; drain frozen sorted by (volume, LBA) into stripe-sized staging buffers written as full stripes only, each segment ending with a summary stripe (volume, LBA, seq, CRC per block); write the map delta run for the CP (24 B per extent, about 0.6% of a 22 GB CP); one `fdatasync` on the md device (a flush fanned to every member); write the superblock as a full stripe with the 4 KiB superblock replicated in every chunk, with O_DSYNC (FUA plus flush), alternating A/B slots; then a Status record retiring the NVLOG locally and on the partner. Startup verifies each member's `queue/fua` and `write_cache`, refuses PERC virtual disks (IT-mode HBA330 or HBA355e only), and tracks member error counters because md swallows member flush errors.

On-disk layout: chunk 256 to 512 KiB, stripe 2.5 to 5 MiB on 12 drives, segment 256 to 512 MiB; RAID6 over RAID10 because full-stripe log writes remove parity's write penalty while keeping 83% capacity; two 12-drive aggregates per 24-bay chassis (two CP streams, two failure domains, half the rebuild blast radius). Write hole closed by design: data stripes are never overwritten in place and become referenced only after the superblock commit, so a torn stripe is unreferenced garbage; keep the write-intent bitmap with a chunk at least the segment size. Map: per-volume copy-on-write B+tree, LBA to (physical address, length, CRCs), checkpoint pages plus per-CP delta runs; hot leaves in RAM, cold on NVMe. GC: cost-benefit selection, hot/cold separation, whole-segment sequential reads (about 0.2 s per 320 MB), explicit frees from overwrite, UNMAP and snapshot deletion. Read path: active, frozen, retained slots, NVMe read cache (2 x 3.84 TB, 16 KiB lines), map, HDD at QD 8 to 16 per member, with read reallocation of fragmented sequential ranges.

Client consistency: a write is durable when its record is persisted locally and acknowledged by the partner. SYNCHRONIZE CACHE and FUA are no-ops only when the NVLOG is persistent. Per-volume seq ordering. Snapshots as a `Snap` record pinning a root at the next CP boundary; clones as writable children; deadlists make freeing correct.

HA data model: production on dual-ported SAS shelves, md assembled on one node, fenced by reservations and iDRAC; takeover is assemble, apply the ring suffix, CP. Node-local deployments use a shadow plex fed by physical CP-segment shipping (the ONTAP Select shape), accepting identical geometry on both nodes, 2x writes on the partner array, and halved usable capacity and ingest.

### Bottlenecks, with numbers
A 22 GB CP takes 16 s at 1.4 GB/s and 24 to 32 s with GC, so under line-rate ingest CP duration exceeds the interval (back-to-back CPs) and a 64 GB dirty budget lasts 45 to 80 s; after that, throughput equals the array rate. Line-rate sustained writes need 36 to 48 spindles per node, meaning external shelves. Random reads: a 7.2K drive gives about 80 IOPS at QD1 and 150 to 210 at QD32; 12 drives give 1 to 2.4K IOPS; a 10GbE link can carry 300K; with a 95% NVMe hit rate the mean read is about 0.8 ms. Map size at 100 TB: 38 GB at 64 KiB average extents, 154 GB at 16 KiB, 600 GB at 4 KiB; this is the central scaling problem of every log-structured block store and why the SSD tier is mandatory. NVLOG device load is own ingest plus the partner's mirror, up to 2x ingest; endurance at 200 MB/s average is 17 TB/day, which a 1.6 TB 3-DWPD NAND drive survives for about 1.4 years and an 800 GB P5800X for about 23 years. Local persist per 64 KiB: PMem 5 to 10 us, Optane SSD 30 to 40 us, NAND PLP 50 to 100 us; persist must overlap the mirror round trip, not follow it.

### Creative solutions
- Shadow replica from the mirror: the partner already receives every mutation record, so with node-local disks the ring plus CP-segment shipping gives full data mirroring with no extra network traffic beyond the segments.
- PMem as the arena: DAX-map the NVLOG and let the dirty index point into it; the CP reads directly from pmem; no DRAM copy; an arena corruption bug cannot destroy the durable copy because there is only one copy.
- Superblock-in-a-stripe: the one in-place overwrite that the RAID6 write hole could hurt is replicated across a full stripe; recovery takes the highest valid CP from any chunk of either slot.
- Read reallocation: fragmentation from aging is repaired by rewriting blocks that a detected sequential stream needed many physical I/Os to read; writes are free in a log structure.
- Two aggregates per node; adaptive CP sizing (CP at min(10 s, dirty at 50%), idle CP after 2 s of quiet); discard as the cheapest GC; zoned checksum blocks if map-resident CRCs prove too costly.

### Holes poked in the plan
- A RAM write cache is not RPO=0: ECC survives bit flips, not power loss; dual PSU plus UPS is a policy, not a mechanism. NVLOG on persistent media on both nodes; DRAM-only is a labelled prototype mode.
- "Network speed" is a latency claim, not a throughput claim; re-scope to "ACK at SSD-class latency, absorb bursts, serve reads from an SSD tier" and plan spindle counts for sustained throughput.
- Node-local disks are incompatible with ONTAP-style takeover.
- Phase ordering hides the real decisions: the record format and persistence medium constrain the transport, so Phase 1 defines the record and ring protocol and the transport carries it.
- 1GbE prototyping proves nothing about the D-Blade: drive it with an in-process load generator at 2 GB/s or more, independent of the fabric.
- The write hole is not solved by "mdadm as a single block device"; PPL is RAID5-only, a journal device is a bandwidth single point of failure, and md hides member flush failures.
- NAND NVLOG endurance is a time bomb at moderate sustained ingest.
- The map, not the write cache, is the real memory consumer.
- Partial and misaligned writes cost a disk read each at CP time: 512e LUNs with a 4 KiB physical exponent so guests align.
- Memory-safety bugs in unsafe arenas are a data-integrity risk: CRC at ingest, verify before the CP write and on read, generation-checked handles, one unsafe crate under Miri and fuzzing, and the NVLOG (not the arena) as the source of truth.
- The degraded-mode ACK policy when the partner is down is undefined and is the owner's call.

### What cross-examination and fact-checking changed
Conceded: the stream-append mirror contract (`append` returning a sequence number, with gap detection) presumes an in-order userspace receiver, which the only in-box FC design lacks; replaced by sender-chosen slots, self-validating records, gaps resolved at replay as the maximal contiguous prefix, and `retire` as a sender-written Status record; two traits, data ring and control messages. The LIO-fileio FC ring over tcm_qla2xxx is withdrawn (out-of-tree on Rocky 9 and 10). fsdax cannot be pinned, so the arena is devdax and the inbound ring is an fsdax file. The record header lacked an owner epoch. A 15 to 30 s takeover replay exceeds every initiator timeout, hence the standby indexer. Unmirrored ACK is a consensus decision, not a local policy. The shadow replica is not free (no device fence, no resync, halved ingest). COMPARE AND WRITE and persistent reservations never reach the D-Blade through ublk and LIO, so they are Phase 3 items. "Rocky 9 is acceptable" was a non-decision: Rocky 10.1 only. O_DSYNC on every data write costs FUA plus N member flushes: plain O_DIRECT data writes, one flush, then the FUA superblock. The PMem commit sequence skipped writing back the payload before the first fence. Pre-GC drain is about 2 GB/s on modern CMR drives with tuned md, not 1.4. Dual-host attachment of MD14xx shelves is outside Dell's support matrix and needs an HBA355e. Latency targets are owned by Network.

Held: the NVLOG is the only durability mechanism; RPO=0 needs persistent log media on both nodes; node-local disks cannot do takeover; write-hole closure by design; the throughput premise is still wrong after corrections (1.0 to 1.4 GB/s net per 12-HDD aggregate); the SSD tier is mandatory; the record comes before the transport; two aggregates per 24-bay node.

### Revised Phase 1 recommendation
Build in order: `otap-record` and `otap-nvlog` (devdax with NT stores, O_DIRECT NVMe with IOPOLL, DRAM behind a loud flag; put, status, replay as maximal-contiguous-prefix with CRC and epoch checks); `otap-arena` and `otap-index` (pinned registered arenas, generation handles, read-your-writes, overlap resolution, sector masks, per-aggregate credits and watermarks); the TCP ring receiver writing inbound records exactly as nvmet-fc will, plus the standby indexer; CP-lite on a real 12-drive md RAID6 (sorted full-stripe `WRITE_FIXED`, one flush, superblock-in-a-stripe, Status retire); an in-process load generator at 2 GB/s or more with no fabric. Prove: 1,000 crash and power-pull tests with zero acknowledged-write loss, zero phantoms, and zero stale-epoch records applied after takeover begins; record overhead at or under 1.03x NVLOG bytes per payload byte at 4 KiB; local persist per 4 KiB record PMem p50 under 10 us, Optane SSD p50 under 40 us; D-Blade ACK p50 under 60 us and p99 under 200 us on one pinned 10GbE link with persist and mirror overlapped; 1.0 GB/s payload for 60 s on one link within 4 cores; standby index within 100 ms of the ring tail; cold replay of 20 GB under 20 s; flush at or above 1.6 GB/s platter-average on 12 x 16 TB CMR drives with zero member reads during a CP; the array's random read baseline recorded to size the SSD tier; injected corruption detected 100% of the time; Miri and fuzzing clean.

Top risks: NVLOG medium supply and endurance (every pmem option is end of life); the ingest ceiling is the mirror link and NVLOG device, then GC, not spindles; the HA data model; freezing the record and ring contract; the platter-durability chain and Tech Preview kernel posture.

## Part 3. Opus-Consensus (Distributed Systems Specialist)

### Executive take
Build the control plane as a three-voter openraft cluster (the two HA nodes plus a tiny witness VM) whose replicated state machine is a few hundred KB of ownership, epoch and pair-state records, and keep every data-path decision out of Raft, gated instead by an epoch carried on every message plus a lease (quorum-attested or partner-attested) backed by a hardware watchdog. The plan as written has no safe automatic takeover at all: a two-voter Raft tolerates zero failures, node-local disks mean the survivor cannot read the partner's flushed data, and a volatile NVLOG means one rack power event breaks RPO=0. ONTAP takeover rests on dual-ported shared shelves, SCSI-3 persistent-reservation fencing and mailbox disks; OpenTAP should copy that with external dual-EMM SAS JBODs cabled to both nodes through HBA355e adapters. A reservation preempt is a fence enforced by the drive itself, which no lease-and-clock argument can match.

### Proposed libraries and subsystems
| Crate | Shape | Verdict |
|---|---|---|
| openraft 0.9.25 (0.10 is alpha) | async library; you implement network, log storage and state machine; `AsyncRuntime` trait with a Tokio implementation | Recommended: joint consensus only (the safe variant), `ensure_linearizable()` reads, follower-side leader lease rejects votes (no pre-vote; rejection is explicit, and only once a node has seen a leader); pre-1.0 API churn; years of use in Databend's meta-service |
| tikv raft-rs 0.7.0 (2023; master lightly maintained in 2026) | sans-I/O core: you provide log, storage, transport, timers, drive the Ready loop | Fallback; pin a git revision, since crates.io still pulls rust-protobuf 2.x; ConfChangeV2, ReadIndex, lease reads, pre-vote, check-quorum |
| omnipaxos 0.2.3 | in-development, EuroSys'23 | Not for v1; the only credible Rust Paxos-family option |
| async-raft, raftify, ruraft, little_raft | abandoned or young | No |
| etcd | Go service | Violates "Rust daemons" and adds an ops dependency; benchmark only |

Supporting: a hand-written append-only Raft log with `fdatasync` plus serde snapshots (or `redb` 2.x); serde plus postcard with versioned enums; no gRPC. Fencing: Redfish over HTTPS to iDRAC9 (`ComputerSystem.Reset` with `ForceOff`, poll `PowerState`); SCSI-3 PR via `SG_IO` or `sg_persist`/`mpathpersist`; `/dev/watchdog` via `iTCO_wdt` or `ipmi_watchdog`. IPMI over LAN is disabled by default on current iDRAC9 firmware and is not a fence rung. mdadm as a process with auto-assembly disabled and udev masked on shared disks. md-cluster is not built on Rocky 9 or 10 and needs Corosync plus DLM anyway. Testing: turmoil 0.7, madsim, shuttle, loom, stateright, TLA+, Jepsen plus elle, nemeses (nftables, tc, `ip link`, iDRAC power, `kill -STOP`, sysrq-c), a switched PDU.

### Proposed architecture
`otap-ctl` on each node (and as the witness with `--role witness`) embeds openraft and contains the failure detector, lease manager, fence ladder, takeover state machine and address manager. The replicated state: aggregates (home node, owner node, epoch, mode: Mirrored, UnmirroredGranted, TakeoverInProgress, GivebackInProgress), volumes, pairs, nodes, portals and LUN identities, cluster version. Takeover granularity is the aggregate. Not in Raft: client I/O, mirror acks, NVLOG contents, CP scheduling, allocator metadata; Raft is written a few times a minute and its commit latency is irrelevant. The applied ownership table is published into a memory-mapped seqlock page that the data daemons read on every admission with no syscall. Every mirror record, CP record and internal RPC carries (aggregate id, owner epoch); the aggregate superblock stores the epoch of its last CP, and an importer refuses an aggregate whose on-disk epoch is newer than its grant.

Quorum, leases, fencing: voters A, B, W. A node may admit I/O for an aggregate it owns only while `now < last_quorum_contact + L` or `now < last_partner_heartbeat + L`, with L = 3 s, heartbeats every 100 ms on every link, renewal every 500 ms. The hardware watchdog is petted only while leases are valid; a paused, wedged or partitioned node resets itself within L plus the watchdog period. The invariant that closes the partition matrix: a node may ACK a write it could not mirror only after Raft has committed `GrantUnmirrored` for that aggregate, and that grant disables takeover of the aggregate; a node without quorum cannot get the grant and so blocks writes.

The partition matrix (Ethernet down with mirror up; mirror down with Ethernet up; both down with the witness reachable by both, by one, or by neither; a wedged node; a node rebooting with stale state; dual power loss; fence unreachable) closes with no split-brain in every row, with RPO=0 in every row except dual power loss on a volatile NVLOG. Takeover on a shared JBOD lands at about 9 s: 2 s detection, lease wait overlapped with read-only assembly, fence, replay from the standby index, commit and ALUA flip. Giveback after a stability window: quiesce, final CP, commit, re-register reservations, paths flip. Membership: new pairs join as learners then one joint change; keep the witness so an odd voter count survives losing a whole pair. Clocks: `CLOCK_MONOTONIC` only for safety; wall clocks for logs only.

### Bottlenecks, with numbers
Failover time: detection 2 s, fence 0.5 to 5 s, assemble 1 to 3 s, replay under 3 s with the standby index, commit and flip about 1 s: 6 to 14 s, or 12 to 16 s without a confirmed fence. Initiator windows, corrected by the fact-check: ESXi's stock iSCSI stack pauses about 35 s after a silent target death (NoopOut 15 s plus NoopOut timeout 10 s plus RecoveryTimeout 10 s) while holding guest I/O; Linux dm-multipath fails I/O at about 15 s with the default `no_path_retry=fail` unless the surviving ports report TRANSITIONING; Windows LinkDownTime is 15 s with a 60 s guest disk timeout; NVMe hosts fail over at once on ANA state with KATO as the detection timer. NVLOG sizing at 10GbE and a 15 s interval is about 75 GB per node including the partner's mirror; NVDIMM-N tops out at 192 GB. The fence paths: PR preempt on 24 drives in parallel under 100 ms; Redfish ForceOff 1 to 5 s (TLS session setup alone is 1 to 3 s on iDRAC9); the watchdog bound 8 s.

### Creative solutions
- The SAS fabric as a third heartbeat path and disk arbiter: an SBD-style mailbox region on three drives, with the preempt on one arbiter drive first so the fence race is atomic.
- A disk-hosted third voter for witness-less sites (exotic; needs a TLA+ model first).
- A shared SAS-SSD journal in the JBOD as the degraded path when the mirror link is down, so RPO=0 survives even the both-links-down row.
- Partner-attested leases: the pair keeps serving without a witness as long as the partners hear each other; quorum is needed only to change ownership.
- Lease-gated hardware watchdog as the universal backstop fence; the epoch seqlock page; segment shipping for resync; nightly planned takeover rehearsal as a product feature.

### Holes poked in the plan
Two-node Raft is a null feature. Node-local disks are incompatible with takeover. A volatile NVLOG breaks RPO=0 on a rack power event and changes takeover. "Mirror down, keep ACKing" is a data-loss trap without a committed grant that disables takeover. If iDRAC shares the Ethernet that just failed, Redfish fencing is unreachable exactly when needed. mdadm has no multi-host protection on shared disks, so the daemon is the only assembly guard. Red Hat removed qla2xxx target mode in RHEL 8 and never restored it. Persistent reservations and ALUA port identities are persistent state that must live in the D-Blade log or the state machine, with stable port IDs on both nodes. Heartbeats must be application-level. A returning node's NVLOG and arrays are poison until the state machine speaks. Nothing in the safety argument may use wall clocks. A Phase 1 mirror daemon whose wire format lacks (aggregate, epoch, seq) and a stale-epoch reject path will be rewritten in Phase 4.

### What cross-examination and fact-checking changed
Conceded: Raft over the FC mirror is impossible (lpfc ports are target-only, so the FC leg is two unidirectional write paths with no receiver); Raft, heartbeats, leases and fence tokens move to a TCP plus mTLS `ControlLink`. Epochs do not reject anything on an NVMe/FC target; the lease plus watchdog is the only fence on every transport. The replay arithmetic was off by 5x (5 s per GB), so the mirror ring must already be persistent and replay is capped by record count. The initiator timers were the wrong knobs. PR, UA and ALUA state in the state machine has no mechanism under LIO: v1 documents that reservations are lost on takeover; the state machine holds identity only plus a LUN table so every LUN is pre-staged Standby on the survivor. A preempt fences only under a held Write-Exclusive Registrants-Only reservation; both nodes must register on every path; per-drive fencing is non-atomic. MD14xx shelves are "maximum servers 1" in Dell's matrix. The unmirrored grant maroons data on a dead node unless its NVLOG is durable, self-describing and transplantable. The watchdog must not be petted on I/O progress alone (the ONTAP veteran's hung-disk reset storm), so I/O stall is an alarm, not a reset trigger. No trust model existed: a cluster CA issues per-node certificates at join, mTLS on the control link, the witness on the management VLAN only, an iDRAC account with power control only.

Held: three voters with a witness; node-local disks cannot give takeover; lease plus lease-gated watchdog is the primary fence, PR and ForceOff are early exits; the Raft-committed, takeover-disabling `GrantUnmirrored` invariant; Raft off the data path; the aggregate as the takeover unit.

### Revised Phase 1 recommendation
The transport split and the shared header, proven by a 10,000-seed turmoil matrix (per-link partitions, reorder, a polled-mailbox model for FC, followers paused longer than the lease) with zero lease overlaps and zero stale-epoch records applied. The detector, lease, Stalled bound and lease-gated watchdog: `kill -STOP` resets the node within 8 s, the partner declares silence at 2 s, a unique-payload checker finds zero writes acknowledged after lease expiry. An ownership oracle stub and seqlock page: an epoch bump fails all in-flight sender writes closed within one round trip. A fence library (PR register-all-paths and preempt-and-abort, Redfish ForceOff with PowerState polling, nvmet and LIO unlink). A shelf spike if shelves are chosen. A durability spike with 50 PDU pulls under load. A one-page decision record before Phase 2.

Top risks: FC cannot be the primary goal on stock Rocky; the shelf is Dell-unsupported; the 10 s takeover budget has no end-to-end owner yet; NVDIMM-N is a refurbished 2017 part; control-plane trust and iDRAC network topology are per-site facts.

## Part 4. Opus-Security (N-Blade / Protocol Specialist)

### Executive take
Build the Phase 1 N-Blade as a thin Rust ublk server behind the kernel's own targets (LIO iSCSI and nvmet-tcp) on Rocky 10.1, not as a Rust protocol stack: the kernel gives interoperable iSCSI and NVMe-oF, CHAP, ALUA and ANA, VAAI primitives and several fabrics for one backstore, and Phase 1's real deliverable is a block-level daemon anyway. Long term the paths diverge only for NVMe: keep LIO for iSCSI permanently (a from-scratch SCSI target that ESXi and Windows Failover Clustering accept is two-plus engineer-years of negative-value work) and write a native Rust NVMe/TCP plus RDMA target once zero-copy and cluster-aware reservations are needed. "Stateless N-Blade" is coherent only if defined as "nothing that must survive the N-Blade": connection state dies with it and initiators reinstate sessions; LUN-scoped SCSI state must live in the D-Blade or control plane, which LIO does not do, and which forces Active/Standby ALUA while LIO is the front end.

### Proposed libraries and subsystems
- LIO core and `iscsi_target_mod` (both kernels): SPC-3 reservations with APTPL, ALUA, COMPARE AND WRITE, XCOPY, UNMAP and WRITE SAME, the VPD pages, all emulated above the backstore. Reservation state is per node and in memory, with APTPL to a local file.
- `target_core_user` (TCMU): passes no initiator identity to userspace, so it cannot give spec-compliant multi-initiator reservations; withdrawn as a path.
- `ublk_drv`: absent from Rocky 9; a module (Technology Preview) on every Rocky 10 release; 10.1's 6.12.0-130 kernel carries the large backport (zero-copy, `AUTO_BUF_REG`, per-I/O daemons, CVE fixes). `USER_RECOVERY` alone aborts in-flight requests; `USER_RECOVERY_REISSUE` requeues them and may issue a request twice. ublk has no block `pr_ops`.
- `nvmet`: TCP, RDMA, FC (lpfc only), ANA groups, DH-HMAC-CHAP in-band auth (6.0), TLS 1.3 PSK via kTLS and `tlshd` (6.7); NVMe reservations landed after 6.12.
- `tcm_qla2xxx` dual mode exists upstream (per-port `qlini_mode` since 5.2, "restore initiator in dual mode" fix in 5.15) but is not built on Rocky; Marvell has no NVMe/FC target and none planned; Emulex has NVMe/FC target and no SCSI target.
- io_uring: provided buffer rings 5.19, multishot receive and `SEND_ZC` 6.0, `DEFER_TASKRUN` 6.1, NAPI busy-poll registration 6.9, zero-copy receive 6.15.
- Rust: `libublk` 0.4.7 (by the ublk maintainer); `io-uring` 0.7; `zerocopy`, `bytes`, `crc32c`; RustCrypto `md-5`, `sha2`, `hmac` for CHAP and DH-HMAC-CHAP; `openssl` 0.10 for TLS 1.3 external PSK (rustls has no external-PSK API); the `ktls` crate; `cargo-fuzz`, `proptest`, `tracing`, `metrics-exporter-prometheus`. Reference only: `ioutgt` (Rust NVMe/TCP and RDMA target, early, needs 6.11+, no in-band auth), the hobby-scale `iscsi-target` 1.0.0 crate, SPDK 24.x.
- Windows has no inbox, MPIO-capable NVMe-oF initiator (Microsoft's preview shipped March 2026 without multipathing; StarWind's third-party initiator exists), so iSCSI cannot be dropped.

### Proposed architecture
Initiator to LIO or nvmet in the kernel, to `/dev/ublkbN`, to `nbladed` over io_uring: one queue thread per NIC RSS queue, an ownership cache (LUN to aggregate to local D-Blade, epoch), a `DBladeClient` that is in-process shared memory today and TCP or RDMA across nodes later. A fabric configuration applier writes configfs directly from desired state (targets, portal groups, node ACLs with CHAP secrets, LUN maps, ALUA and ANA groups), with identical `vpd_unit_serial` and NGUID on both nodes so the initiator sees one device with two paths. One ublk device per LUN, hardware queues equal to data cores, `USER_RECOVERY|REISSUE|USER_COPY`, Read/Write/Flush/Discard/WriteZeroes mapping 1:1 onto record ops, Flush a no-op only when the NVLOG is persistent. On a stale epoch the N-Blade fails closed at once: TPG to ALUA Standby and ANA group to Inaccessible via configfs, so initiators re-issue RTPG and move to the new active path.

```rust
pub struct IoReq<'a> { obj: ObjectId, epoch: Epoch, op: BlockOp, lba: u64, nblocks: u32, data: Option<&'a [u8]> }
pub enum IoStatus { Ok, StaleEpoch { current: Epoch, owner: NodeId }, NotOwner, Media(SenseKey), Timeout }
pub trait DBladeClient: Send + Sync {
    fn submit(&self, req: IoReq<'_>, done: Completion<IoStatus>) -> Result<(), SubmitError>; // completes only after the mirror ack
    fn resolve(&self, obj: ObjectId) -> (NodeId, Epoch);
}
```
Key decisions: kernel targets, not Rust stacks; ublk over TCMU; Active/Standby ALUA (owner Active/Optimized, partner Standby) and ANA Optimized/Inaccessible while LIO or nvmet front the LUN, because LIO's COMPARE AND WRITE is a per-device semaphore and its reservations are per node; two copies per write on 6.12 (socket to LIO page, page to ublk buffer), one with ublk zero-copy later; `IoReq` keys on an object id plus offset so NFS and SMB can map a file to many objects later, with an inode layer, lock manager and grace-period backend still to build.

### Bottlenecks, with numbers
A 4 KiB iSCSI write at QD1 over 10GbE through the Phase 1 stack: initiator 15 to 25 us; wire plus NIC to the LIO receive thread 13 to 23 us; LIO parse, bio, ublk wake 5 to 10 us; ublk copy plus local RPC 2 to 4 us; NVLOG append plus mirror send about 5 us; partner receive to ack 15 to 25 us (8 to 12 us busy-polled); ack return 10 to 20 us; status PDU 10 to 15 us. Total 90 to 150 us tuned, 90 to 200 us untuned (6.5 to 11K IOPS per QD1 stream); 1GbE adds 34 us of serialization per hop twice plus NIC round trips for 250 to 350 us and caps the mirror link at about 28K 4 KiB writes per second; 25GbE RoCE is the only transport that moves the number materially (60 to 80 us total). Per node at QD32: about 40K IOPS per core, 250 to 300K per node theoretical; LIO caps a session at 100 to 150K IOPS (one receive and transmit thread pair per connection); a single 10GbE mirror link carries 250 to 280K 4 KiB writes per second at QD8 to 16. Reads: 12 HDDs at about 150 random IOPS each is 1.8K IOPS at 8 to 12 ms, which is what initiators will feel. Takeover must land in 10 s with a 25 s hard ceiling only if host tuning ships.

### Creative solutions
- The LUN as a replicated SCSI object: NAA and serial, the reservation table, unit attentions, mode parameters and ALUA state live in the D-Blade log as ordered `PrUpdate` records, so they are mirrored with RPO=0 for free and N-Blades read them at login.
- Flush is free: completion implies mirrored into a persistent NVLOG, so SYNCHRONIZE CACHE, FUA and NVMe Flush are no-ops and the target advertises write-cache-disabled.
- 1:1:1 core mapping: NIC RSS queue i, LIO or nvmet threads pinned by cpuset, ublk queue i, D-Blade shard i, with io_uring NAPI busy-poll on data cores and core 0 untouched.
- Differential conformance: the future Rust NVMe target runs beside nvmet on the same backstore under blktests, nvme-cli and fio verify; LIO is the iSCSI oracle; fuzz seeds come from packet captures of ESXi, Windows and open-iscsi logins.
- Slowloris by construction: no data-buffer allocation before a validated header; login on a cheap thread with a 30 s negotiation timeout and at most 4 half-open logins per source; nftables connlimit in front of LIO.
- Read-miss transparency: per-LUN read-miss latency exported so initiator timeouts are tuned, not guessed.

### Holes poked in the plan
Node-local disks make ALUA failover theatre. "Stateless N-Blade" is incoherent as written. Reservations survive failover only by luck (Windows Failover Clustering re-arbitrates; VMware in-guest clustering with RDMs does not). Two-node Raft is worse than no Raft. RAM without persistence is not RPO=0; the honest alternative is to advertise write-cache-enabled and let SYNCHRONIZE CACHE force a mini-CP, which destroys the sequential-CP premise under fsync-heavy guests. FC is the wrong tier and the right fabric: client-side at most. Rocky 9 cannot host the design (no ublk, nvmet without auth or TLS). Windows needs iSCSI. nvmet reservations are post-6.12. "One massive contiguous stripe" needs full-stripe alignment, a raised stripe cache and group threads. Takeover timing versus initiator timers was unbudgeted. The attack surface in Phase 1 is the kernel's (LIO's login parser and nvmet-tcp have had CVEs) plus our record and control parsers and the configfs applier: fuzz them, bind data listeners only to data addresses, management on its own VLAN with mTLS, nftables default-deny on data NICs except 3260, 4420 and 8009, CHAP and `allow_any_host=0` mandatory by default.

### What cross-examination and fact-checking changed
Conceded: Rocky 10 for the right reasons (the io_uring sysctl is identical on 9.4+ and 10.x; the real reasons are ublk, NAPI busy-poll, `SEND_ZC`, multishot receive and nvmet auth and TLS, all absent from 5.14). TCMU buys no cluster reservations, so the TCMU passthrough handler and a proposed ublk `pr_ops` patch are withdrawn. "FC for free via tcm_qla2xxx" was wrong on Rocky; the HBA330 has no external ports. "The mirror is the fence" was half a fence: inline rejection needs a userspace receiver, nvmet-fc rejects nothing, the lease and watchdog fence on every transport, the witness is needed for every ownership change under partition, and running unmirrored needs a committed grant. Holding I/O on a stale epoch was wrong; fail closed at once. `USER_RECOVERY` alone aborts in-flight I/O, so REISSUE plus idempotent mirroring keyed by a request id is required, and with the D-Blade in the same process a restart becomes a 15 to 30 s replay stall: N-Blade and D-Blade are separate processes. The cleaner reads segments sequentially; a mirror link equal to the flush rate caps burst absorption, so it must exceed peak client ingest. The FC round-trip figure was unsourced; FC demotion rests on support status and the extra kernel hop, not latency. PPL and journal withdrawn for never-overwrite plus a write-intent bitmap. iSCSI LUNs are 512e. Reservation updates are ordered NVLOG records, not Raft commits. IPMI is not a fence rung. A hobby-scale Rust iSCSI crate exists (reference only).

Held: kernel targets in Phase 1; ublk over TCMU on Rocky 10.1; Active/Standby ALUA while LIO or nvmet front the LUN; FC is not the mirror transport; iSCSI and LIO cannot be dropped, though the NVMe-oF front end must be built Windows-capable for Microsoft's eventual GA; no ack without a partner-durable ack; reservations in the D-Blade log; the 1GbE ceiling, the QD1 arithmetic and the security posture.

### Revised Phase 1 recommendation
Rocky 10.1 (6.12.0-130 or later); `nbladed` on `libublk` and `io-uring` with one ublk device per LUN, REISSUE recovery, 512e for iSCSI and 4 KiB for NVMe namespaces; one `dbladed` per aggregate; per-core SPSC rings in shared memory carrying the frozen RPC header; a configfs applier for LIO iSCSI and nvmet-tcp from a declarative spec with CHAP and DH-HMAC-CHAP mandatory, `allow_any_host=0`, discovery authentication, and identical identities on both nodes. Prove: ESXi 8, Windows Server 2022 with MPIO, and Rocky or Ubuntu initiators log in with CHAP, format, and run 24 h of `fio --verify`; the libiscsi suite and blktests nvme group pass; 4 KiB write QD1 at or under 200 us untuned and 120 us with NAPI busy-poll over 10GbE; QD32 at or above 100K 4 KiB write IOPS per node; 50 iDRAC power-offs of the owner during verify with zero acknowledged writes missing; 50 `nbladed` restarts under load with no path drop and no verify failure; `dbladed` restart replays within 5 s; manual takeover with the old owner Standby strictly before the survivor Active/Optimized and both flips visible within 3 s; 100 partition trials with zero post-expiry acknowledgements; 24 h of fuzzing on the record and control parsers; a 1,000-session login flood under the memory cap.

Top risks: node-local disks make takeover theatre; Technology Preview foundations (io_uring and ublk unsupported by Red Hat on both releases, ABI backported in bulk); FC expectations; reservations and COMPARE AND WRITE are single-node until the native target; takeover time versus guest timers.

## Part 5. The critics

### Completeness critic
Missing before or during Phase 1: a lab and CI plan without target hardware (a bill of materials with lead times, and a VM matrix using `memmap=` pmem, nvmet-tcp as the BlockRing stand-in, and `nvmet-fcloop`, which is in-box on both Rocky kernels and exercises the nvmet-fc target and host code on one box with no HBA); observability as a contract (per-stage histograms, ring fill, CP duration and reason, GC amplification, link health, lease and `nvlog_armed` state, alerts for states that silently weaken RPO=0); a performance methodology (the TCP band is tuning-dominated, so fio job files, warm-up, array aging state and a regression gate must be owned); a cold-start reconcile protocol after dual power loss (each node holds its own NVLOG plus the partner's ring; who replays what, in what order, before anyone serves); a core, NUMA and memory budget per SKU; mirror-link isolation (every customer byte crosses the mirror in clear; a physically private link, or kTLS); a privilege model, secrets handling and a licence pass over the dependency tree. Phase 2: the read path and SSD tier (fill policy, persistence across restart, coldness after takeover), capacity over months (free-space reserve, write amplification near full, thin provisioning and out-of-space semantics, an aging soak), data reduction and encryption at rest (reserve fields in the formats now), snapshots and asynchronous replication. Formats in Phase 1 with policy by Phase 4: upgrades and rollback (the record header needs a version field; superblock, segment and map versioning), the management plane and API, runbooks and host utilities.

Unresolved conflicts: the record layout (crossed concessions on alignment and the request id; no version field); the shadow-replica mechanism (physical segment shipping versus logical record shipping); process topology; DRAM-only semantics; FC in Phase 1; the takeover hard ceiling; Phase 1 scope ("four Phase 1s"). The critic's recommended decisions appear, with my rulings, in Part 6.

### ONTAP veteran
Where the plan diverges from ONTAP: ONTAP mirrors the NVLOG (a journal of logged operations with payload) into the partner's NVRAM, never a buffer cache; NVRAM is the durability mechanism and an ack means "in two persistent logs"; HA pairs sit in takeover for hours or days awaiting parts, and the survivor's own crash in that state is survivable only because NVRAM persists; every shelf is cabled to both controllers, ownership is a soft label per disk, takeover reserves the partner's disks, and mailbox disks carry HA state, so node-local disks are not an HA pair (NetApp's commodity answer is ONTAP Select: SyncMirror plexes across both nodes' local disks over Ethernet, a mediator, 50% usable); the 10 s CP timer is a ceiling and CPs also fire on log-half-full, high-water and back-to-back, so under load the interval is log size divided by ingest; the HA interconnect carries NVLOG mirror, heartbeats and takeover coordination and never SpinNP or RDB (the brief fused two fabrics); FC-VI is an RDMA-style protocol in purpose-built adapter firmware, data is not "replicated over FC", and NetApp then built MetroCluster IP over Ethernet (the brief copied the cable, not the mechanism); RDB replicates configuration only and does not decide takeover; SAN LIFs never migrate in clustered ONTAP, partner paths are pre-logged-in and takeover flips ALUA state, so floating IPs are 7-mode's design and should not be built.

Hard lessons the team is about to re-learn: back-to-back CPs and watchdog storms (a mechanism that resets a node for lack of I/O progress hands the load to a partner on the same spindles, which then stalls too; pet the watchdog on control-plane liveness, alarm on stalled I/O); log size follows CP duration, not burst ambitions, because replay time is takeover time; fragmentation over months and the cliff past about 85 to 90% full; hung disks stall whole stripes (md waits on SCSI error handling, SATA drives without SCT ERC retry for minutes, and md sees errors but never latency); write-cache-full is the steady state with 12 HDDs behind 10GbE, so build a proportional throttle on day one; "in takeover" is a normal state and a second failure there is an outage rather than data loss only because the log persists; giveback failures and auto-giveback timers; every protocol brought state that had to outlive the front end; and under an LFS on md, a map-CRC mismatch is detected but cannot be repaired from parity.

Copy: NVLOG quartering with a log generation in the header; the CP trigger taxonomy and sysstat-style counters; takeover-disabled-unsynchronized-log as a first-class alarmed state; hardware-assisted takeover (subscribe to the partner iDRAC's power and reset events as a push source); the ONTAP Select HA model if disks stay local; software disk ownership and self-describing aggregates; planned takeover first and nightly rehearsal; rapid RAID recovery (md `want_replacement`, per-member latency SLOs, SCT ERC at 7 s, SCSI timeouts near 10 s); fullness guardrails; Host Utilities (ship multipath.conf, ESXi claim rules, Windows MPIO settings) instead of betting on stock timers; scrub with identity. Do not copy: FC as the interconnect; a bespoke RAID-DP; the full scale-out machinery; 7-mode identity takeover; panic-on-slow-I/O; maximal NVRAM; the v1 feature surface. Phase 1 advice: decide shelf versus the Select model before code; build the frozen record and slot ring, local persistence with a loud DRAM flag, the TCP mirror with lease-at-ack, replay, CP-lite on a real array, the ublk and LIO front door, planned takeover and giveback driven by an ownership stub, and sysstat-style instrumentation from the first commit; break it early with hung-disk injection; age the array before measuring; do not attempt FC, Raft itself, NFS or SMB, snapshots, cross-node data paths, zero-copy, 1GbE, floating IPs, reservation survival, or automatic unplanned takeover in product code.

## Part 6. Executive synthesis (Fable 5.1)

### Three premises of the brief do not survive

**We are not mirroring a RAM write cache; we are mirroring a persistent log.** ONTAP mirrors the NVLOG into NVRAM, and its buffer cache is a derivative that can be rebuilt. A DRAM-to-DRAM mirror satisfies "no acknowledged write lost on a single-node failure" literally, and fails what a SAN customer means by RPO=0: one PDU or a rack power event loses a full CP interval of acknowledged writes on both nodes, and a survivor that crashes while in takeover for days loses everything unmirrored. The NVLOG, not the arena, is the source of truth. It must be on persistent media on both nodes in the product (devdax pmem, or a PLP NVMe log), and the ack level is a logged cluster setting, not a transport accident. DRAM-only is a prototype mode that announces itself. This decides the Phase 1 record format, the ack semantics, and the sizing rule: log half equals ingest times maximum CP duration, capped by record count so replay fits the takeover budget.

**Node-local disks cannot do ONTAP-style takeover.** The survivor would own the last 10 to 15 s of writes and none of the flushed data. ONTAP's HA pair is dual-ported shelves plus SCSI-3 reservations plus mailbox disks. OpenTAP has three honest options and one dishonest one. Shared SAS shelves (works in the field with an HBA355e per node and SAS or NL-SAS drives, but dual-host attachment of Dell MD14xx shelves is outside Dell's support matrix, and SATA is excluded). The ONTAP Select model (every CP segment also shipped to the partner's own array as a second plex, a witness as mediator, 50% usable capacity, halved sustainable ingest, identical geometry on both nodes). Manual failover (RPO=0, RTO equals repair time). The dishonest option is the brief as written. This must be decided before Phase 2; Phase 1 runs on node-local lab hardware under a written statement and builds the partner-side ring consumer so that both models work.

**FC cannot be the primary interconnect on a stock Rocky kernel, and it buys no latency.** Verified against the Rocky 9 and 10 kernel configs: no FC SCSI target is built (`tcm_qla2xxx` and `efct` are unset; Red Hat removed qla2xxx target mode in RHEL 8 and patches the fabric out of targetcli in 9 and 10). The only in-box FC target is NVMe/FC on Emulex lpfc, which Red Hat explicitly does not support (nvmet is Technology Preview, and nvmet-fc is listed as unmaintained in RHEL 9), whose ports are target-or-initiator (four ports per node for a bidirectional dual-path mirror), and for which no public Linux-to-Linux direct-connect validation exists. Through any kernel target stack a 4 KiB FC mirror write lands at 50 to 150 us; busy-polled 10GbE TCP is 20 to 35 us; 25GbE RoCE is 5 to 10 us. NetApp's FC-VI was custom RDMA-style firmware that stock HBAs cannot run, and NetApp itself moved MetroCluster to Ethernet. My recommendation to the owner: make 25GbE RoCE the Tier 2 performance interconnect, and keep FC as an optional isolation and distance tier (NVMe/FC mirror-only on Emulex, Red Hat-unsupported, behind a time-boxed spike) chosen only if distance or FC clients require it. The abstraction is still built FC-ready in Phase 1: the BlockRing (an NVMe namespace on a DAX file) is the FC path with identical code, proven over nvmet-tcp, and `nvmet-fcloop` exercises the nvmet-fc code on one box with no HBA.

### What survived, and what the team converged on
The N-Blade/D-Blade split, the log plus Consistency Point model, a Raft control plane, Rust daemons, and an abstracted transport all stand. The converged design after rebuttal:

- The NVLOG is the only durability mechanism; the arena and dirty index are a rebuildable cache. A write is acknowledged when its record is locally persistent and partner-durable, with persist and mirror overlapped.
- The mirror is a slot-addressed, idempotent, receiver-optional ring: sender-chosen slots, self-validating records (header and payload CRCs), out-of-order and duplicate tolerant, replay as the maximal contiguous prefix per aggregate and epoch. This is the only shape under which in-box FC, NVMe multipath and RDMA write-with-immediate are one implementation.
- Two transports, not one: `MirrorRing` (put-at-slot, durable ack, advisory `can_reject`) and `ControlLink` (TCP plus mTLS for heartbeats, leases, epochs, and later Raft). Raft never rides the mirror.
- Fencing on every transport is lease-at-ack plus a lease-gated hardware watchdog; SCSI-3 reservations where shelves exist; Redfish ForceOff over a dedicated iDRAC network as an accelerator; receiver teardown (nvmet port unlink, LIO ACL removal, TCP close) before the survivor serves; the record epoch is replay cleanup and defence in depth, never the safety argument.
- A node acknowledges unmirrored writes only under a Raft-committed `GrantUnmirrored` that disables takeover of that aggregate, and only with an armed persistent NVLOG. With a volatile NVLOG, a mirror-link failure is a write outage (BUSY after 2 s), which is Phase 1's reality.
- Three voters: the two nodes plus a witness VM, on openraft 0.9.x pinned. Raft off the data path; ownership published through a seqlock page.
- The takeover unit is the aggregate; LUNs and namespaces inherit its epoch; two aggregates per 24-bay node; one ring and credit budget per aggregate.
- The partner indexes its inbound ring continuously, so takeover replay is a sub-second residual scan; a records-per-CP cap bounds the worst case.
- The Phase 1 front door is kernel LIO iSCSI and nvmet-tcp over ublk into a Rust daemon on Rocky 10.1; Active/Standby ALUA and ANA; iSCSI stays (Windows); a native Rust NVMe-oF target later owns reservations and COMPARE AND WRITE and unlocks Active/Active.
- Rocky 10.1 stock kernel, no out-of-tree modules in v1; the install profile enables io_uring (`kernel.io_uring_disabled`, SELinux policy for `URING_CMD`) and masks `target.service`; Technology Preview status accepted in writing.
- 10GbE from day one with a fixed tuning profile; 1GbE is functional only.

### Rulings on what remained contested
- **Record layout.** The split layout: 4 KiB descriptor blocks holding dense 64 B headers with per-4 KiB CRCs, plus a 4 KiB-granular payload ring. Packed payloads would make every CP flush a memcpy; padded headers would double 4 KiB record cost. Fields: magic, version, op, flags, header CRC, aggregate id, owner epoch, nvlog seq, cp seq, volume, LBA, length, request id, CRC count. The request id stays (ublk REISSUE needs idempotent dedupe). Opus-Storage owns the byte-level document; all four sign it in week 1.
- **Shadow-replica mechanism**, if node-local disks are chosen: physical CP-segment shipping as the single steady-state, resync and giveback mechanism (ONTAP Select's plex model), with the ring covering only the last CP. Identical md geometry on both nodes is the price. Logical record shipping is the ring replay path and nothing more.
- **Process topology.** `nbladed` (ublk server and configfs applier), one `dbladed` per aggregate (NVLOG, arena, index, mirror, CP), and `otap-ctl` (leases, detector, fences, epoch page, watchdog, later Raft). Crash and replay isolation match the takeover unit. A daemon restart never stops the node's watchdog pet; the watchdog is petted on control-plane liveness and lease validity, and stalled I/O is an alarm.
- **DRAM-only semantics in Phase 1.** `Placed` acknowledgements with write-cache-disabled advertised, loudly labelled as prototype mode in logs, metrics and the API. The write-cache-enabled mini-CP path is not built.
- **FC in Phase 1.** No HBAs are bought and no FC spike runs until the owner has confirmed FC with the facts above. The BlockRing over nvmet-tcp and the fcloop test are the FC readiness proof.
- **Takeover ceiling.** 10 s p99 and 15 s hard, with surviving ports reporting TRANSITIONING and a shipped multipath.conf and host tuning package. No floating IPs: pre-staged standby paths, as clustered ONTAP does.
- **Timers**, one table: ring heartbeat 20 ms (link health only); control heartbeat 100 ms per link; link dead at 1 s; partner silent at 2 s on all links; Stalled at most 2 s then BUSY, never an acknowledgement; lease 3 s renewed every 500 ms, quorum- or partner-attested, carrying the armed state; watchdog 5 s with an 8 s hard bound; takeover admission at the later of fence confirmed and last-heard plus 3.2 s.
- **Phase 1 scope.** The mirror daemon with the control-plane seeds, a measurement-grade CP-lite, and the front door needed to test end to end. Not the map, GC or snapshots (Phase 2), not the configfs applier or cross-node RPC (Phase 3), not Raft (Phase 4).

### Decisions only the project owner can make
1. Disk topology: shared SAS shelves (Dell-unsupported dual-host attach, or a vendor-documented dual-host JBOD; SAS only), the Select-style full replication, or manual failover for v1.
2. FC: accept the re-ranking (25GbE RoCE as Tier 2, FC optional) or confirm FC with the support and latency facts in hand; and whether direct-connect is mandatory or switches are acceptable.
3. Kernel posture: Rocky 10.1 stock kernel with Technology Preview io_uring and ublk, no out-of-tree modules.
4. RPO=0 wording and the NVLOG medium budget: persistent log media on both nodes (Optane-class or large 3-DWPD PLP NVMe; NVDIMM-N optional), and whether RPO=0 must hold under correlated power loss.
5. A witness VM on an independent network path, and an iDRAC network physically separate from data and cluster networks.
6. Initiator population and the tolerated takeover stall, and whether host tuning may be required.
7. Peak client ingest per node, which fixes the mirror link (direct-connect 10GbE for Phase 1; 25GbE for the product).

## Part 7. Phase 1 technical blueprint

### Objective
A Rust daemon pair that takes block writes into a persistent-capable log, mirrors each record to the HA partner before acknowledging, over 10GbE TCP in two transport shapes (one of which is byte-for-byte the FC and RDMA path), with the control-plane seeds (epoch, lease, watchdog, fence library) that Phase 4 will not have to rewrite, proven by a checker that compares client-observed acknowledgements with replayed state under faults.

### Baseline
- Rocky Linux 10.1, kernel 6.12.0-130 or later, stock. Install profile: `kernel.io_uring_disabled=0` (or 1 plus `io_uring_group`), the SELinux module for `IORING_OP_URING_CMD`, `target.service` masked, mdadm `AUTO -all`, SCT ERC at 7 s and SCSI timeouts near 10 s on members, NIC `rx-usecs 0`, C-state cap, `SO_BUSY_POLL`, 9000 MTU on the mirror link, `stripe_cache_size` 32768 and `group_thread_cnt` 4 on the array.
- Startup probes that fail loudly: io_uring EPERM or ENOSYS; ublk features including REISSUE; CPUID CLWB; member `queue/fua` and `write_cache`; HBA in IT mode (refuse PERC virtual disks); NVDIMM armed state when present.
- Rust stable; `asm!` for `clwb`; `cargo-deny` for licences; `#![forbid(unsafe_code)]` everywhere except `otap-arena` and the pmem commit path.

### The frozen contract (week 1)
Record: 64 B header `{magic, version, op, flags, hdr_crc, aggregate_id, owner_epoch, nvlog_seq, cp_seq, vol, lba, len, req_id, ncrc}` followed by `ncrc` per-4 KiB CRC32Cs, in a 4 KiB descriptor block (one per batch, dense); payload in a separate 4 KiB-granular ring. Ops in v1: Write, Discard, WriteZeroes, CpBoundary, Status (retire, carries epoch), Control; reserved: Snap, Clone, PrUpdate. A record is valid when the header CRC and every payload CRC verify; acknowledged implies both the descriptor and payload writes completed. Replay: per (aggregate, owner epoch), take the maximal contiguous prefix, dedupe by seq, apply in seq order, discard records whose epoch is below the aggregate superblock's epoch. The same bytes are the NVLOG entry, the wire format and the replay unit.

Ring: per (aggregate, direction) a descriptor ring plus a payload ring in the partner's inbound region; sender-chosen slots with lap counters; credits in bytes; retire by Status record after CP commit; quarantine for unknown-fate slots until the carrying link's command lifetime has expired; capacity equals ingest times (CP interval plus maximum CP duration) plus quarantine; `max_outstanding_records` as cluster configuration derived from the takeover replay budget.

Two traits:
```rust
pub trait RemoteRing: Send {              // MirrorRing: TcpRing now, BlockRing now, VerbsRing later
    fn caps(&self) -> Caps;               // ack level Placed|Durable, max_msg, max_inflight, can_reject (advisory only)
    fn put(&mut self, slot: Slot, iov: &[IoSlice<'_>], tag: u64) -> Result<(), Busy>;
    fn kick(&mut self);
    fn poll(&mut self, out: &mut Vec<Done>, max: usize) -> usize;
    fn fail_all(&mut self) -> Vec<u64>;   // quarantine + redeliver to fresh slots
}
pub trait ControlLink {                   // TCP + mTLS, postcard-framed, versioned enum messages
    fn send(&self, to: NodeId, msg: CtlMsg) -> Result<(), LinkDown>;
    fn recv(&self) -> impl Stream<Item = (NodeId, CtlMsg)>;   // heartbeats, lease renewals, epoch announcements, Hello/version; Raft in Phase 4
}
```

### Transports built in Phase 1
- **TcpRing**: pinned thread per link, blocking `sendmsg` with iovecs straight from the arena, receiver `readv` into the inbound ring (DRAM or devdax), `clwb` plus `sfence`, 16 B ack `{upto_seq, consumed}`; `TCP_NODELAY`, `SO_BUSY_POLL`; epoch rejection as fail-fast defence in depth; io_uring multishot and `SEND_ZC` as a follow-up on the same code.
- **BlockRing**: io_uring `pwritev` O_DIRECT plus FUA to `/dev/nvmeXnY` at the slot offset; partner side is an nvmet-tcp file-backed namespace on a fully pre-written fsdax file (`memmap=` emulated pmem on dev boxes); fence is unlinking the subsystem from the port, with teardown time measured; dual path through NVMe native multipath. This is the FC and RDMA path minus the fabric.
- **ControlLink**: TCP plus mTLS from a cluster CA, direct-connect on the cluster network and reachable over the management network.
- **Same-node N to D**: SPSC ring over a memfd hugepage arena; the ublk copy lands in the NVLOG slot with the header built alongside.
