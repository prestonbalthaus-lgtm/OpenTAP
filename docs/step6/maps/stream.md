# Map: `otap-stream` (replication stream v1) for Step 6 scope (C)

Read-only survey of the replication stream crate, its on-wire contract in
`otap-format`, the design text it departs from, and the engine surfaces a
sender and a receiver will have to touch. All paths are under
`E:/Coding/OpenTAP`. Line numbers are from the tree as of 2026-10-14
(Step 5 = commit `5114866`).

Short form of the verdict: the crate is a complete, frozen, well-tested
*codec + resume state + credit arithmetic* library. It contains **no
session logic, no sockets, no digest computation, no engine coupling, no
`DeltaSource`/`DeltaStream`/`DeltaSink` traits, and nothing in `otap-cp`
knows it exists** (only `otap-sim` has it, as a dev-dependency, for one
loopback-network test). Everything in doc 05 section 7.3's trait sketch
and state tables is still to be written.

### 2.5 Codec (`codec.rs`)

- `RawFrame { pub hdr: StreamHeader, pub payload: Bytes }` codec.rs:45-50; `kind() -> Option<FrameKind>` 56; `meta() -> FrameMeta` 62; `decode(self) -> Result<(FrameMeta, Frame)>` 67-71.

  - `needed() -> usize` 244-252: bytes wanted before the next frame can be yielded (rest of a header, or rest of a payload); **0 when poisoned or when an error is deferred**, so "a transport that reads `needed()` bytes before each call never sits on one".
  - `next_frame() -> Result<Option<RawFrame>>` 255-307, in order: (1) a poisoned decoder repeats its error; (2) a deferred error is returned once; (3) with no pending header and `< 64` bytes, `Ok(None)`; `StreamHeader::read` failure poisons with `Format(e)`; `wire_len > max_payload` poisons with `PayloadTooLarge`; the 64 header bytes are split off and the header kept pending; (4) with fewer than `wire_len` bytes buffered, `reserve` the rest and `Ok(None)`; (5) the payload is `split_to(wire_len).freeze()` (zero copy, shares the receive allocation), the pending header cleared, `verify_payload` failure returns `PayloadCrc { kind, chunk_idx, cp_seq }` with the frame consumed and `corrupt += 1`; otherwise `frames += 1` and `Ok(Some(RawFrame))`.
  - `drain() -> Result<Vec<RawFrame>>` 312-327: every complete frame; an error after some frames were decoded is held in `deferred` (unless poisoned) and returned by the next call, so nothing decoded is lost.
- What a decode error means for the connection (codec.rs:13-28, S5): a header error (`Format(_)`, `PayloadTooLarge`) is fatal: no way to find the next frame, drop the connection, the cursor survives, reconnect resumes. A `PayloadCrc` is recoverable: for a `Chunk` answer `Abort(Corrupt, chunk_idx)` and the sender resends that chunk; for any other kind answer `Abort(Corrupt, 0)` and the sender restarts the delta from `DeltaBegin` (which resumes, see `BeginOutcome::Resumed`).

### 2.7 Credits (`flow.rs`)

- Constants: `CREDIT_BYTES: u32 = 4096` flow.rs:17; `INITIAL_GRANT_BYTES: u64 = 64 MiB` flow.rs:19; `MAX_STAGING_BYTES: u64 = 2 GiB` flow.rs:21; `MAX_CREDITS: u32 = 524_288` flow.rs:23 (const-asserted flow.rs:204).

- `ReceiverWindow { capacity, outstanding, staged }` flow.rs:41-45 (all in credits):
  - `new(staging_bytes: u64) -> Result` 50-65: non-zero, 4 KiB multiple, `<= 2 GiB` (else `BadBody{"staging_bytes"}`).

  - `reset()` 140-143: `outstanding = staged = 0` ("a delta was aborted: whatever was staged is discarded and the sender's outstanding credits are withdrawn (the next `HelloAck` or `Landed` grants anew)").
- `SenderWindow { credits }` flow.rs:148-150: `new(credits)` (capped at `MAX_CREDITS`) 155-163; `available()` 167; `can_send(bytes)` 173; `reserve(bytes) -> Result<u32>` 179-189 (spends `credits_for(bytes)` or `Window{..}` and spends nothing); `grant(credits)` 193-195 (saturating, capped at `MAX_CREDITS`; "from a `Landed` or `HelloAck` grant"); `reset()` 198-200 ("a reconnect starts from the receiver's cursor").
- Who sends credits to whom, in which frame: the **receiver** grants, the **sender** spends. The opening grant travels as `HelloAck.cursor.credits` ("credits the sender holds", cursor.rs:314-315; flow.rs:91-92), later grants as `Landed.credits` (frame.rs:559-560). `Hello.initial_credits` is a *proposal* field that is `0` from a sender (frame.rs:141-143); nothing in the crate consumes it, and in the design the `Hello` is sent by the connecting sender, so the field is only meaningful if the receiver side also emits a `Hello` (open question 8.5).
- Invariant pinned by the tests (stream_tests.rs:807-863, adversarial 3900-3991): `outstanding + staged <= capacity` through any mix of grants, sends, spurious landings, drains and resets; a refused operation changes nothing; `sender.available() == receiver.outstanding()` as long as both sides see the same sequence of grants and sends.

## 3. Invariants and rules in force

### 3.1 The stream rules S1-S10 (docs/07 E06, lines 106-163; "owned by this file and enforced by the tests named under each")

- **S1 The header is the contract.** Kinds 1-12 only; the only flag bits are the codec; `wire_len`, `raw_len <= 8 MiB`; `cp_seq <= MAX_CP_SEQ`; `base <= cp_seq`; `raw_len == wire_len` for Raw. New kinds/codecs/flags are negotiated in `Hello` first. (`StreamHeader::verify`, `FrameMeta::check`.)
- **S2 Bodies are canonical.** Reserved bytes zero; enumerations defined; unused fields zero/nil/empty and a refusal names the field; `chunk_idx` zero off chunks and `< 2^24` on one; `HelloAck` sparse ranges sorted, disjoint, above `landed_contig`, inside `chunks`.
- **S3 The builder refuses what the parser refuses, and never clamps.** `Frame::validate`, `Encoder::{header, encode_into, encode}`, `Cursor::to_page` (a `Result` for this reason) refuse exactly what `Frame::decode`/`Cursor::from_page` refuse. Only `Cursor::new` caps `credits`.
- **S4 Bounds.** `MAX_DELTA_CHUNKS = 2^24`; `MAX_WIRE_RANGES = 4096` (longer fragmentation truncated; the chunks beyond are resent harmlessly); `MAX_NAME_LEN = 255`; `CursorPage` keeps 500 ranges; `CREDIT_BYTES = 4096`, `INITIAL_GRANT_BYTES = 64 MiB`, `MAX_STAGING_BYTES = 2 GiB`, `MAX_CREDITS = 524,288`.
- **S5 Decoder error semantics.** Bad header → poisoned (repeats the error, drops input, keeps what it refused, `needed() == 0`). Bad payload CRC → frame consumed, `PayloadCrc{kind, chunk_idx, cp_seq}`, decoder in sync; receiver answers `Abort(Corrupt, idx)` for a chunk and `Abort(Corrupt, 0)` otherwise. `drain` never loses a decoded frame; `needed()` is zero while an error is held.
- **S6 Delta byte counts are raw image bytes.** `DeltaBegin.bytes` and `DeltaEnd.bytes` are sums of `raw_len`, between `chunks x 8 KiB` and `chunks x 8 MiB`, unchanged by a codec. `DeltaEnd.digest` is BLAKE3 over the chunk images in index order.
- **S7 Codecs are negotiated, not assumed.** `CAP_CODEC_LZ4`/`CAP_CODEC_ZSTD` reserved; v1 sends raw and passes a chunk with a codec through with its own `raw_len`; compression is Phase B.
- **S8 No sockets.** The transport (`TlsTcp`, `FileSink`) is a consumer.
- **S9 `StreamError` is `#[non_exhaustive]`.**
- **S10 Nothing proportional to an untrusted count is allocated before the count is checked** (record counts vs payload length; payload bound at the header; the encoder checks before reserving). Proven with a counting global allocator.
- E07 (docs/07:165-172): the header and `HoleRecord` are frozen in `otap-format`; a wire change is a `STREAM_MINOR` bump there. E11 (232-243): a new wire/protocol decision becomes a new S-rule in E06.

### 3.2 Format rulings that bind the payload (`otap-format/src/lib.rs`)

- **F3** (lib.rs:93-99): the stripe summary layout; "the on-disk stripe image is the chunk payload byte for byte; the 64-byte stream frame belongs to the transport and is never stored (R25)"; a stripe is at most 8 MiB, which is also the frame payload bound.
- **F4** (100-102): per-descriptor kind is Data/Hole; the stripe kind is in the header once.
- **F5** (103-107): CPs are `u64` in headers and `u32` as `birth_cp`; CP 0 is mkfs; every written block or punched hole has `birth_cp >= 1`.
- **F6** (108-110): the superblock carries `cut_seq` and `cp_nonce`; `cp_nonce` "is the random per-CP identity that keys resume and partial discard (R25, section 1.3)".
- **F8** (118-123): volume index dense below 1024; every descriptor/hole record verified against it.
- **F9** (124-126): a hole descriptor's data slot is present and zero, CRC `ZERO_BLOCK_CRC32C`; map holes carry CRC 0.
- **F15** (185-194): the pool's geometry (stripe, segment, capacity) is per pool, recorded in the superblock, refused if it differs at boot.
- **F17** (212-220): every commit lists its data stripes (`cp_stripes`).

### 3.3 Design rules the crate was written to (docs/05)

- **R25** (docs/05:393): the envelope is Fabrics', the payload Storage's; `otap-stream` v1 freezes the frame, the record kinds, the cursor and the credit semantics and treats the payload as opaque bytes with a CRC; a chunk is re-derivable from disk by `(lseg, stripe_idx)`; **chunk-aligned resume is the contract; the delta's segments are GC-pinned from `describe()` to `DeltaEnd`**.
- Section 3.3 "The pipe, the delta, the chunk" (docs/05:162): a delta is `(rel, base, target, cp_id)`; steady state ships one committed CP's ingest stripes in staging order; catch-up, resync and coalesced deltas are map walks in PBA order per consistency group, chunked as the live blocks of each on-disk stripe born after `base`.
- "Framing" (164): `VolEvent` and `Holes` are ordered inside the delta before any chunk that references the volume; `Abort(UnknownVol)` is retried every second for 60 s; `DeltaEnd` "carries a BLAKE3 digest over the summary pages and is sent only after the sender's superblock write completed".
- "Cursor, credits, integrity" (166): cursor persisted in a 4 KiB page per pipe at every receiver CP; landing idempotent by `(cp_id, idx)`; sender restart resumes at `landed_contig`; different `cp_id` for the same `cp_seq` discards the partial; receiver restart re-lands what its last CP did not record; credits granted in `Landed` as the receiver's segment writer stages stripes, initial 64 MiB, cap 2 GiB; "three `Abort(Corrupt, idx)` for one chunk make the sender re-read the stripe from disk bypassing cache and verify every 4 KiB CRC; ... a chunk is never skipped".
- "Connections" (170): `Ping` every second when idle, dead after 3 s of silence with data pending, connect budget 1 s, two reconnects then the next endpoint, back-off 1-30 s; `throttle_kbps` (R62).
- 7.7 invariant 8 (docs/05:841): "The replica is at a sender CP boundary after every `Committed`; a BLAKE3 over the pinned root at a common CP is equal on both sides; a `DeltaBegin` with a known `cp_seq` and a different `cp_id` discards exactly one partial; duplicate applies equal zero and resends equal the duplicate count (the loopback harness)". Invariant 3: encode/decode/re-encode byte-identical, N decodes N-1's vectors (`otap-format`, `otap-stream`).
- 7.7 invariant 9: every snapshot retained on the sender and younger than the base exists on the receiver with identical content after catch-up (ordered increments).

### 3.4 Rules stated in the code comments that the session layer must honour

- codec.rs:25-28: for a corrupt non-chunk frame "there is no resend of one frame, and the receiver aborts the delta (`Abort(Corrupt, 0)`), which the sender restarts from `DeltaBegin`".
- codec.rs:30-32: a yielded payload shares the receive buffer's allocation with the frames decoded from the same read; "holding a chunk pins at most that read's allocation".
- cursor.rs:14-17: ranges beyond 4096 (wire) / 500 (page) are dropped and those chunks land again as duplicates; "a sender that sends in order never produces more than a handful".
- cursor.rs:338-342: a refused begin leaves any partial alone; a resumed one allocates nothing.
- cursor.rs:500-504: `to_page` drops ranges beyond 500; a receiver restart re-lands them, harmlessly.
- frame.rs:439-441: "The image is verified as a stripe only when the engine lands it into aligned staging (`Chunk::summary`)".
- flow.rs:4-9: the receiver grants an initial window then more in `Landed` frames "as its segment writer drains staged stripes to disk"; the sender "must stop when the window is empty".
- stripe.rs:20-28: `parse` proves integrity, not identity; a reader that knows which stripe it expects uses `parse_expected` with a `StripeId` and treats `IdentityMismatch` as torn/missing.

## 4. How things happen, in order

### 4.1 Encoding one frame (`Encoder::encode`, codec.rs:153-159 → `encode_into` 124-148 → `header` 90-120)

1. `frame.validate()` (frame.rs:897-977): payload length bound, then the per-kind rules of section 2.4.
2. `meta.check(frame.kind())` (frame.rs:99-117): `chunk_idx` rule, `cp_seq` bound, `base <= cp_seq`. Up to here nothing is allocated (S10).
3. `BytesMut::with_capacity(64 + frame.payload_len())`.
4. `encode_into`: validate again, append 64 zero bytes, `frame.encode_payload(out)` (truncate on error).
5. `header(meta, frame, payload)`: validate again, payload length must be exactly `payload_len()`, `StreamHeader::new(kind, codec)`, `meta.apply`, `set_payload` (Raw) or `set_encoded_payload(payload, raw_len)`, `seal`, `verify` (so a header the peer would refuse is never emitted; defect 2 of QA pass 1).
6. The sealed 64 bytes are copied over the placeholder; `encode` freezes to `Bytes`.

### 4.2 Decoding a byte stream (`Decoder::next_frame`, codec.rs:255-307)

1. Poisoned → the same error again. Deferred (from `drain`) → that error once.
2. No pending header: need 64 bytes (`Ok(None)` otherwise); `StreamHeader::read` → on error poison with `Format(e)`; `wire_len > max_payload` → poison with `PayloadTooLarge`; consume the 64 bytes, keep the header pending.
3. Need `wire_len` payload bytes: `reserve` the shortfall and `Ok(None)`.
4. Split the payload off (zero copy), clear pending, `verify_payload`: mismatch → `corrupt += 1`, `Err(PayloadCrc{kind, chunk_idx, cp_seq})`, decoder stays in sync at the next header.
5. `frames += 1`, `Ok(Some(RawFrame{hdr, payload}))`; the caller then `raw.decode()` → `Frame::decode(&hdr, payload)` (frame.rs:982-1203), which may fail with a body error (`BadBody`, `BodyTooShort`, `BodyTooLong`, `Format`) **without affecting the decoder** (both CRCs were fine; the stream is still in sync; the adversarial `decode_body` helper, lines 206-224, pins that the frame after a refused body decodes).
6. A transport loop (adversarial test 1322-1357): `let n = decoder.needed().clamp(1, READ_CAP); let buf = decoder.buffer(); buf.reserve(n); read into buf; loop { match decoder.next_frame() { Ok(Some(raw)) => handle(raw.decode()), Ok(None) => break, Err(PayloadCrc{..}) => abort_corrupt(..), Err(fatal) => drop_connection() } }`. Once a chunk's header is parsed `needed() == wire_len` and the buffer has reserved it, so the whole payload lands in place.

### 4.3 Receiver resume state over a delta (`Cursor`)

1. `Cursor::begin(base, cp_seq, cp_nonce, chunks)` on `DeltaBegin` (cursor.rs:343-383): base check, cp check, chunk count check, then the four outcomes. On `Resumed` the bitmap already holds the landed set.
2. Per chunk, `Cursor::land(cp_seq, cp_nonce, idx)` (387-405) → `New` or `Duplicate`; `ChunkOutOfRange` for `idx >= chunks`.
3. `resume_point()` (431-440) / `to_wire()` (450-472) at the next `HelloAck`; `to_page(pipe_id)` (505-518) at every receiver CP.
4. `commit(epoch)` (409-421) after `DeltaEnd` once `is_complete()`: `applied_cp_seq = cp_seq`, `applied_epoch = epoch`, landing cleared.
5. `abort()` (424-426) on an abort that gives the delta up (the crate does not say which aborts do; by the design table a `Corrupt` abort keeps the landing and a sender restart resumes it).

### 4.4 Credit accounting across one chunk

Sender: `window.can_send(image.len())` → `window.reserve(image.len())` (spends) → send. Receiver: `cursor.land` → `window.landed(raw_len)` (outstanding→staged) → stage/write → `window.drained(raw_len)` (staged→free) → `grant = window.grant_up_to(want)` (free→outstanding) → `Landed { idx, credits: grant, landed_contig }`. Sender on `Landed`: `window.grant(credits)`. The initial grant: receiver `credits = window.initial_grant()`, `cursor.credits = credits`, `HelloAck{cursor}`; sender `SenderWindow::new(ack.cursor.credits)` (or `reset()` then `grant`).

### 4.5 Full sender session (one pipe, one connection; design tables docs/05-record:3557-3573 and 852-866, docs/05:666-715)

What the crate enforces is marked **[crate]**; what the transport/session must add is **[add]**.

1. **Idle → Connecting.** Trigger: a committed CP above the receiver's `applied` (`Event::CpCommitted` on the sender), or a catch-up order. [add] Pick the endpoint; connect TCP (loopback first; TLS is a later layer, design 3.3 "TLS and zero copy"); 1 s budget; a fresh `Decoder::new()` per connection; `SenderWindow::reset()`.
2. **Hello.** [add] Send `Frame::Hello(Hello{node_id, pipe_id, direction_epoch, capabilities: 0, max_payload: <= MAX_WIRE_PAYLOAD and >= the largest image we will send, initial_credits: 0})` under `FrameMeta{rel, chunk_idx: 0, cp_seq: 0, base: 0, cp_nonce: 0, owner_epoch}` (any `cp_seq >= base` passes). [crate] non-nil ids, `max_payload` in `[8192, 8 MiB]`, `initial_credits <= MAX_CREDITS`, `rsvd` zero.
3. **HelloAck or Abort.** [add] Expect `HelloAck{cursor}` (`Frame::decode_as(&hdr, payload, FrameKind::HelloAck)` or match); an `Abort(Version | StaleEpoch{detail = current epoch})` instead ends the session (Broken / re-handshake with the new epoch). [crate] the cursor is canonical and in bounds (`Cursor::from_wire`). [add] `window = SenderWindow::new(cursor.credits)`.
4. **Choose the delta.** [add] `base = cursor.applied_cp_seq` (the sender's CP numbering). If `cursor.landing == Some(l)` and `(l.cp_seq, l.cp_nonce)` is the delta we were shipping, this is a **resume**: `ResumeBitmap::from_parts(chunks, contig, &sparse)?.missing()` is the resend list (duplicates beyond the 4096 wire ranges are harmless). If the landing names another delta we no longer ship, our next `DeltaBegin` replaces it (`Replaced`/`Discarded` on the receiver). If `base` is not a CP we still hold (no common base) → `NoCommonBase`, nothing to send. Coalescing (more than two queued CPs and no tag between) is design, not crate.
5. **Describe.** [add] Build the delta: for the relationship's volumes, `Engine::live_diff(vol, base_snapshot)` (steady, or the increment's `snapshot_diff(to, Some(from))`), producing `(lba, MapEntry)` lists; partition data entries into stripe images of the chosen size (`SummaryLayout::for_stripe(stripe_bytes).nblocks` per image, section 5.2), hole entries into `HoleRecord` runs; count `chunks` and `bytes = sum(raw_len)`; snapshot tags (`SnapTag{uuid, retention_s, rsvd: 0}`), `write_active` (sender superblock / `Event::IntentWritten`), `acked` (`AckedBytes{vol, bytes}` from the volume table, R40), `cut_age_ms`. Send `DeltaBegin` under `FrameMeta{rel, 0, cp_seq: target, base, cp_nonce: nonce(target), owner_epoch}`. [crate] every bound of section 2.4; `base <= cp_seq`. Note `chunks >= 1` is mandatory (a holes-only delta still needs one chunk; open question 8.6).
6. **VolEvents and Holes.** [add] Before any chunk that references a volume: `VolEvent::Create{vol, class, size_blocks, stripe_bytes, uuid, name}` for volumes the receiver lacks, `Resize`, `Delete`, `SnapTag{vol, uuid, retention_s, name}`; `Holes{records}` (split so a frame stays under 8 MiB). On a resume these are resent (the receiver must make them idempotent, section 7). [crate] per-event canonical fields, name <= 255 bytes UTF-8, hole records in bounds, non-empty `Holes`.
7. **Stream chunks.** For each `idx` to send (all, or `missing()`): [crate] `window.reserve(image.len())` else `Window{..}`: wait for a `Landed`; `Chunk::raw(image)` requires a stripe-sized image; `Encoder::header(&FrameMeta{chunk_idx: idx, ..delta_meta}, &Frame::Chunk(chunk), &image)` then a vectored write of header + image (or `encode`). [add] Interleave reads: `Landed{idx, credits, landed_contig}` → `window.grant(credits)`, mark `idx` acknowledged; `Abort(Corrupt, idx)` → resend `idx` (count per idx; third time re-read from disk bypassing cache and verify every block CRC against its descriptor; an on-disk mismatch is `NoCommonBase(MediaError)` per design); `Abort(Corrupt, 0)` → restart from step 5 (a `DeltaBegin` with the same `(cp_seq, nonce)` resumes; see pitfall 7.4 on the idx-0 ambiguity); `Abort(NoSpace | BaseMismatch | Version | StaleEpoch | UnknownVol)` → stop, Broken (UnknownVol: retry every second for 60 s first). `Ping` every second when idle; answer `Pong{nonce, mono_ns}` to a `Ping`; 3 s of silence with data pending = dead endpoint.
8. **DeltaEnd.** When every chunk has been acknowledged (`landed_contig == chunks` on the last `Landed`, or every idx acknowledged) and the target CP's superblock is durable on the sender (it is: we ship committed CPs; `Event::CpCommitted` is the signal): [add] compute `digest = blake3(images in index order)` (S6 — the crate has no BLAKE3; add `blake3` to the transport crate), send `DeltaEnd{digest, chunks, bytes}` under the delta's meta. [crate] bounds only.
9. **Committed.** [add] Expect `Committed{applied_cp_seq == target, applied_epoch == owner_epoch}`; then advance the base: `set_replication_base(vol, Some(new_base_snapshot))` for each volume (the new base being a snapshot at `target`, `SnapOrigin::Transfer`, created before/at describe so it is pinned while shipping; E36 says a newer committed base supersedes the old one in the same CP); unpin/delete the old; report lag. Back to **Idle**.
10. **Disconnect at any point.** [add] Keep the delta description and the images' source; go to step 1; the `HelloAck` cursor tells what landed. [crate] nothing to do: the sender holds no cursor.

### 4.6 Full receiver session (one inbound pipe; design tables docs/05-record:3575-3585 and 868-878)

1. **Listening.** [add] Accept; fresh `Decoder::new()`; `ReceiverWindow::new(staging_bytes)` (4 KiB multiple, <= 2 GiB); load the pipe's `Cursor` (`CursorPage::read(bytes)` → `Cursor::from_page`, or `Cursor::new(applied_cp_seq, applied_epoch, 0)` from `InboundState`, or `Cursor::new(0, 0, 0)` for a never-replicated target).
2. **Hello.** [add] Decode; check `pipe_id` is one we serve and `direction_epoch` is current (else `Abort{StaleEpoch, idx: 0, detail: current}`); a wrong major never gets here (the decoder poisons: drop). `Decoder::with_max_payload(hello.max_payload)` for this connection (optional tightening). Remember `capabilities` (v1: ignore codec bits, we never send compressed; refuse a compressed chunk later with `Abort(Version)`? — the crate decodes it fine and `summary()` refuses `codec != Raw` with `BadBody{"codec"}`; open question 8.9).
3. **HelloAck.** [add] `cursor.credits = window.initial_grant()` (the window should be fresh for a new connection: `window.reset()` first, since any credits the previous connection's sender held are void after `SenderWindow::reset()`); send `HelloAck{cursor: cursor.clone()}` under `FrameMeta{rel, 0, 0, 0, 0, 0}`. [crate] `to_wire` truncates to 4096 ranges; `validate` refuses an out-of-bound cursor (never clamp `credits` above `MAX_CREDITS`).
4. **DeltaBegin → Landing.** [add] Read `meta = raw.meta()`; `d = DeltaBegin`. `cursor.begin(meta.base, meta.cp_seq, meta.cp_nonce, d.chunks)`: `Err(BaseMismatch{..})` → `Abort{BaseMismatch, 0, detail: applied}` and stay Sessioned; `Err(BadBody{"cp_seq"|"chunks"})` → protocol error, drop; `Ok(Resumed)` → keep staged data; `Ok(Discarded | Replaced)` → discard the previous partial's staged data and `window.drained` it (or `window.reset()` + regrant in the next `Landed`; see pitfall 7.6); `Ok(Started)` → fresh. Check `d.bytes` against free space minus the reserve (`Engine::free_segments()`, `reserve_segments()`) → `Abort{NoSpace, 0, 0}` and `cursor.abort()`. Record `d` (chunks, bytes, mode, tags, write_active, acked) for the commit. [crate] `DeltaBegin` canonical; `cp_seq > base == applied`.
5. **VolEvent / Holes.** [add] Every in-delta frame must carry `meta.cp_seq/base/cp_nonce` equal to the landing's (the crate checks this only on `Chunk` via `land`; check it yourself for `VolEvent`, `Holes`, `DeltaEnd`). Apply `Create` (`Engine::create_volume(vol, size_blocks)` + `set_volume_name`), `Resize`, `Delete`, `SnapTag`, or stage them until commit; unknown `vol` on any frame → `Abort{UnknownVol, 0, detail: vol}`. Holes: stage `(vol, lba, len)` runs for the commit (they become punches). Make both idempotent per landing (a resumed delta resends them).
6. **Chunk.** [add] `meta.chunk_idx`; `cursor.land(meta.cp_seq, meta.cp_nonce, idx)`: `Err(NoDelta)` → protocol error (`Abort(Corrupt, 0)`? drop); `Err(BadBody{"cp_nonce"})` → a chunk of another delta: ignore or drop; `Err(ChunkOutOfRange)` → drop; `Ok(New)` → `window.landed(chunk.raw_len)` (refusal `Window{..}` means the sender overran its credits: protocol violation, drop), copy `chunk.image` into an **8-aligned** staging buffer, `StripeSummary::parse(&staging[..])` (integrity; `IdentityMismatch` is not applicable since the sender's `StripeId` is unknown, but check `hdr.cp_seq == meta.cp_seq && hdr.cp_nonce == meta.cp_nonce`), verify each `Data` descriptor's `crc32c` against its 4 KiB slot (boot.rs:650-666 is the pattern), then hand `(vol, lba, block)` / hole descriptors to the target engine; when the staged bytes are "written" (the engine owns them: at least copied into its arena; strictly, when its CP has them on disk), `window.drained(raw_len)`, `credits = window.grant_up_to(want)`, send `Landed{idx, credits, landed_contig: cursor.landing.bitmap.landed_contig()}`. `Ok(Duplicate)` → the sender spent credits on it: `window.landed(raw_len)` then `window.drained(raw_len)` at once, grant, send `Landed` (design: "drop, `Landed`"). A `PayloadCrc{kind: 5, chunk_idx, ..}` from the decoder → `Abort{Corrupt, chunk_idx, 0}`; `PayloadCrc{kind != 5}` → `Abort{Corrupt, 0, 0}` (the landing stays; the sender resumes).
7. **DeltaEnd → commit.** [add] Check `e.chunks == landing.bitmap.chunks()`, `e.bytes == sum of landed raw_len`, `e.digest == blake3(landed images in index order)` (so the receiver must keep a running BLAKE3 per idx or the images until commit; a resumed delta needs the digest of chunks landed before the disconnect, i.e. persist per-chunk hashes or re-hash from the staged data), `cursor.landing.bitmap.is_complete()` (else `Incomplete` from `commit`). Apply the staged events/holes/blocks as **one** CP on the target pool (`Engine::request_cp()` + tick until `Event::CpCommitted`), then `cursor.commit(meta.owner_epoch)`, write the `CursorPage` and the `InboundState` (`applied_cp_seq`, `applied_owner_epoch`, `acked_cp_seq`), send `Committed{applied_cp_seq, applied_epoch}`. Sessioned again. [crate] `commit` refuses `Incomplete`.
8. **Disconnect / restart.** [add] Keep the cursor (landing included); persist the page at the next receiver CP (design) or immediately; on restart `Cursor::from_page` (ranges beyond 500 lost: those chunks will be re-landed as duplicates); the next `Hello` gets the resume point. A receiver restart must also discard or re-validate staged-but-uncommitted data; the simplest correct rule is to treat every chunk the page did not record as not landed (it is, by `from_page`).
9. **Keepalive.** [add] Answer every `Ping{nonce, mono_ns}` with `Pong{nonce, mono_ns}` (echo both).

## 5. Hook points for Step 6

### 5.1 Where the new code can live

- **A new crate `crates/otap-transport`** (or a `transport` module in `otap-daemon`) depending on `otap-stream`, `otap-cp`, `otap-format`, `blake3`, `bytes`: the sender session, the receiver session, the `Net`-backed loopback transport and a `FileSink`. This keeps `otap-stream` frozen (S8: "the transport is a consumer of this crate") and `otap-cp` free of sockets. The simulator's `LoopbackNet` (`otap_cp::Net`) is the deterministic substrate; a `TcpNet` implementing the same `Net` trait over `std::net::TcpStream` gives the loopback-TCP backend with the same session code (the `Net` contract is ordered reliable byte chunks with `Busy` back-pressure, traits.rs:490-503).
- **Engine additions in `otap-cp`** (the receiver's "engine half" of `DeltaSink`, the sender's `DeltaSource`): see 5.3 and 5.4.
- **Daemon**: a second listener for the stream (not the control framing of E38), or the sender/receiver driven from the engine thread's tick loop with `Net` polled per tick (the engine is tick-driven, E13: "driven by `tick()`, never by a thread it owns").

### 5.2 What a chunk must contain and whether the sender packs its own images

- A chunk is a complete stripe image (section 2.8): `StripeHdr` + `VolBitSet` + descriptors + zero padding to 4 KiB + `nblocks x 4 KiB` data slots, both CRCs sealed (`write_summary`), each `Data` descriptor's `crc32c` equal to the CRC of its slot, each `Hole` descriptor's slot zero with `ZERO_BLOCK_CRC32C`. Size: a stripe size (`stripe_size_ok`): `8192 <= len <= 8 MiB`, multiple of 4096. The smallest image is one summary page + one block.
- **The sender must pack its own images for anything that is a map walk** (catch-up, increments, the initial baseline from base 0, any delta filtered per consistency group): the walk yields `(lba, MapEntry)` per volume, not stripes. Recipe: choose `stripe_bytes` (the sender's `layout().stripe_bytes` is natural, but it is only the sender's; the receiver pool may differ, F15), `SummaryLayout::for_stripe(stripe_bytes)` → `nblocks` per image; for each data entry read the block (`layout.block_pba(lseg, off)` + `backstore.read`), check `crc32c == entry.crc32c`, push `StripeDescriptor::data(vol, lba, entry.birth_cp, entry.crc32c)`; emit holes as `Holes` records rather than hole descriptors (16 B per run instead of 4 KiB per block); `StripeHdr::new(agg_id, StripeKind::Ingest)` with `cp_seq = target`, `cp_nonce = nonce(target)`, `lseg` any non-zero (e.g. 1; `validate_fields` refuses 0), `stripe_idx = chunk idx`, `nblocks`, `group = 0`; `write_summary(&mut image[..summary_bytes], &hdr, &descs)`; the last image of a delta may be short (fewer blocks → a smaller image is still a valid stripe size as long as the summary fits; `MIN_STRIPE_BYTES` needs at least one block).
- **Shipping on-disk stripes byte for byte** (R25's steady state) is possible only for a whole-aggregate relationship with identical geometry on both pools: the engine's stripes mix every volume of the aggregate (`group` is always 0), `Relocate` stripes carry old births and must not ship, and the stripe list of a past CP has no public accessor (`parse_cp_stripes` is used by the boot). For v0.1 the map-walk path covers steady state too (`live_diff(vol, Some(base_snapshot))` over the last committed CP), at the cost of one read per block instead of one per stripe. Either way the receiver re-packs (5.3), so byte-identical shipping buys nothing on the target side today.
- `lseg`/`off` of the sender's entries, `agg_id`/`lseg`/`stripe_idx` of the header, and the sender's `birth_cp` values are meaningless on the target pool except as data to check or record; only `(vol, lba, kind, block bytes, crc32c)` per descriptor is what the receiver applies. Whether the receiver preserves the sender's births is open (8.3).

### 5.3 Receiver side: the smallest coherent engine change

- Today's only ingest path is `serve_write`/`serve_punch` behind a `FrontDoor` request (engine.rs:3402-3560): a write reserves an arena run, `front.copy_in(&req, dst)`, computes CRCs, inserts into the dirty index, places the run and acknowledges; the next CP packs it into stripes with the **target pool's** `cp_seq` as birth (engine.rs:4494). Two routes: (a) a **replication `FrontDoor`** that feeds landed blocks as `RequestKind::Write`/`Discard` requests whose `copy_in` copies from the staged image (no engine change; the receiver is a client of its own pool; `MAX_REQUEST_BLOCKS`/`MAX_PUNCH_BLOCKS` bound each request); (b) a new `Engine::apply_blocks(vol, lba, &[u8], birth: Option<u32>)` that bypasses the front door and optionally preserves births. Route (a) needs no engine change and reuses every crash-consistency proof; route (b) is what "preserve births / `StripeKind::Applied`" needs. The commit "as an atomic CP" is `Engine::request_cp()` then tick until `Event::CpCommitted`; atomicity across volumes holds because one CP commits all of them, but reads served between landing and commit would see partial data unless the volumes are offline/non-serving on the target (open question 8.4).
- Credits: `drained(bytes)` is only honest once the engine has taken the bytes; with route (a) that is after `copy_in` returned (the arena holds them; a CP will write them), which keeps `staging` = the receiver's bounce buffers rather than the arena.
- Persistence: `InboundState` (72 B x 16 in the superblock) can hold `applied_cp_seq`/`applied_owner_epoch`/`acked_cp_seq`; the `CursorPage` has no home (open question 8.1). Until it has one, a page written to a file beside the pool (the daemon's state directory) is the Windows-testable stopgap; `Cursor::from_page` tolerates reserved bytes so a later format home needs no page change.

### 5.4 Sender side

- `Engine::live_diff`/`snapshot_diff` are the birth walks (engine.rs:2958-3003), one volume at a time, materialised into a `Vec<(u64, MapEntry)>` (fine for Windows-sized tests; a streaming variant with the `MapSet::diff` closure is a later optimisation). `set_replication_base` (2523) moves the pin; `create_snapshot(vol, uuid, SnapKind::Crash, SnapOrigin::Transfer)` makes the base; the pin keeps the base's segments alive (`PIN_REPLICATION` refuses deletion, E36) which is the "GC-pin from `describe()` to `DeltaEnd`" of R25 as long as the *target* CP is also pinned by a snapshot while shipping (otherwise the cleaner may relocate blocks under the walk: relocation preserves `(lba, birth, crc)` but moves `lseg/off`, so a sender holding stale entries would read a wrong block and fail the CRC check; treat `Corrupt` from the read as "re-walk").
- The sender needs `cp_nonce` of the **target CP**; `Engine::cp_nonce()` gives the committed CP's; for an older target the nonce must come from the snapshot/CP log (the `SnapRootPage`/superblock of that CP), or the sender always ships the latest committed CP.

### 5.5 What must not break

- `otap-stream`'s wire bytes (golden behaviour pinned by `stream_tests.rs` + `adversarial_stream_tests.rs` + the fuzz target; a change is a `STREAM_MINOR` bump in `otap-format`, E07). Nothing in scope (C) needs a wire change: every field the sessions need exists.
- `FrameMeta::check` / `Frame::validate` refusals: build every frame through the typed structs and let the encoder refuse; never hand-roll headers in production code.
- The engine's `tick()` discipline (E13) and the simulator's determinism (E18): the transport must be pollable from a tick, not thread-owned, to stay testable in `otap-sim`.
- The 10,000-case gate (180 min today): new proptests must stay cheap per case (the simulator walks dominate; `docs/06` section 5).

## 7. Risks, pitfalls and traps

1. **Nothing checks that in-delta frames belong to the landing except `Chunk`.** `Cursor::land` compares `(cp_seq, cp_nonce)`; `VolEvent`, `Holes`, `DeltaEnd` carry the same header fields but the crate never looks. A stale `DeltaEnd` from a previous connection could commit the wrong delta if the session does not compare `meta` with the landing. Also `base` on chunk frames is never compared with the landing's base (only `base <= cp_seq`).
2. **`Cursor::commit` does not verify `DeltaEnd`.** Digest, `chunks`, `bytes` comparisons are the session's; the crate has no BLAKE3 at all (and `blake3` is not a dependency of `otap-stream`; it is a workspace dependency). Decide what the digest covers: frame.rs/S6 say the whole images in index order; docs/05:164 says "over the summary pages". The crate's wording wins unless the lead rules otherwise (E11: record it as an S-rule amendment).
3. **Alignment.** A chunk's `Bytes` is a slice of the receive buffer; `Chunk::summary()` (= `StripeSummary::parse`) needs 8-alignment and a `Holes` payload (16 B records) or a `VolEvent` name of odd length before it will misalign everything after. Always copy into an aligned staging buffer (`#[repr(C, align(4096))]` or `Block4K`) before parsing. `Chunk::stripe_hdr()` works anywhere.
4. **`Abort(Corrupt, 0)` is ambiguous on the wire.** It means both "chunk 0's payload CRC failed" and "a non-chunk frame's CRC failed" (frame.rs:604-606); the `Abort` body has no kind field, only `detail: u64` (unused for `Corrupt`). The safe sender rule: on `idx == 0` restart from `DeltaBegin` (resume keeps every landed chunk, resends events/holes and chunk 0). Or define `detail = kind byte` for `Corrupt` (an S-rule addition, no wire change).
5. **Resend of `VolEvent`/`Holes` on resume.** The cursor tracks chunks only; a resumed delta (same nonce) resends `VolEvent`s and `Holes`; `Create` twice must not fail with "volume exists" and holes must be applied once; stage them per landing or make them idempotent.
6. **Credit bookkeeping on duplicates, discards and reconnects.** A duplicate chunk still cost the sender credits: call `landed()` then `drained()` so `sender.available() == receiver.outstanding()` stays true (the invariant the tests pin). On `Discarded`/`Replaced` the previous partial's staged credits must be released (`drained`) or the window `reset()` and regranted in the next `Landed`/`HelloAck`; never `reset()` the receiver window *after* sending a `HelloAck` grant the sender already holds. On a new connection the sender's old credits are void (`SenderWindow::reset()`); the receiver must also forget them (`reset()` before `initial_grant()`), otherwise `outstanding` leaks and `free()` shrinks for ever. `credits` persisted in the `CursorPage` are stale after a receiver restart (the staging they described is gone): regrant from a fresh window, do not trust the page's `credits`.
7. **`credits_for(image.len())` vs `raw_len`.** For Raw they are equal; under a codec the sender reserves wire bytes while staging is decoded bytes. Phase B problem, but write the session with `raw_len` on the receiver side now.
8. **`DeltaBegin.chunks >= 1`** (`check_chunks`). A delta that only carries holes or `VolEvent`s is unencodable; the sender must include at least one image (possibly of one block) or the lead defines a convention (8.6).
9. **Two CP sequence spaces.** The cursor's `applied_cp_seq`, `Committed.applied_cp_seq`, `InboundState.applied_cp_seq` are the **sender's** CP numbers; the target pool's own `cp_seq` is unrelated. Never feed the receiver engine's `cp_seq()` into the cursor. The first delta to a fresh target is `base = 0` (`Cursor::new(0, ..)`; `Engine::live_diff(vol, None)` walks everything, since births are `>= 1`).
10. **`Cursor::begin` requires `cp_seq > base`**: a "delta" at the same CP (a no-op heartbeat) is refused; use `Ping`.
11. **Header-error = drop the connection.** The decoder never recovers from a bad header; create a new `Decoder` per connection; a poisoned decoder's `needed()` is 0, so a loop that reads `needed()` bytes must check `is_poisoned()` or it spins reading 0 bytes.
12. **`drain` holds an error.** After `drain()` returns frames, the next `next_frame()`/`drain()` may return the held `PayloadCrc`; a session that only calls `drain` in a loop still sees it (as `Err` with an empty prefix). `needed()` is 0 meanwhile.
13. **The 4096-range `HelloAck` truncation and the 500-range page** mean "landed" in the receiver's bitmap can exceed what the sender learns; the sender must tolerate `Landed` for chunks it did not resend (they are duplicates of chunks landed before the disconnect) and must not treat an unexpected `Landed.idx` as an error.
14. **`landed_contig` in `Landed`** is the receiver's view after landing; use it to prune the sender's resend list, not as the only completion signal (sparse landings above it exist).
15. **`Hello.max_payload` lower bound is 8192**, so a receiver can `with_max_payload(hello.max_payload)` safely; but a sender whose stripe size exceeds the peer's bound must split (it cannot: a chunk is one image) → refuse the relationship.
16. **`VolEvent::Create.class` is mandatory** and there is no volume class in the engine (`VolClass` exists only in the stream); the sender must invent one (`File` or `DatastoreLun`) until D5's class table lands. `stripe_bytes` in `Create` is "the stripe geometry at creation" — per volume in the design, per pool in the engine (F15).
17. **`MAX_DELTA_CHUNKS` bitmap**: `Cursor::begin` allocates up to 2 MiB per accepted `DeltaBegin`; bounded, but a hostile peer can churn it; rate-limit begins per connection.
18. **Volume index mapping**: descriptors and hole records carry the sender's dense index; the receiver must map sender `vol` → receiver `vol` (identical only if both pools create volumes in the same order); `VolEvent::Create` carries the sender's `vol` and `uuid`, so key the mapping by uuid.
19. **`Landed.credits` is a grant, not a balance**: the sender adds; a receiver that re-sends a `Landed` (retry) double-grants. Send each `Landed` once per `land` call.
20. **Relocation under a walk**: the cleaner moves live blocks (`build_reloc_stripe`), changing `lseg/off` but not `(lba, birth, crc)`; a materialised `Vec<(lba, MapEntry)>` can go stale while shipping; a block read that fails the CRC check should be re-resolved through the live map, not reported as media error (the design's "third Corrupt → media alert" applies to the *receiver's* CRC failures, i.e. on-the-wire or on-disk corruption, after a fresh read).
21. **`Engine::snapshot_diff` returns `SnapshotOrder`** when the base is not strictly older (`base_cp >= birth`); pick increments in snapshot order (7.7 invariant 9).
22. **`otap-sim`'s `LoopbackNet` preserves `send` boundaries** per message but the `Decoder` does not care; the TCP backend will split arbitrarily; the adversarial `decoder_is_invariant_to_chunking` property is what guarantees equivalence; still test the session under both.
23. **`Frame::decode` requires `payload.len() == wire_len` exactly** and `records()` refuses over-counts before allocating; a session must never slice a payload before decoding.
24. **`write_active`** in `DeltaBegin` is any bitset (not validated); the receiver should not index volumes by it without mapping.

## 8. Open questions for the lead

1. **Where does the `CursorPage` live on the target pool?** No region exists (`DiskLayout`, superblock roots); adding one is a format minor bump (F-ruling, vectors) or a file beside the pool for v0.1; `InboundState` already holds `applied_cp_seq`/`applied_owner_epoch`/`acked_cp_seq` per group but not the landing. Decide: format 2.4 with a per-pipe cursor root, or daemon-side file now.
2. **Who is the receiver's engine half?** Route (a) feed landed blocks through a replication `FrontDoor` (no engine change, target births = receiver CPs, `StripeKind::Ingest`), or route (b) a new `Engine::apply_*` path preserving the sender's `birth_cp` and tagging stripes `StripeKind::Applied`. Invariant 7.7-8 ("a BLAKE3 over the pinned root at a common CP is equal on both sides") needs identical map contents including births, which only (b) can give.
3. **Must the sender's and receiver's stripe geometries match?** The design treats a chunk as an on-disk stripe re-derivable by `(lseg, stripe_idx)` (R25) and `VolEvent::Create` carries a per-volume `stripe_bytes`; the engine has one geometry per pool (F15). If the receiver re-packs, the sender may choose any image size up to the peer's `max_payload`.
4. **Atomic visibility on the target**: are replica volumes offline/non-serving while a delta lands (then one `request_cp` commits it), or must landing go to a staging area invisible to reads until commit (the design's "pending log")? Route (a) makes landed blocks readable before commit.
5. **`Hello.initial_credits`**: is the handshake symmetric (both sides send `Hello`, the receiver's carries its proposal) or does the receiver send only `HelloAck` (then the field is dead at 0)? The crate's doc hints at the former; the design tables show only `Hello → HelloAck`.
6. **A holes-only or events-only delta**: `chunks >= 1` is enforced; either always ship at least one image, or amend S-rules (a wire change to allow `chunks == 0` would need a `STREAM_MINOR` bump since `ResumeBitmap::check_chunks` refuses 0 on both sides).
7. **Digest coverage**: whole images in index order (frame.rs, S6) or summary pages only (docs/05:164)? And is the digest computed over the sender's packed images (then the receiver must keep per-chunk hashes across a disconnect) or recomputable from what the receiver applied?
8. **Steady-state source**: ship the last committed CP via a map walk per volume (`live_diff` against the base snapshot) or add an accessor for the CP's stripe list (F17) and ship `Ingest` stripes byte for byte (needs identical geometry and whole-aggregate relationships)?
9. **Compressed chunks and `CAP_*`**: v1 sends raw; should a receiver that gets a `Chunk` with `codec != Raw` answer `Abort(Version)` or drop the connection? The crate decodes it and only `summary()`/`stripe_hdr()` refuse.
10. **`direction_epoch`, `rel`, `pipe_id`, `node_id`**: where do they come from on a single node with no control-plane store (D3 pending)? Proposal for v0.1: `rel = 0`, `direction_epoch = 1`, `pipe_id`/`node_id` from the daemon config, persisted in the same place as the cursor.
11. **`cut_age_ms`**: the engine does not expose the cut's monotonic time publicly (not checked in depth); either add an accessor or send 0 for v0.1.
12. **The base snapshot's lifecycle**: `create_snapshot(..., SnapOrigin::Transfer)` + `set_replication_base` per volume means one base per volume; the design speaks of a base per consistency group/relationship. Is the v0.1 relationship one volume, one aggregate, or a set?
13. **`Abort(Corrupt, 0)` ambiguity** (pitfall 7.4): define `detail = kind` for `Corrupt` aborts (S-rule addition) or always restart from `DeltaBegin` on `idx == 0`.
14. **The Windows-only `Net` backends**: a `TcpNet` over `std::net` on loopback (blocking reads on a thread with an mpsc into the tick loop) versus making the session async; the engine is strictly tick-driven (E13), so the session must be pollable.
15. **`FileSink` format**: "a file of frames with the same header" (docs/05:715) — does `dump --since` write `Hello`/`HelloAck` too (a cursor in a file is meaningless) or start at `DeltaBegin`? And is the restore the same receiver session reading a file instead of a socket?
