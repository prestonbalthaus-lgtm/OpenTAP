## 1. The consistency-point path and the two tables (scope B1)

Map: `cp-engine-cp-path.md`.

### Summary

The map covers the engine's consistency-point path as it concerns the snapshot table and the catalogue: the MetaStream (reserve/place_at/place_region/finish and the reserve rule that seals the open segment's run when a region does not fit), the exact placement order inside prepare_meta_inner, what Prepared carries to build_slot and finalize, how 'freed' and 'table_regions' drive the deferred release in release_freed, and how boot.rs (not engine.rs) reads the roots through walk_cp/load_cp/read_root. The central finding for scope (B): the snapshot table is re-placed in every CP that has at least one snapshot, changed or not (engine 5173-5179), and is one of the five 'table_regions' released after the next commit; the catalogue is rebuilt in memory every CP (quadratically) but its region is carried forward unchanged when no name changed (5222-5223), which is exactly the carry-forward behaviour an incremental base+chain scheme needs for both tables. The docs (06 section 8, E39) under-state this by saying both tables are rewritten 'in every CP that changes them'. The existing model for a chain is the map's delta_roots/CpLogDir/freed_deltas machinery in otap-map and the 'freed' routing at engine 5371; a CpLogPage cannot carry a SnapRecord or CatalogRec, so a new page type and two superblock roots from the 2,332 reserved bytes (format 2.4, new golden vectors) are needed. The hook points are listed per function with the smallest coherent change, the one assumption that must be broken ('table_regions' means replaced-every-CP), the boot's 'own' tearing rule and the W4 shared-region hazard, and the test helpers in step5_sim_tests.rs / review_step5_sim_tests.rs / records_tests.rs to copy, including how PROPTEST_CASES is honoured.

### Key findings

- The snapshot table region is placed unconditionally in every CP with >= 1 snapshot (engine.rs 5173-5179: records = remaining ++ new_snapshots sorted by snap_id, snap_table_image, place_region) and sits in table_regions (5398), so it is rewritten and released every CP; docs/06 and E39 wrongly say 'in every CP that changes them'.
- The catalogue is carried forward unchanged when `catalog == self.catalog && !self.catalog_ref.is_none()` (5222-5223); otherwise the old ref goes to freed_other and a new region is placed (5225-5233). It is deliberately NOT in table_regions, which is the carry-forward model an incremental scheme must copy for both tables.
- Placement order in prepare_meta_inner: map.prepare_cp places new-volume indexes, delta regions (split at blocks_per_segment), fold pages and fold indexes (map 1022/1109/1129/1301/1325); then rewritten-snapshot pages/indexes/SnapRootPages (5078-5095); new snapshots' SnapRootPages (5143); snap_table (5178); catalogue (5233); cp_stripes (5243); map_roots (5249); cp_log_head (5252); seg_table reserved last (5254) and filled after set_live_bytes (5344). E24's 'reserved first' wording is wrong about the order.
- freed (5370-5397) = previous table_regions + prepared.freed_deltas + freed_other (deleted snapshots' root pages as RootRef::new(pba,1,0), the replaced catalogue) + rewritten old root pages + unreferenced pages/indexes, dedup by pba; finalize pushes (cp_seq, freed) and release_freed pops entries with cp + keep <= cp_seq (keep 1, or 2 under a trusted opaque barrier), decrementing meta_live via layout.segments_of_region and freeing metadata segments at meta_live == 0.
- table_regions = [map_roots, cp_log_head, snap_table, cp_stripes, seg_table] minus NONE (5398-5401) is the one place encoding 'replaced every CP'; a base or chain region placed there would be freed while still referenced. The Engine field's doc comment (1387-1388) names only three of the five.
- MetaStream::reserve (meta.rs 186-217): if room < pages, every Open segment of the current run is sealed and `ceil(pages / blocks_per_segment)` ADJACENT free segments are allocated via allocate_run with `reserve` kept free (0 boot, 1 shutdown, 2 otherwise; engine 4853-4857); finish() seals every run segment except the one holding the append point.
- MetaStream implements otap_map::RegionWriter (meta.rs 344-348); MetaError::NoSpace maps to MapError::NoSpace, and step_staging (4439-4448) treats EngineError::NoSpace | Map(NoSpace) | Meta(NoSpace) as a full pool, dropping a fold (fold_blocked_at = free_segments) and retrying as a plain CP; this keys on job.folds() (the map fold), so a table fold needs its own flag.
- build_slot (5608-5613) sets sb.seg_table, cp_log_head, map_roots, snap_table, catalog, cp_stripes from Prepared; Superblock::verify (superblock.rs 583-646) checks no root at all; roots are checked only by boot::read_root (pba != 0, on-device, <= 4 GiB, exact length + CRC).
- Superblock has `reserved: [u8; 2332]` at offset 1760 (catalog @1728, cp_stripes @1744); new roots take bytes from it with a minor bump to 2.4, a tests/vectors/v2.4 set and a pinned manifest hash (E05, E35); the boot currently refuses `(ver & 0xff) < 3` (boot.rs 269-271).
- Boot reads the tables in boot::walk_cp, not engine.rs: map_roots -> parse_map_roots (395-403); cp_log_head -> CpLogDir::decode with dir.cp_seq == sb.cp_seq (424-444); cp_stripes; catalog with W4 tolerance (466-487: a CRC/parse failure yields empty catalogue, catalog_ref NONE, catalog_damage; only an Io error tears); snap_table -> parse_snap_table where any failure is TornReason::Snapshot (493-498); per record load_snapshot, tearing only when birth_cp == sb.cp_seq ('own', 500/511).
- load_cp (boot 698-703) computes meta_live over every verified region (`regions`), including each snapshot's root page, index and map pages; table_regions = the walk's four + seg_table (760-766); evaluate walks the other verified slots and protects their segments for keep+1 commits (boot_protect, engine 6010); freed_pending starts empty at boot (2014) and the boot commit's `freed` carries the selected slot's table regions.
- The in-memory state between CPs: Engine.snapshots: Vec<SnapState { record: SnapRecord, pinned: Option<PinnedRoot>, damage }> sorted by snap_id, plus snap_requests, snap_deletes, pin_changes, catalog: Vec<CatalogRec>, catalog_ref; prepare_meta_inner clones the whole snapshots vector (with every pinned page index, 16 B per 1,024-block page) twice per CP (4906, 5168) and rebuilds the catalogue with a linear find per volume and per snapshot (5191-5204): quadratic.
- Region sizes: snap_table ceil(S/64) pages (64 B records; max 1,024 x 271 = 277,504 records = 4,336 pages); catalogue ceil(N/8) pages (512 B records; max 278,528 = 34,816 pages = 136 MiB); map_roots <= 16 pages; cp_log_head ceil((deltas since fold + pages)/252); seg_table (segments+1)*32 B every CP; cp_stripes 16 B per stripe; one SnapRootPage per new or rewritten snapshot.
- CpLogPage cannot carry a SnapRecord or CatalogRec: CpLogRec is a fixed 32-byte map record whose validate refuses an unmapped entry; the brief's 'deltas in CpLogPage' needs a new page type (64-byte header with magic/ver/count/cp_seq/page_seq/agg_id/cp_nonce/CRC like CpLogPageHdr, then op + record).
- The existing 'list of regions since a fold' is CpLogDir { cp_seq, fold_cp_seq, deltas, pages } encoded as CpLogDirPages (252 RootRefs each, totals in every header, decode checks agreement and count); the map keeps delta_roots across CPs, appends in apply (map 1610), returns them as freed_deltas at a fold (map 1343), and the engine routes freed_deltas into freed (5371).
- should_fold (4651-4698) folds on request, an eligible snapshot request (snap_eligible: after_gen <= job gen), a pending volume op in a non-cleaning CP, a clean shutdown with a dirty overlay, or the FoldPolicy bounds (log bytes + pending*32, cps_since_fold + 1, dirty pages, overlay entries, interval since last_fold_ns) when dirty; blocked by fold_damaged and fold_blocked_at. A table fold policy should mirror this including the blocked-at and degrade-to-append behaviour.
- Snapshot lifecycle through the records list: create_snapshot_named validates uuid/name/limits and pushes a SnapRequest + request_fold; prepare_meta moves eligible requests into job.snaps and fail_cp splices them back; ids are next_snap_id + i (5140); deletions run in id order against `remaining` (4919), pins rewrite flags and re-seal (5122-5128), rewritten snapshots get a new SnapRootPage (5088-5098); finalize applies all and sorts (5744-5781, 5943-5953).
- A shared base/chain region would tear every ring candidate if damaged (the W4 failure E39 fixed for the catalogue); the map's delta chain already has this exposure; the lead must pick tear vs drop-and-warn for the tables and apply the 'own' rule per chain region's cp_seq.
- Nothing outside otap-cp and otap-format reads the tables (grep: only otap-format/tests, review_sim_tests.rs, the engine); PoolStatus exposes snapshots, catalog_entries, fold_cp, cps_since_fold, log_bytes_since_fold as the policy's observables.
- Test patterns: step5_sim_tests.rs:993 (catalogue across daemon crash, torn power cut, clean restart), review_step5_sim_tests.rs:534 (flip a byte in the shared catalogue region, boot, verify_recovery), review_sim_tests.rs:103 newest_slot + 577-586 (read snap_table from the newest slot, parse_snap_table, corrupt a root page), records_tests.rs:661/434/515 and catalog_tests.rs:239/257 (round trips, disorder, bit flips), format_tests.rs:2455/2517 (golden images and the ignored vector writer); PROPTEST_CASES is read explicitly by proptest_cases()/cases() and passed as `cases:` with failure_persistence: None.
- Pitfalls: a changed SnapRecord must be re-sealed before snap_table_image (which verifies CRCs) or the CP fails the tick, not the pool; freed_other RootRefs carry CRC 0 and the free path dedups by pba only; the reserve rule wastes the open segment's remainder when a large fold region comes after small ones; a boot that drops the catalogue (catalog_kept) must also reset any chain; MapRoot/parse_map_roots need exactly vol_count slots while the tables are zero-terminated.

### Open questions

- Delta encoding: new page types per table (op + SnapRecord, op + CatalogRec), one shared table-log page type, or copy-on-write paged tables with an index region (no replay/fold, but an O(pages) index per CP: 68 pages for the maximal snapshot table, 544 for the maximal catalogue)? CpLogPage cannot hold either record.
- One chain directory region (modelled on CpLogDir, listing base + chain for both tables) or two new superblock roots (snap_log_head, catalog_log_head), or a linked chain with no directory?
- Table fold policy: which bounds (regions, bytes, CPs, time); does a map fold also fold the tables; does a clean shutdown fold them so a clean boot reads a base only?
- Damage policy for a shared base/chain region: tear the candidate (today's snapshot-table rule) or drop with an OperatorWarning (today's catalogue rule, W4)? Dropping the snapshot table loses pins and records of real data.
- Format 2.4 with the boot refusing minors < 4 (the Step 4/5 precedent), or the first minor that also reads 2.3 pools as 'base only, empty chain'?
- Does scope (B) also cover the segment table (400 MiB per CP at 100 TiB) and the fold's whole-index rewrite, which docs/06 section 7 lists under 'the incremental tables' but the brief does not?
- May the implementer restructure the in-memory state (Arc<PinnedRoot> in SnapState, a keyed catalogue map) to remove the per-CP clones and the quadratic catalogue rebuild, or is scope (B) on-disk only?
- With a chain, a Create record's snap_id can be reused after a rewind; should chain records be keyed by uuid for replay?
- Should the attestation pass (otapctl pool verify) list the table chain's regions and CPs and check the materialised tables against the engine's in-memory lists?

## 2. The engine surface, the boot verification and liveness (scopes B2, C)

Map: `cp-engine-api-boot-verify.md`.

### Summary

The map covers the engine's public surface (engine.rs 1-3352 and the private accounting paths 3600-6266), boot.rs in full, segments.rs, layout.rs, meta.rs, cleaner.rs, the otap-map walkers and the otap-format layouts, with file:line for every item a verifier or a sender will touch. The boot ranks the four raw slots with SuperblockSlot::rank (owner_epoch, cp_seq, cut_seq, A wins), refuses pre-2.3 layouts and a geometry mismatch, then tries candidates newest first: load_cp reads the segment table, walk_cp reads every root region (map roots, each volume's index, the directory and deltas, directory pages, cp_stripes, catalogue, snapshot table, each root page and pinned index) and verifies each against its RootRef; every stripe in the cp_stripes list is checked by parse_expected with the CP's nonce (data CRCs too under a trusted opaque barrier after an unclean stop); a read error fails the boot, a region that does not verify tears the candidate, and damage to an older snapshot or the catalogue is contained rather than torn. The only existing reconciliation is audit_liveness: it walks the live map (overlay included) and every readable pinned root with diff/pinned_diff at base 0, dedups by (lseg, off), and compares per-segment counts with the private data_live map; it reads no data block and ignores meta_live and the deferred lists. The on-disk Superblock::freed_pending is reserved and always NONE: the real deferral is the in-memory freed_pending, dead_data_pending and boot_protect queues released by release_freed at N+1 (N+2 under the trust policy), and SegEntry::live_bytes is written from data_live*4096 or meta_live at each CP's table image. The map tells a verifier exactly what to expect per block (desc.vol/lba/kind/birth/crc equal to the entry, block CRC equal to entry.crc32c, lseg == pseg, block_pba and the inverse of block_off), and that full stripe identity (nonce) exists only for the committed CP. For the sender, snapshot_diff(snap, Some(base)) walks the pinned tree for entries with birth_cp > base's birth_cp (data at their current, possibly relocated, address, and holes, one entry per LBA, LBA order), refuses a base not older than the snapshot, and live_diff does the same over the committed map; set_replication_base moves PIN_REPLICATION in one CP and delete_snapshot honours pending pin changes. The attestation should be an Engine method inside otap-cp run between ticks after wait_quiet (private state, uncommitted allocations on the live table during staging), chunked per segment if needed. Two defects/traps surfaced: load_cp double-counts metadata regions shared by the live tree and a pinned snapshot (Step 4 review hazard 12, never closed), and failed CP attempts leave stripes with the committed cp_seq+1 under a different nonce in open segments.

### Key findings

- Backstore::read(&mut self, pba: u64, dst: &mut [u8]) -> Result<(), IoError> (traits.rs:250) is synchronous; FileBackstore/SimBackstore refuse a zero or non-4096-multiple length (BadLength) and a range past capacity (OutOfRange), device errors become Device{errno}; zero-copy parsers need 8-aligned buffers and every reader relies on a Vec<u8> for that.
- boot::read_ring (boot.rs:177-191) reads all four slots and both intents raw; SuperblockSlot::rank (superblock.rs:789-812) keeps slots that verify, match agg_id and sit at their own location, orders by (owner_epoch, cp_seq, cut_seq, is_A) descending, NewerFormat is a hard stop; evaluate (257-348) then refuses minor < 3 (OldLayout) and a geometry mismatch before trying candidates.
- A candidate is loaded by load_cp (577-772): seg_table image, walk_cp (385-533: map_roots, every volume's index via index_root_ref + verify_index, directory + deltas + directory pages, cp_stripes, catalogue, snap_table, each SnapRootPage + pinned index), replay of deltas, then every CpStripe verified by StripeSummary::parse_expected with StripeId{agg_id, lseg=pseg, idx, sb.cp_seq, sb.cp_nonce} (624-674), data-block CRCs checked only when trusts_opaque_barrier && !is_clean_shutdown.
- What tears vs fails: TornReason::Io fails the whole boot (BootError::Io, 292-295) so a transient read error never rewinds; any other TornReason skips the candidate; a snapshot root page/index that does not verify tears only when record.birth_cp == sb.cp_seq (500, 511), else SnapshotDamaged; a catalogue that does not verify is catalog_damage, never torn (466-487).
- Superblock::freed_pending [RootRef;2] is reserved and always NONE (superblock.rs:469-473; build_slot never sets it) and SegState::FreedPending is never written; the deferred frees are the private Engine::freed_pending VecDeque<(cp, Vec<RootRef>)>, dead_data_pending VecDeque<(cp, Vec<pseg>)> and boot_protect, released by release_freed (6004-6076) when cp + keep <= cp_seq with keep = 2 under a trusted opaque barrier else 1.
- SegEntry::live_bytes is written at every CP from the engine's maps (engine.rs:5330-5343): data segments get data_live[pseg]*4096, metadata segments get meta_live[pseg]; data_live changes in prepare_meta_inner (5256-5320: replaced entries decrement unless pinned_by a remaining snapshot, relocation moves one count, deleted snapshots release, drained segments forced to 0) and keys are removed by free_segment/fail_cp; the boot seeds data_live from entry.live_bytes/4096 (1901-1907).
- meta_live grows by every region a CP places (stream.bytes_per_segment plus the reserved table region, 5321-5329) and shrinks only when a queued region is released; a metadata segment is freed at meta_live == 0; exact reconciliation formula: meta_live[pseg] == bytes of the committed CP's regions in pseg + bytes of regions still queued in freed_pending there.
- DEFECT (unclosed): load_cp (boot.rs:697-703) sums every region without dedup by pba while walk_cp pushes both the live index/pages and each snapshot's pinned.regions(); a snapshot shares the live root right after its fold (PinnedRoot::from_parts at 5161), so after a reboot meta_live over-counts and those metadata segments cannot reach zero until the next boot; listed as Step 4 review hazard 12 (docs/reviews/step4-adversarial-qa.md:52) and neither fixed nor recorded as a limit in docs/08 623-631.
- audit_liveness (2820-2878) is the closest existing reconciliation: map.diff(vol, base 0) over every rooted volume (overlay interleaved, holes included) and map.pinned_diff over every snapshot with pinned.is_some(), dedup by (lseg, off), compare found[pseg] with data_live[pseg]; it reads no data block, checks no CRC, ignores meta_live and the deferred lists, and skips damaged snapshots (their blocks show as drift).
- What the map expects per block: entry.addr packs lseg:36|off:16|plen:12 with lseg == pseg (no relocation tables, E34/E37); physical block = layout.block_pba(lseg, off); stripe idx = off / blocks_per_stripe, data slot i = off - idx*blocks_per_stripe - summary_bytes/4096 (inverse of block_off, layout.rs:197); descriptor i must be Data with vol/lba/birth_cp/crc32c equal to the entry and crc32c(block) == entry.crc32c (read_entry 3710-3736 checks only the block CRC); ingest stripes have hdr.cp_seq == birth, relocation stripes keep old births (4475-4611).
- Full stripe identity (nonce) is available only for the committed CP (cp_nonce() 3210 plus the cp_stripes list); older CPs' nonces exist only inside stripe headers; cleaner::scan (cleaner.rs:197-264) shows the identity rule for older stripes: skip a header that does not name (agg_id, pseg, idx), treat an all-zero summary as never written, treat any other unparsable summary as damage.
- Failed CP attempts leave leftovers: fail_cp (4256-4313) frees job_data_segments but keeps open_data.next_idx advanced, and the retry reuses cp_seq+1 with a new nonce (3972-3973), so data segments can hold stripes with the committed+1 cp_seq under several nonces; stripes in the open data segment at idx >= the committed slot's open_data_idx are not committed.
- Engine exposes no accessor for the SegmentTable, freed_pending, dead_data_pending, boot_protect, open_data or snapshots[].pinned (only free_segments, live_blocks, meta_live_bytes, map() as &MapSet, backstore() as &mut B, layout(), cp_seq(), cp_nonce(), snapshots()), so the attestation must be an Engine method inside otap-cp; map() is & while MapSet::get/diff/pinned_diff need &mut, so engine code uses `let Engine { map, backstore, .. } = self` with BackstoreReader (1351-1361).
- Consistency window: open_data_segment allocates on the live table during staging (4613-4635) while MetaStream works on a copy swapped at finalize, so when phase() != Idle self.segments shows uncommitted data allocations; run the pass after is_quiet() (3194-3200; the daemon's Pool::wait_quiet pool.rs:561) or exclude job_data_segments; the committed map/data_live/meta_live are immutable between ticks even mid-CP; the pass must not mutate, drain take_events (single consumer, mem::take) or hold backstore() across a tick.
- The daemon runs every control request synchronously between ticks on the one engine thread (Daemon::run daemon.rs:278-318, Pool::wait_for/wait_until/wait_quiet pool.rs:476-566), so a whole-pool scan stalls the data path for its duration; the cleaner already does synchronous whole-segment reads inside new_job (plan_clean 4020-4146); a resumable per-segment VerifyJob is the chunking option.
- snapshot_diff(snap_id, base: Option<snap_id>) (2958-2991): base resolves to that snapshot's birth_cp (0 for None, must be the same volume, NoSuchSnapshot otherwise), refuses base_cp >= snapshot birth (SnapshotOrder) and a damaged snapshot; pinned_diff (otap-map 1714-1734) reads only index pages with max_birth > base and emits entries with birth_cp > base && !unmapped in LBA order: data at the snapshot tree's current (possibly relocated) address and holes, one entry per LBA (state, not history), nothing from the overlay.
- live_diff(vol, base) (2995-3007) uses MapSet::diff (1620-1673): the committed map's overlay interleaved with pages, same birth filter and order; live entries are not pinned (the next CP or the cleaner can move or free them), whereas a snapshot pins blocks by birth but not by address (rewrite_pinned relocates, SegmentCleaned), so a sender must re-resolve after a clean touching its segments.
- set_replication_base(vol, Some(id)) (2523-2560) sets PIN_REPLICATION on the new base and clears it on every other snapshot of the volume via set_snapshot_pins, durable at the next CP (Event::SnapshotPinned per change); delete_snapshot (2464-2486) checks effective_pins (pending changes win) so 'set new base then delete old' needs no CP in between; transfer snapshots (SnapOrigin::Transfer/Divergent) count against MAX_RESERVED_SNAPSHOTS = 16, user/scheduled against 255.
- snapshot_read (2916-2954) bounds by the snapshot's lba_count (not the volume's current size), reads through pinned_get and read_entry (CRC checked, Corrupt{vol,lba}); peek_disk (3117) is the committed-map view; map_entry (3157-3163) returns None for unmapped, no root OR an unreadable page, so it must not be used to detect damage.
- Stream bodies the sender fills (otap-stream frame.rs): DeltaBegin{mode Increment{from_snap,to_snap}, chunks, bytes = sum raw_len, cut_age_ms, write_active, tags: SnapTag{uuid, retention_s}, acked: AckedBytes}, VolEvent::Create needs size_blocks, stripe_bytes, a volume uuid (the engine has none) and name, Holes of HoleRecord{vol,len,lba} precede chunks, Chunk::raw(Bytes) is a whole stripe image (summary() needs 8-aligned bytes), DeltaEnd.digest = BLAKE3 over images in index order (S6); StreamHeader carries cp_seq, base <= cp_seq, cp_nonce, owner_epoch.
- Invariants to keep: E17 order data->metadata->flush->A->B with the map changing only after B; E14 trust only what a root names; E21/E24 deferral depth; E25/E36 pinned_by rule (a snapshot with birth >= block birth keeps it live); E31 META_RESERVE_SEGMENTS = 2; E37/E39 a relocating CP carries no deletion or volume op; S1-S10 for frames; PROPTEST_CASES overrides any explicit cases so every property test is in the gate.
- Test patterns: SimConfig::small(seed) + Sim::new/boot/write/punch/snapshot/request_cp/request_fold/crash_power/crash_daemon/shutdown_clean/verify_recovery/check_diff/audit_liveness (harness.rs), SimBackstore::corrupt_durable(offset, bytes) for damage after crash_power (review_sim_tests.rs 1013-1017), newest_slot (103-118) for reading the ring outside the engine, fifo1()/no_auto_fold()/TearPolicy constants and tick_until on phase()+pending_kinds for phase-targeted crashes, proptest_cases(64) reading PROPTEST_CASES (step5_sim_tests.rs 1376-1409), in-process Daemon::new(config())/handle(Request::PoolFormat|PoolBoot{arena: Heap}) on a 128 MiB file (daemon_tests.rs 1-110), LoopbackNet (otap-sim net.rs) implementing otap_cp::Net with delay, partitions and Busy.
- The Step 6 brief in docs/10 (578-627) is truncated mid-transport-scope ('Dual Transport Backends: 1'); the attestation items it lists are ring CRC and monotonicity, every volume's radix map and pinned roots, every live segment's summaries and block CRCs against the map's (lseg, off, birth_cp), and exact reconciliation with SegEntry::live_bytes and the deferred-free accounting without panicking.

### Open questions

- Which nonce keys an increment delta: StreamHeader.cp_nonce is 'the nonce of cp_seq' and keys the Cursor, but a snapshot's CP nonce is recorded nowhere except in stripe headers born at that CP (which relocation can rewrite); record cp_nonce in SnapRootPage (format 2.4), derive it from the snapshot uuid, or make the target snapshot uuid the delta identity?
- Chunk form on the wire: verbatim stripe images (foreign, dead and pre-base blocks included; the receiver filters by descriptor) or repacked Applied stripes built from the delta's blocks as docs/05 line 162 describes (then the receiver needs write_summary and DeltaBegin.bytes changes meaning)?
- Volume identity for VolEvent::Create: volumes have an index and a catalogue name but no uuid; derive from (agg_id, vol), add a uuid to CatalogRec (format change), or send nil?
- Where the attestation runs: whole between ticks (blocks the data path for the scan), chunked per segment across control-plane polls (a VerifyJob in the engine), or a second thread over its own read-only backstore (consistent per segment only, races with segment reuse after the deferral)?
- Must the pass require is_quiet() (unreachable on a full pool: wait_quiet returns early there) or run mid-CP with the open-segment exclusions?
- The boot's double count of shared metadata regions (load_cp 697-703, Step 4 hazard 12): fix by deduplicating regions by pba (changes meta_live after every boot with snapshots) or record it as a limit the attestation tolerates?
- Report shape and exit status of otapctl pool verify: non-zero on any finding, or warnings for drift the engine already tolerates (damaged snapshots, damaged pages, a dropped catalogue)?
- Should the attestation also verify the intent slots and the other ring pair's regions (what evaluate walks only to compute protected), or the committed CP alone?
- DeltaBegin.write_active and acked per volume: add Engine accessors (durable_active and unflushed_bytes_after are private) or let the sender read the committed slot through read_ring + rank?
- Is MAX_RESERVED_SNAPSHOTS = 16 per volume enough for base + target per relationship plus retries, and should a transfer snapshot be user-deletable before it becomes the base?
- Once the catalogue and snapshot table become incremental (scope B's other half), the roots walk in section 5.1 changes shape; should the attestation be written against the new tables from the start?

## 3. The on-disk format and the format-change procedure (scope B1)

Map: `format.md`.

### Summary

## 5. The ublk path and the kernel recovery protocol (scope A)

Map: `ublk-sys-frontdoor.md`.

### Summary

The map covers otap-sys::ublk (UAPI, nine repr(C) structs, builders, the Linux UblkControlRing/UblkQueue), otap-ublk (Transport, UblkFrontDoor's tag state machine, MockTransport, UblkDevice/LinuxTransport), the daemon's device call sites, and the 6.12 driver's recovery semantics read from ublk_drv.c. The start_user_recovery/end_user_recovery builders already exist in otap-sys and no new unsafe block is needed; a recovery path is a sibling of UblkDevice::create/open_queue/start that runs GET_DEV_INFO, START_USER_RECOVERY (retrying -EBUSY), then opens /dev/ublkcN, mmaps, fetches every tag and issues END_USER_RECOVERY with the new pid, all on the engine thread because the kernel pins a queue to the task of its last fetch. The kernel's exact rules are recorded: START is -EBUSY while the char fd is held or the device is not QUIESCED, END blocks until every tag is fetched, requests the dead daemon never fetched are requeued and re-delivered after END, requests it had fetched but not committed are failed with EIO unless UBLK_F_USER_RECOVERY_REISSUE is set, and the quiesce can take up to blk-mq's 30 s request timeout when every tag was owned at death. The kernel knows nothing of pools or volumes; the write-once 64-bit ublksrv_flags (copied through untouched at ADD_DEV, currently left 0) is the only kernel-held tag, and GET_DEV_INFO (not GET_DEV_INFO2, which demands a dev path even for root) is the probe. A dead daemon's device shows state QUIESCED with the dead pid and can be STOP_DEV/DEL_DEV'd by any root process, but DEL_DEV blocks while anyone holds the char fd and a quiesced device hangs I/O rather than failing it in 6.12. The mock must be split into a shared MockDevice (states, open bit, pid, ublksrv_flags, per-tag Active/Owned, requeue list, an application-results ledger, explicit cancel/quiesce/release steps) and a per-daemon transport handle so the -EBUSY window, the re-dispatch after END and the reaper's classification are testable on Windows; the existing frontdoor_tests, the proptest model and engine_tests' crash pattern are the templates. Nine open questions are listed, chiefly where the reaper lives, whether to enable REISSUE, the ublksrv_flags layout, and the -EBUSY retry budget against the 30 s window.

### Key findings

- CtrlCommand::start_user_recovery(dev_id) (ublk.rs:807) and end_user_recovery(dev_id, pid) (ublk.rs:815, data[0]=pid) already exist; no get_dev_info2 or del_dev_async builder, but CtrlCommand::new(UBLK_U_CMD_DEL_DEV_ASYNC, id, None) suffices. No new unsafe block is needed: START/END/GET_DEV_INFO/DEL go through UblkControlRing::execute (ublk.rs:1213), fetches through UblkQueue::push_fetch (ublk.rs:1382).
- UblkControlRing::execute returns a negative CQE result as Err(io::Error::from_raw_os_error(-r)) (ublk.rs:1272-1273): -EBUSY arrives as raw_os_error()==Some(16); the kernel's own -EINTR (from an interruptible wait) is not retried.
- Kernel protocol, in order: GET_DEV_INFO -> START_USER_RECOVERY -> open /dev/ublkcN -> mmap -> FETCH every tag -> END_USER_RECOVERY(new pid). Opening the char device before START sets UB_STATE_OPEN and makes START -EBUSY (ublk_drv.c:1306, 2719-2723).
- ublk_ctrl_start_recovery (ublk_drv.c:2694-2736): -EINVAL without USER_RECOVERY or when nr_queues_ready==0; -EBUSY while UB_STATE_OPEN is set or state != QUIESCED; on success every queue is reinit (nr_io_ready=0, ubq_daemon=NULL, io flags cleared), ub->mm=NULL, completion re-armed.
- ublk_ctrl_end_recovery (ublk_drv.c:2738-2774): waits (interruptibly, -EINTR) until every queue has every tag fetched, then -EBUSY if state != QUIESCED, else ublksrv_pid=data[0], unquiesce, kick the requeue list, state=LIVE.
- What dies with the daemon (ublk_drv.c:1061-1070, 1090-1098, 1387-1408): requests delivered to the server and not committed (OWNED_BY_SRV) are failed with EIO unless UBLK_F_USER_RECOVERY_REISSUE, in which case they are requeued; requests dispatched but never delivered are requeued under USER_RECOVERY regardless of REISSUE; not-yet-dispatched requests wait in the quiesced blk-mq queue. All requeued ones arrive on the new daemon as ordinary RES_OK fetch completions after END.
- The quiesce is scheduled only from the dying-daemon path: io_uring's cancel of pending fetch cmds (ublk_drv.c:1464-1497) or ublk_timeout when the daemon is PF_EXITING and every tag is owned (ublk_drv.c:1224-1245, blk-mq's 30 s request timeout). A daemon that died with all 128 tags owned leaves the device LIVE-with-dead-pid for up to 30 s; a 2 s retry budget misses it.
- 6.12 has no UBLK_F_USER_RECOVERY_FAIL_IO (UBLK_F_ALL at ublk_drv.c:55-63): a QUIESCED device hangs I/O to /dev/ublkbN until END or STOP_DEV; only STOP_DEV (force_abort, ublk_drv.c:1585-1586, 1271-1272) unwedges it.
- GET_DEV_INFO of a dead daemon's device: state=2 (QUIESCED) after the quiesce work (1=LIVE before it), ublksrv_pid=the dead pid (STOP_DEV sets -1, ublk_drv.c:1611), flags include USER_RECOVERY|USER_COPY|CMD_IOCTL_ENCODE plus URING_CMD_COMP_IN_TASK (ORed in at ADD_DEV, ublk_drv.c:2447-2448), ublksrv_flags as created, owner_uid/gid root.
- The kernel does not know the pool or volume. ublksrv_flags (u64) is copied through untouched at ADD_DEV (ublk_drv.c:2434), returned by GET_DEV_INFO, never interpreted, write-once. UblkDevice::create leaves it 0 today (device.rs:90-97); proposed layout magic:16 | vol:16 (MAX_VOLS=1024) | agg_id prefix:32, corroborated by GET_PARAMS dev_sectors.
- Use GET_DEV_INFO, not GET_DEV_INFO2: for non-unprivileged devices every control command needs CAP_SYS_ADMIN, and GET_DEV_INFO2 additionally demands a dev_path in the buffer even for root (ublk_drv.c:2831-2851).
- Enumeration: no list command; probe ids 0..ublks_max (module param, default 64, ublk_drv.c:494/3058; -ENODEV for an unused id at 2921-2925) or list /sys/class/ublk-char/ublkcN. ADD_DEV fails -EACCES once ublks_added >= ublks_max (2417-2419): unreaped stale devices exhaust the budget.
- Any root process can STOP_DEV then DEL_DEV a dead daemon's QUIESCED device (ublk_stop_dev 1593-1618, ublk_ctrl_del_dev 2512-2549), but DEL_DEV with wait blocks (interruptibly) until the cdev's last reference drops, which an open /dev/ublkcN anywhere holds; DEL_DEV_ASYNC (0x8020_7514) returns at once. STOP_DEV/DEL_DEV have no owner check, so a mis-classified live device is killed silently (every fetch gets RES_ABORT, the front door retires every tag, nothing in Pool notices).
- Thread pinning: ublk_mark_io_ready sets ubq_daemon=current at the queue's LAST fetch (ublk_drv.c:1625-1627) and later commands from another task are -EINVAL (1706-1707); mmap is pinned to one mm (1329-1334). Pool::boot and handle run on the "dbladed-engine" thread (daemon.rs:243-251), so recover_device must run there like create_device does.
- LinuxTransport::poll treats ANY non-zero fetch/commit result as Abort (device.rs:297-303): a fetch refused -EBUSY (queue already ready) or -EINVAL (wrong thread) silently retires the tag for the daemon's life. Issue recovery fetches exactly once per tag from the serving thread.
- UblkFrontDoor needs no change for recovery: a recovered queue is a fresh front door (all tags Idle, gen 0; frontdoor.rs:247-282) and requeued requests arrive as normal QueueEvent::Request. Generation (request_id = gen<<32|q<<16|tag, frontdoor.rs:213) only guards same-daemon staleness; a refused commit retires the tag (frontdoor.rs:426-434).
- UblkDevice has no Drop (device.rs:70-76): only delete() removes the kernel device; delete_inner drops the queue (closing the char fd) before DEL_DEV (device.rs:203-208). A recovered device must set started=true so delete() issues STOP_DEV first; START_DEV after recovery would be -EEXIST (ublk_drv.c:2248-2251).
- Hook points: otap-ublk UblkDevice::recover(dev_id, retry) mirroring create/open_queue/start plus pure probe/delete helpers; set ublksrv_flags in create; pool.rs:281-293 boot loop scans the kernel and calls recover_device before ensure_device; new Request::DeviceList/DeviceReap in otap-control protocol.rs:42 (deny_unknown_fields), otapctl args.rs:244-445 "device" group, render.rs:20 arms. ## 6. The daemon: engine thread, boot, devices, requests (scopes A, B, C)

Map: `daemon.md`.

### Summary

The daemon is one engine thread (Daemon::run, daemon.rs:278-318) that owns Engine<Box<dyn Backstore>, DaemonFrontDoor, SystemClock>, ticks it, and executes exactly one control request between ticks; a request that needs a CP ticks the engine itself inside wait_for/wait_until/io (pool.rs:476-556, 1164-1205) under op_timeout (120 s default), checking is_stopped, the deadline and the signal flag (interrupted(), exempt while stopping) on every turn, sleeping 200 us only when a tick was idle. Pool::boot (209-295) probes the whole superblock ring, opens the backstore under the recorded geometry, opens the arena (HugeArena::map_file re-attaches a hugetlbfs file implicitly by path, never truncating, under an exclusive flock; the engine's Arena::attach decides whether the contents are usable and Booted.reattached = reattach.is_some()), boots the engine with no configured volumes, waits for the boot commit, then ensure_device for every online volume; 'arena re-attached' in the status is the Booted event rendered by Pool::note into last_boot. Devices are created and destroyed only on the engine thread (queue pinning), at boot/create/online, and torn down at offline, before rollback, after resize (recreated), at pool stop and exit; nothing records dev_ids anywhere, and a killed daemon's devices linger quiesced. DaemonFrontDoor polls devices round-robin first and the channel only when no device has a request, routing completions by the bit-63 channel id (owns) then by req.vol(). The only Send path into the engine is IoHandle (raw bytes, up to the engine's 2048-block bound), but it is private to Pool; the protocol's Io* path is hex, 256 blocks per request, and serialized with every other control request. Pool::handle is an exhaustive match (adding a Request variant is a compile error until dispatched) while Daemon::handle has a wildcard that requires a pool, so a no-pool request such as device list/reap must be added before it. The map specifies where A (recover_devices between the boot-commit wait and the ensure_device loop; the reaper as a daemon-level request), B (a resumable verifier in otap-cp driven slice-by-slice with self.tick() between slices, not over wait_for, polling interrupted()) and C (a Pool::io_handle accessor plus one of three seams for threads to reach the engine; sync_now as the delta commit; VolEvent to existing volume/snapshot methods) plug in, with the test patterns (in-process Daemon over a 128 MiB file, the dirty restart by dropping a Daemon without PoolStop, Daemon::spawn with a stop flag, the TCP server, the otapctl Rig, the ublk MockTransport engine tests, and the proptest_cases(64) PROPTEST_CASES helper) and 23 pitfalls including five doc/code disagreements.

### Key findings

- Engine loop (daemon.rs:278-318): one Pool::tick, then if busy rx.try_recv() with no sleep (spins during every CP), else recv_timeout(idle_wait) = 200 us doubling to 2 ms with a pool, 50 ms with no pool (undocumented); at most one request handled per iteration; stop flag read only at the loop top, exit only acted on there.
- A request waits by ticking itself: wait_for (pool.rs:476-520) ticks, takes and notes every event, matches by identity (vol/snap_id/uuid), fails on Stopped/is_stopped, on the deadline (ErrorCode::Timeout), on interrupted() (ErrorCode::Engine, exempt while stopping), sleeps IDLE_TICK=200 us only when idle; wait_until (523-556) checks done() before any tick; io() (1164-1205) polls the completion receiver then ticks the same way.
- Events are consumed once (Engine::take_events is mem::take); nothing is replayed to a later wait, so every new wait must match by identity, and E39 means a wait sees its event one CP later when a cleaning CP is in flight; sync_now = wait_quiet (skipped on a full pool) + request_cp + next CpCommitted, discarding max_seq.
- Pool::boot (209-295): check bounds -> device exists -> probe_superblock over A0/A1/B0/B1 (W5) -> open_backstore under the recorded geometry (F15 wins, overrides that disagree refused) -> open_arena -> slots_for_len -> EngineConfig::new(agg_id, vec![]) (no configured volumes) -> PoolEngine::boot -> io_handle -> wait_until(is_serving) -> ensure_device per online volume (a failure calls pool.stop(), which writes a clean-shutdown CP).
- Arena re-attach is implicit in HugeArena::map_file (hugetlb.rs:324-395): open create(true).truncate(false), hugetlbfs checked, exclusive non-blocking flock (WouldBlock = another arena holds it), a longer file refused, MAP_SHARED; the engine's Arena::can_attach/attach (engine.rs:1687-1709) decides usability and Booted.reattached = reattach.is_some() (1991); 'arena re-attached (N blocks replayed)' is Pool::note's rendering into last_boot (pool.rs:353-357, 373).
- The daemon persists nothing (E38, S5-4, lib.rs:29-31): the arena path and device path come from the command line or the PoolBoot request (ArenaKind carries the path); Pool.devices is in-memory; UblkDevice::create uses ANY_DEV and leaves ublksrv_flags (the driver-ignored 64-bit server field) at 0 (otap-ublk device.rs:90-97); there is no device enumeration API in otap-sys/otap-ublk.
- Device lifecycle is engine-thread only (queue pinning, E28): ensure_device (678-709) is idempotent and skips offline/absent volumes and !ublk; drop_device (714-739) sets the queue offline (ENODEV), waits for in_engine == 0 under op_timeout, then STOP_DEV+DEL_DEV; devices are torn down at offline, before rollback (restored after), after resize (recreated, new /dev/ublkbN), at pool stop and at exit; volume_delete never drops a device (relies on offline-first); no Drop exists, so a kill leaves devices quiesced.
- DaemonFrontDoor::fetch (frontdoor.rs:278-296) polls devices round-robin from `turn` and asks the channel only when no device yielded; the engine calls fetch at most 64 times per tick (engine.rs:3360); copy_in/copy_out/complete route by channel.owns(id) (bit 63 and in inflight) first, then by req.vol() to a device: a third door needs a disjoint id space and a claim before that fallback.
- Two cross-thread paths into the engine exist: DaemonHandle::call (any thread, serialized with all control requests; IoWrite is hex even in-process and capped at MAX_IO_BLOCKS=256 blocks by check_blocks) and IoHandle::submit (raw bytes, any RequestKind, bound only by MAX_REQUEST_BLOCKS=2048 / MAX_PUNCH_BLOCKS=2^18 / the arena), but Pool.io is private with no accessor and the Daemon holds no handle to itself, so scope C needs a Pool::io_handle() accessor plus a seam (self-handle + ReplicationStart request, config-driven threads in run, or a closure variant in the Call channel).
- ChannelFrontDoor has no back-pressure: an unbounded mpsc channel, pull() drains everything into the queue, and inflight grows without bound; the ublk door has watermarks (Watermarks::for_depth), the channel does not; arena pacing only delays completions.
- Engine reads a sender needs (snapshot_diff, live_diff, snapshot_read, engine.rs:2916-3007) are &mut Engine and return whole Vec<(u64, MapEntry)> diffs: engine-thread only and unpaged; audit_liveness (2820) is monolithic; Backstore::read is synchronous; boot::read_ring/evaluate are public for a ring check.
- Pool::handle (744-809) is an exhaustive match over Request (a new variant fails to compile until dispatched) and refuses Ping/PoolFormat/PoolBoot/PoolStop/DaemonStop; Daemon::handle (127-213) has an `other =>` arm requiring a pool, so device list/reap with no pool must be added before it; PoolBoot takes ublk and op_timeout from the daemon's cfg, not the request.
- PoolReport is built by report.rs pool_report from pool_status/stats/layout/config plus the daemon's device, arena_bytes, arena word (heap | hugetlb:<path>), cp_interval_secs and last_boot; the 64-line recent_events log (Pool::log, also eprintln'd) is not exposed by any request.
- Server (server.rs): loopback-only TCP unless allow_remote; one thread per connection; IDLE_TIMEOUT 300 s is a read timeout between requests only (a thread blocked in handle.call has no timeout); Decode errors answer BadRequest and keep the connection; Unix sockets take over a stale path and refuse a live one; otapctl's own reply timeout is 600 s.
- dbladed.rs parse (56-136) accepts --flag value and --flag=value; adding a flag = a DaemonConfig field with a Default, a USAGE line, one match arm; main binds the server before Daemon::spawn, and spawn boots the pool synchronously inside the engine thread before returning (boot failure = exit 1).
- Devices are created with UBLK_F_USER_COPY | UBLK_F_USER_RECOVERY | UBLK_F_CMD_IOCTL_ENCODE but not UBLK_F_USER_RECOVERY_REISSUE; otap-sys has start_user_recovery/end_user_recovery (END completes once every tag has a fetch pending, i.e. the open_queue sequence) and UblksrvCtrlDevInfo with state (DEAD/LIVE/QUIESCED), ublksrv_pid and ublksrv_flags; UblkFrontDoor::new assumes every tag Idle with a fetch pending.
- Scope B cannot use wait_for/wait_until (op_timeout) and must not call audit_liveness on a large pool from the daemon: it needs a resumable verifier in otap-cp stepped with self.tick() between bounded slices, polling interrupted(); a background job in Pool::tick must report busy or run waits up to 2 ms; the CP timer fires every 1-15 s regardless and there is no pause-the-cleaner API.
- Test patterns: daemon_tests.rs runs Daemon::new(config()) + d.handle(&req) over a 128 MiB file with a 64 MiB heap arena and cp 1 s; the dirty restart is a scoped Daemon dropped without PoolStop; Daemon::spawn + stop.store(true) simulates a signal; the TCP test uses Server::bind(tcp:127.0.0.1:0), serve on a thread, Client, raw frames; ctl_tests.rs's Rig runs otapctl via CARGO_BIN_EXE_otapctl; otap-ublk engine_tests.rs boots Engine<SimBackstore, UblkFrontDoor<MockTransport>, SimClock>; PROPTEST_CASES is read by fn proptest_cases(default) with failure_persistence: None (and overrides explicit cases anyway).
- The daemon cannot keep an arena across a simulated kill on Windows today (Pool::boot creates its own HugeArena from ArenaKind; a heap arena is new each time), unlike Sim::crash_daemon; a Pool::boot_with_memory seam and a DaemonFrontDoor slot for UblkFrontDoor<MockTransport> (VolumeDevice is Linux-only) would be needed for daemon-level recovery tests on Windows.
- Doc/code disagreements: otap-ublk lib.rs:34-36 says the re-attach is dbladed's Step 5 (not done per E38/docs 06); E38 describes an A0/A1-only probe (superseded by E39 W5, code probes four slots); E38 mentions a 64 MiB frame bound (code 4 MiB); daemon lib.rs says a hugetlbfs arena re-attaches after a crash (true for the arena, not the devices); docs 06 omits the 50 ms no-pool idle wait.

## 7. The control protocol and otapctl (scopes A, B, C)

Map: `control-ctl.md`.

### Summary

The control protocol is three crates' worth of surface: otap-control (Request tagged by `op`, Response tagged by `kind`, both snake_case and deny_unknown_fields; four report structs; ErrorCode with nine variants; a 4-byte LE length frame bounded at 4 MiB checked before allocation; Endpoint::parse for unix:/tcp:/bare forms; a blocking Client whose --timeout is a per-read socket timeout and whose hello() checks PROTOCOL_VERSION = 1 on Pong), otap-ctl (args.rs tokenizes `--flag value` with a BOOL_FLAGS list, requires exactly `<group> <verb>`, builds one Request per verb and refuses leftover flags; render.rs is an exhaustive match over Response; run() exits 0/1/2/3 and makes two round trips per command), and the daemon side where every request executes on the single engine thread between ticks (Daemon::handle answers Ping/format/boot/stop itself and forwards everything else to Pool::handle or NoPool; Pool::handle is exhaustive with no wildcard). The two hidden serde clauses (no newtype variant over a bare sequence/primitive; no report field named like the tag) are enforced only by the two round-trip tests in protocol/tests.rs, to which every new variant must be appended as a literal. The map specifies, per scope, the exact Request/Response/report shapes, the daemon arm to add (scope A's device verbs must be matched in Daemon::handle before the `other =>` arm and listed in Pool::handle's last arm; B and C go in Pool::handle), the args.rs/render.rs/USAGE/BOOL_FLAGS/test insertion points, and the conflict surface (protocol.rs enums, lib.rs re-exports, the round-trip vectors, the args match, the render match, ctl_tests) with a skeleton-first commit plus per-worker files as the way to avoid three people editing the same lines. Key constraints for B and C: a reply must fit 4 MiB, long handlers must tick the engine or the data path stalls, one pool per daemon means loopback replication is two daemons with a new stream listener, and the daemon keeps no durable state so relationship state is either ephemeral or a format change. Doc/code disagreements found: otap-ublk's lib.rs still says the re-attach is "Step 5"; docs/10 promises a note on the missing tail of the Step 6 brief that does not exist; docs/05 and 06 put dump/restore under `volume`, the task puts them under a replication group.

### Key findings

- Request: `#[serde(tag = "op", rename_all = "snake_case", deny_unknown_fields)]`, derives Eq (protocol.rs:40-42); 25 variants listed with fields and op tags in section 2.2; Response: `#[serde(tag = "kind", ...)]`, PartialEq only because PoolReport holds f64 (355-357); ErrorCode: NoPool, PoolBooted, NotFound, BadRequest, Engine, Timeout, Io, Unsupported, Protocol (408-429); ControlError { code, message } with Display `{:?}: {}` (432-458); Reply = Result<Response, ControlError> serialized as serde's external {"Ok":..}/{"Err":..} (461).

## 8. The replication stream crate and the sessions (scope C)

Map: `stream.md`.

### Summary

I read the whole of crates/otap-stream (lib.rs, frame.rs, codec.rs, cursor.rs, flow.rs, both test files, the fuzz target), the frozen header and HoleRecord in otap-format/src/stream.rs, the stripe image structures in otap-format/src/stripe.rs, the F-rulings, E06/E07/E09/E11/E13 in docs/07, docs/05 sections 3.3 (1.3), 7.3 and 7.7 plus the two versions of the sender/receiver state tables in the docs/05 record, the Step 6 brief, and the engine surfaces a sender and receiver would call (Engine diff walks, set_replication_base, Event, serve_write, build_stripe, boot's stripe verification, the Net trait, otap-sim's LoopbackNet, the daemon's TCP server). The crate is a complete, frozen, well-tested codec + resume state + credit arithmetic library with no session logic, no sockets, no BLAKE3, and no coupling to otap-cp; otap-cp and otap-daemon do not depend on it, and only one otap-sim test uses it (Pings over LoopbackNet). Every frame, body field, bound and refusal is catalogued with file:line, as are the Decoder's three error classes (poison = drop the connection; PayloadCrc = Abort(Corrupt, idx) with the stream in sync; typed body refusals that leave the decoder untouched), the Cursor's (cp_seq, cp_nonce) identity with its four BeginOutcomes, the 2^24 chunk bound, 4,096 wire ranges and 500 page ranges, and the credit flow (receiver grants in HelloAck.cursor.credits and Landed.credits; sender reserves per image). The map then writes out the full sender and receiver sessions step by step, marking what the crate enforces versus what the transport must add. The biggest gaps found: the engine has no path to ingest foreign blocks (StripeKind::Applied is never used; the only write path is serve_write behind a FrontDoor request, and births are assigned from the target pool's CP), the 4 KiB CursorPage has no on-disk home (DiskLayout has no cursor region; only InboundState exists in the superblock), the digest is computed nowhere and docs disagree on what it covers, chunks must be sender-packed stripe images for any map-walk delta (and the receiver must re-pack anyway because geometry is per pool), and several session-level checks the crate deliberately leaves to the caller (in-delta frames other than Chunk are never tied to the landing; Cursor::commit ignores DeltaEnd; duplicates and discards need explicit credit bookkeeping).

### Key findings

- otap-stream is codec + cursor + credit arithmetic only: no session state machine, no sockets (S8), no BLAKE3 dependency, no DeltaSource/DeltaStream/DeltaSink traits anywhere in the tree; otap-cp/otap-daemon do not depend on it; otap-sim has it as a dev-dependency for one LoopbackNet Ping test (sim_tests.rs:446-508).
- Frame kinds 1-12 are frozen in otap-format/src/stream.rs:41-67 under STREAM_MAGIC 'OTSF', version 0x0100; the 64-byte header carries rel, chunk_idx, cp_seq, base, cp_nonce, owner_epoch (FrameMeta, frame.rs:40-53); the crate validates only chunk_idx (0 off chunks, < 2^24 on one), cp_seq <= u32::MAX and base <= cp_seq (FrameMeta::check frame.rs:99-117); rel and owner_epoch are never checked.
- Decoder error classes (codec.rs:255-307, S5): a bad header (magic/major/CRC/kind/flags/bounds or wire_len > max_payload) poisons the decoder for good, needed()==0, drop the connection; a bad payload CRC consumes the frame and returns PayloadCrc{kind, chunk_idx, cp_seq} with the stream in sync (receiver answers Abort(Corrupt, idx) for a chunk, Abort(Corrupt, 0) otherwise and the sender restarts from DeltaBegin, which resumes); a typed body refusal from Frame::decode leaves the decoder untouched; drain() never loses frames and defers the error to the next call.
- Encoder::header(meta, frame, payload) (codec.rs:90-120) is the vectored-write entry point: it returns the sealed 64-byte header for an image the caller already holds, so a chunk need not be copied into a frame buffer; encode/encode_into validate frame and meta before reserving memory (S10).
- A Chunk is Chunk{image: Bytes, codec, raw_len} (frame.rs:443-451); Chunk::raw requires a stripe size (8192..=8 MiB, 4 KiB multiple); stripe_hdr() works at any alignment but summary() = StripeSummary::parse needs an 8-aligned buffer, so the receiver must copy the payload into aligned staging before parsing (a Holes payload or an odd-length VolEvent name misaligns everything after it).
- A chunk payload is a complete stripe image (F3): StripeHdr(64, 'OTST', kind/agg_id/cp_seq/cp_nonce/lseg!=0/stripe_idx/nblocks>=1/group) + VolBitSet(128) + StripeDescriptor x nblocks (vol:20|lba:40|kind:2, birth_cp>=1, crc32c) + zero pad to 4 KiB + nblocks x 4 KiB slots; write_summary (stripe.rs:641-669) seals it; SummaryLayout::for_stripe gives nblocks per size (32 KiB stripe -> 7 blocks). The sender's agg_id/lseg/stripe_idx/births are meaningless on the target; only (vol, lba, kind, bytes, crc32c) per descriptor is applied.
- The sender must pack its own stripe images for every map-walk delta: Engine::live_diff(vol, base)/snapshot_diff(snap, base) (engine.rs:2958-3003, otap-map diff/pinned_diff) yield (lba, MapEntry) per volume (data entries with lseg/off/birth/crc and hole entries), not stripes; on-disk stripes mix all volumes (group is always 0), Relocate stripes must not ship, and a past CP's stripe list has no public accessor. The receiver re-packs anyway, so byte-identical shipping buys nothing today.
- The engine has NO path to land foreign blocks: StripeKind::Applied is never used in otap-cp; the only ingest is serve_write/serve_punch behind a FrontDoor request (engine.rs:3488-3560) and build_stripe assigns birth = the target pool's cp_seq (engine.rs:4494). Smallest route: a replication FrontDoor feeding landed blocks as Write/Discard requests, then Engine::request_cp() and wait for Event::CpCommitted; preserving sender births needs a new engine entry.
- The 4 KiB CursorPage ('OTCU', 500 ranges, CRC over 0..4092, cursor.rs:622-698) has no on-disk home: DiskLayout has no cursor region and nothing in otap-cp mentions a cursor; the superblock has InboundState[16] (applied_cp_seq, applied_owner_epoch, acked_cp_seq, ..., superblock.rs:323-346) but no landing state. Format change or a daemon-side file is a lead decision.
- Cursor identity and outcomes (cursor.rs:343-383): begin(base, cp_seq, cp_nonce, chunks) refuses base != applied_cp_seq (BaseMismatch) and cp_seq <= base; same (cp_seq, nonce) -> Resumed (chunk count must match; bitmap untouched), same cp_seq other nonce -> Discarded, other cp_seq -> Replaced, none -> Started; land(cp_seq, cp_nonce, idx) -> New|Duplicate; commit(epoch) requires every chunk landed and ignores DeltaEnd entirely; abort() drops the landing.
- Cursor's applied_cp_seq, Committed.applied_cp_seq and InboundState.applied_cp_seq are in the SENDER's CP numbering; the target pool's own cp_seq is unrelated; a fresh replica starts at Cursor::new(0, 0, 0) and the first delta has base 0 (live_diff(vol, None) walks every written block since births are >= 1).
- Bounds (S4): MAX_DELTA_CHUNKS = 2^24 (2 MiB bitmap allocated per accepted DeltaBegin), MAX_WIRE_RANGES = 4096 per HelloAck (longer fragmentation truncated; extra chunks re-land as duplicates), CursorPage keeps 500 ranges, MAX_NAME_LEN 255, CREDIT_BYTES 4096, initial grant 64 MiB (16,384 credits), staging cap 2 GiB, MAX_CREDITS 524,288, a Holes frame holds at most 524,288 records, DeltaBegin.chunks must be >= 1 (a holes-only delta is unencodable).
- Credits flow receiver -> sender: the opening grant travels as HelloAck.cursor.credits ('credits the sender holds'), later grants as Landed.credits; ReceiverWindow::{initial_grant, grant_up_to, landed (outstanding->staged), drained (staged->free), reset}, SenderWindow::{reserve, grant, reset}; the tests pin outstanding + staged <= capacity and sender.available() == receiver.outstanding(). Hello.initial_credits is a 'proposal' that is 0 from a sender and is consumed by nothing.
- Credit bookkeeping traps: a duplicate chunk still cost the sender credits (call landed() then drained() and still send Landed); Discarded/Replaced partials must release their staged credits; a new connection must reset both windows before the HelloAck grant; credits persisted in the CursorPage are stale after a receiver restart; Landed.credits is a grant, so never re-send a Landed.
- Session checks the crate leaves to the caller: only Chunk is tied to the landing (via land); VolEvent/Holes/DeltaEnd headers are never compared with the landing; base on chunks is never compared; DeltaEnd.digest/chunks/bytes are never checked (S6 says BLAKE3 over whole images in index order; docs/05:164 says summary pages only - the docs disagree); VolEvents and Holes are resent on a resumed delta and must be idempotent on the receiver.
- Abort(Corrupt, 0) is ambiguous on the wire (chunk 0 vs a non-chunk frame; AbortBody has reason/idx/detail only, frame.rs:648-657); the safe sender rule is to restart from DeltaBegin on idx == 0, or define detail = kind byte as an S-rule addition.
- Engine hooks that exist: set_replication_base(vol, Some(snap_id)) moves PIN_REPLICATION in one CP (engine.rs:2523-2558, E36); create_snapshot(vol, uuid, SnapKind, SnapOrigin::Transfer) is durable at Event::SnapshotCreated; Event::CpCommitted{cp_seq,..} is the 'sender superblock durable' signal before DeltaEnd; cp_seq()/cp_nonce()/config().agg_id/owner_epoch/layout()/backstore().read give the identity and block reads; Net trait (traits.rs:494-503) + otap_sim::LoopbackNet (delay, partition, Busy) is the deterministic transport substrate; the daemon's TCP server (server.rs) is control-plane framing only.
- VolEvent::Create requires a VolClass (DatastoreLun|DatastoreNfs|File|Object|Root) and a per-volume stripe_bytes; the engine has no volume class and one geometry per pool (F15), so the sender must invent both; sender volume indices must be mapped to receiver indices by uuid, not assumed equal.
- Test conventions: stream_tests.rs uses plain proptest! blocks (PROPTEST_CASES applies directly); the adversarial suite uses #![proptest_config(config())] with failure_persistence: None and max_shrink_iters: 4096 and never sets cases (docs/09: the env var overrides an explicit cases); prop_assert! must carry a message (E09); the adversarial file's counting global allocator (ProbeAlloc, HEAVY mutex, PROBE_LIMIT 4 MiB) is the S10 proof pattern; the window random-walk test (WindowOp enum, adversarial 3877-3991) is the shape to copy for a session random walk; two Sims from SimConfig::small plus LoopbackNet::new(2) give source and target pools with crash_daemon/crash_power for disconnects.
- Nothing in scope (C) needs a wire change: every field the sessions need exists; a wire change would be a STREAM_MINOR bump in otap-format (E07) and a new S-rule in E06 (E11).

- Transport threading on Windows: a TcpNet over std::net on loopback with blocking reads on a thread feeding the tick loop, versus an async session; the engine is strictly tick-driven (E13).

## 9. The simulator and how Step 6 tests would be built (all scopes)

### Summary

The map covers the whole of crates/otap-sim (harness, backstore, frontdoor, model, net, clock, rng), the Step 4/5 test suites' scenario and property patterns, and the engine, ublk, stream, map and format surfaces the harness leans on, with file:line for every item. For scope B the only fault knob is SimBackstore::corrupt_durable(byte_offset, bytes) (backstore.rs:232-239); the tests already contain address recipes for every structure (stripe summary, block payload, map page, page index, roots table, delta region, directory, segment table, snapshot table and root page, catalogue, superblock slots), but there is no read-error injection and the boot already tears what the newest candidate wrote, so attestation tests must damage older structures and need a fail_reads knob. ### Key findings

- SimEngine = Engine<SimBackstore, SimFrontDoor, SimClock> (harness.rs:190); Sim stores front: Option<SimFrontDoor> and uses SimFrontDoor-only methods at ~12 sites (submit_*, take_completions in collect, take_read in read, reset in every stop); it is not generic over the front door.
- SimConfig::small(seed): 32 KiB stripes, 8/segment, 48 segments (reserve 8), 2 MiB arena, volumes [(0,64),(1,64)], Conservative, 5 s timer, fold max_cps 5; agg_id is derived from the seed alone (engine_config 145-152), so two Sims with one seed share an aggregate identity; Sim::new builds its own SimClock (290), so two Sims have independent virtual time.
- Driving: tick/ticks/tick_until (TICK_BUDGET 100_000, error text carries phase, frozen count, pool_status, last six complaints), advance(ns); submit_write records model.issued and data = Model::data_of(op,...); collect() is the only path that records acks (Ok -> model.acked(op, seq), else refused); read() checks data against the model only when nothing is in flight.
- crash_power (1169-1182): record_stop, into_parts, disk.crash_power() (pending/cached writes dropped/whole/torn per TearPolicy, protected cache lands whole), front.reset(), a NEW arena. crash_daemon (1186-1196): disk.crash_daemon() completes everything pending (discards included), arena kept. shutdown_clean records Stop::Daemon when the final CP had no room.
- verify_recovery rules (1278-1340): Fresh -> k==0, nvfail empty; Daemon/Clean -> no acknowledged write lost and nvfail == held_at_stop (Clean must not boot dirty); Power -> lost ⊆ nvfail, held ⊆ nvfail, dirty+Conservative -> nvfail == all volumes, dirty+Precise -> nvfail ⊆ recently_active ∪ held; then model.settle(k), verify_snapshots, audit_liveness.
- Model::check_prefix (408-503) finds the largest consistent prefix: decode every block (garbage fails; a Write{op} must be covered by a record of that vol/range), fixed point raising j to the oldest later punch/rollback that explains a disagreeing block, every block must agree at j, then j raised to the largest op still consistent (zeros are ambiguous). block_data encodes op, vol, lba, k in bytes 0..24 plus an xorshift fill.
- SimBackstore has one fault knob: corrupt_durable(offset_bytes, &bytes) (backstore.rs:232-239), byte-addressed, writes durable and current. There is no corrupt(pba), no read-error injection (read never fails except BadLength/OutOfRange), and no transient fault; the attestation's device-error path needs a new fail_reads knob.
- Existing corruption recipes (byte offsets) for every structure: block payload via layout.block_pba(e.lseg(), e.off()); summary via layout.stripe_offset(lseg, stripe_of_off(off)) (+8 header CRC, +64 summary CRC); map page via map().volume(v).index()[n].page_pba; page index via root().index_pba; roots table/directory/segment table/snapshot table/catalogue/cp_stripes via newest_slot(s).sb.<root>.pba; superblock slots via layout.sb_pba(SbSlot); snapshot root page via parse_snap_table(...).map_root_pba; the arena via placed_slot_data or arena_memory_mut. The helpers are duplicated across three test files and worth lifting into otap-sim.
- The boot (E30, F17) verifies only the newest candidate's regions, the fold's pages, the stripes that candidate wrote and pinned roots; older stripes, payloads and unread map pages are verified lazily on read (Status::Corrupt for a CRC failure, Status::Failed for a device error, engine.rs:3644-3652). Attestation tests must damage older structures; a running engine's map-page cache masks damage until a cold-cache boot (recipe: crash_daemon, corrupt, boot).
- Engine::audit_liveness (2820-2878) walks the live map (MapSet::diff base 0) and every pinned root (pinned_diff), counts distinct (lseg, off) data entries per segment and compares with the in-memory data_live; the harness runs it after every recovery. The attestation's reconciliation should reuse the same walks but compare against the on-disk SegEntry::live_bytes and account for the deferred frees.
- LoopbackNet (net.rs): new(endpoints), end(id), tick() (separate from Sim::tick), set_delay, set_partitioned (global, both directions; healing stamps held entries now+delay in order), held(), set_queue_limit (send answers NetError::Busy); FIFO per inbox, nothing ever dropped; Rc<RefCell<_>> so single-threaded. Only tests use it today (sim_tests.rs 445-508, adversarial_sim_tests.rs 1035-1061, 1205-1231); no engine or daemon code implements or consumes Net; no TlsTcp/FileSink exists.
- Scope A: the existing ublk rig (engine_tests.rs:22-135, UblkEngine over SimBackstore + MockTransport; crash at 288-334 via into_parts -> disk.crash_power() -> a NEW door) is the right home; for kill -9 use disk.crash_daemon() and keep the arena. Missing: UblkFrontDoor::into_transport (only transport() -> &mut T exists), a recovery constructor, and mock knobs to keep busy/payloads across the death, re-deliver outstanding requests and refuse commits while quiesced. 'No duplicate ack' is checkable because committing an idle tag fails (errno 22, mock.rs:215-220).
- The ublk door discards seq (frontdoor.rs:499 `_seq`) and errno_for folds NvFailed|Corrupt|Failed into -EIO and NoSuchVolume|Stopped|Offline into -ENODEV; Model::mark_committed needs seq != 0, so only the Precise-mode branch of the verdict is affected; a standalone Model works with the ublk rig if payloads are Model::data_of and acks are recorded by the test.
- Scope C's target-side ingest (stage chunks, commit a delta as a CP, staging credits, CursorPage home) does not exist in otap-cp; the engine's only write path is the front door. End-to-end replication tests are blocked on that engine API; the oracle once it exists is the source's SnapExpect.image of the delta's end snapshot compared block by block with dst.engine().peek_disk (verify_snapshots loop pattern, 761-777).
- Scope C needs small harness additions: SimConfig::agg_id override and Sim::with_clock(shared SimClock) (hook harness.rs:289-291), a test-local Pair that ticks src, dst, net and both state machines, and a loopback disconnect-with-loss knob (doc 05 8.4 wants ss -K resume with duplicates == resends, which the never-drop Net contract cannot express).
- Determinism: no wall clock (SimClock only; engine timers fire on advance), seeded SplitMix64 everywhere, proptest seeds differ per run (the gate is repeated over time), PROPTEST_CASES read explicitly by proptest_cases()/cases() and applied by proptest's contextualize_config anyway (review C1 disproved, docs/08 943-952), failure_persistence: None, max_shrink_iters 128-2048.
- Test patterns to copy: power_cut_and_recover/daemon_crash_and_recover/clean_restart (step5 105-132), check_everything (135-143), fifo1 + tick_to_phase / tick_into over CUT_PHASES (review_step5 967-986), stop_and_recover(kind) (1010-1029), submit_inflight, note_deleted by uuid, the WalkOp enum + prop_oneof + pick + per-op step wrapper + final clean restart with v.k == model.last_op() (step5 1149-1409).
- Traps: a stalled/fifo1 schedule persists across a crash (restore Schedule::default() before boot); snapshot/quiesce/rollback refuse while unsettled (call verify_recovery after every boot); snapshot ids are reused after a rewind (key by uuid); Sim.events accumulates across reboots (count from a saved length); cfg.volumes is advisory (boot patches it on VolumeSizeMismatch, sync_sizes after every boot); the engine fetches at most 64 requests per tick and the ublk watermark closes at depth; otap-sim does not depend on otap-ublk (a joint test lives in otap-ublk/tests).
- Docs vs code: otap-cp/src/lib.rs 74-86 and segments.rs:4 still say the cleaner and snapshot deletion are later steps (stale since Step 5); otap-ublk/src/lib.rs 33-36 puts the USER_RECOVERY re-attach in Step 5 while docs/06 550-556 and the brief put it in Step 6 (nothing exists); the Step 6 brief in docs/10 ends mid-sentence in the transport's backend list, so the WSL 2 worker and the rest of the transport scope were never received in writing; doc 05 8.4's nightly million-seed lane and turmoil/TokioTcp lane do not exist (E18 chose proptest + the seeded device).
