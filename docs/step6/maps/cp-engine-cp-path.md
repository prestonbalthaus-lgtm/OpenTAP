## 2. Public API and key internals

### 2.1 `otap-format`: the regions and records

**`RootRef`** (`types.rs:479-486`): `{ pba: u64, pages: u32, crc32c: u32 }`, 16 bytes. `RootRef::NONE` (490) is all zero; `is_none()` is `pages == 0` (517); `bytes()` (523); `for_region(pba, &[u8])` (503-513) requires a whole number of pages and takes `crc32c(region)`; `verify(&self, region)` (529-538) checks exact length then CRC. Every region the superblock names is "named exactly" (E14): block, length, CRC.

**`SnapRecord`** (`records.rs:359-384`), 64 bytes, trailing CRC over `0..60`: `snap_id: u64` (monotonic per aggregate, 0 = empty slot), `snap_uuid: Uuid` (never nil), `map_root_pba: u64` (the `SnapRootPage`, at least 1), `deadlist_pba: u64` (0, reserved; E36 rejected deadlists), `created_wall_ns: u64`, `birth_cp: u32` (the CP pinned, at least 1), `vol: u32`, `kind: u8` (`SnapKind`: Fsfreeze=1, Crash=2; 283-307), `origin: u8` (`SnapOrigin`: Scheduled=1, User=2, Transfer=3, Divergent=4; 312-341), `flags: u8` (`PIN_USER` 1, `PIN_SCHEDULE` 2, `PIN_REPLICATION` 4, `PIN_CLONE` 8, `PIN_MASK` 0x0f; 344-352), `rsvd: u8`, `crc32c: u32`. `validate()` (435-470) checks kind, origin, `flags & !PIN_MASK == 0`, `vol <= MAX_VOL`, `birth_cp != 0`, uuid non-nil, `map_root_pba != 0`; `rsvd` is **not** checked. `verify()` (471-479) adds the CRC (an `EMPTY` slot carries none). `seal()` (409) must follow the last field change: the engine re-seals after changing `flags` (engine 5125, 5773) and `map_root_pba` (5098).

**`snap_table_image(records: &[SnapRecord]) -> Result<Vec<u8>, FormatError>`** (`records.rs:1241-1254`): verifies every record (CRC included), requires strictly ascending `snap_id`, emits the records back to back, zero-padded to whole 4 KiB pages, at least one page (`max(1)`). The docs say an empty table is no region at all; the engine enforces that itself (engine 5175-5179) because the function would happily produce one zero page.

**`parse_snap_table(bytes) -> Result<Vec<SnapRecord>, FormatError>`** (1258-1286): length a page multiple; reads 64-byte slots until the first all-zero slot; each verified; ids strictly ascending; everything after the first empty slot must be zero. 64 records per page.

**`CatalogRec`** (`catalog.rs:78-99`), 512 bytes, trailing CRC over `0..508`: `kind: u8` (`CatalogKind`: Volume=1 keyed by `vol`, Snapshot=2 keyed by `snap_uuid`; 32-55), `name_len: u8`, `flags: u8` (reserved, ignored), `rsvd0`, `vol: u32`, `snap_uuid: Uuid` (nil for a volume), `created_wall_ns: u64`, `name: [u8; 255]`, `rsvd1: [u8; 221]`, `crc32c`. Builders `CatalogRec::volume(vol, name, created)` (129) and `::snapshot(vol, uuid, name, created)` (134) validate and seal. `sort_key()` (181-183) = `(kind, vol, uuid bytes)`: the canonical order (volumes by index, then snapshots by volume and uuid). `validate_name` (60-73): 1..=255 bytes of UTF-8, no byte < 0x20, no 0x7f, no `/`.

**`catalog_image(&[CatalogRec])`** (261-267) runs `check_catalog` (230-257: every record verifies, none empty, keys strictly ascending, names unique per scope with a `HashSet`, linear) then pads to whole pages, at least one. **`parse_catalog(bytes)`** (272-295): page multiple, records until the first empty slot, zero tail, then `check_catalog`. 8 records per page. F16: "A commit that changed no name carries the previous region forward unchanged."

**`CpLogDirHdr` / `CpLogDirPage` / `CpLogDir`** (`records.rs:831-1116`), the existing "list of regions since a fold":
- `CpLogDirHdr` (831-859), 64 bytes: `magic` `OTCD`, `ver`, `count: u16` (entries used in this page, max 252), `cp_seq: u64` (the writing CP), `fold_cp_seq: u64` (the last fold; `fold_cp_seq <= cp_seq` enforced in `verify` 892-898), `agg_id`, `delta_entries: u32` (delta regions in the whole directory, listed first), `page_entries: u32` (map-page regions, listed after; since 2.3 non-zero in any CP, F18), `page_seq: u32` (position in the region), `rsvd: [u8; 8]`, `crc32c` over `0..60`.
- `CpLogDirPage` (906-912): header + `[RootRef; 252]`. `push(root)` refuses `is_none()` or `pba == 0` and returns `Ok(None)` when full (931-942); `verify` (963-975) insists unused entries are exactly `NONE`.
- `CpLogDir { cp_seq, fold_cp_seq, deltas: Vec<RootRef>, pages: Vec<RootRef> }` (995-1006). `encode(agg_id)` (1010-1050) writes whole pages, every page carrying the same totals; `decode(bytes, agg_id)` (1056-1107) requires every page to verify, agree with the first on `cp_seq`/`fold_cp_seq`/totals/agg, be in `page_seq` order, and the entry count to equal `delta_entries + page_entries`; `pages_needed()` (1111-1115) = `ceil(n / 252)`, min 1.
- The directory is rewritten **whole** every CP (it lists every delta region since the fold, so it grows to `cps_since_fold` entries, 252 per page) and the previous one is released after the next commit. This is the model the brief points at for the tables.

**`CpLogRec` / `CpLogPage`** (`records.rs:486-720`): a 32-byte map record `{ lba, addr, vol, birth_cp, block_crc32c, crc32c }` (`validate` 563-583 refuses an unmapped entry: "a CP log never records nothing happened"); a 4 KiB page = 64-byte `CpLogPageHdr { magic OTCL, ver, count: u16, cp_seq: u64, page_seq: u64, agg_id, cp_nonce: u64, rsvd: [u8; 12], crc32c }` + 126 records. **A `CpLogPage` cannot carry a `SnapRecord` or a `CatalogRec`**: its record is fixed at 32 bytes with map semantics; the brief's "logging ... deltas in `CpLogPage`" would need a new page type.

**`SnapRootPage`** (1123-1236), 4 KiB: `{ magic OTSR, ver, rsvd0, snap_id, agg_id, birth_cp: u64, root: MapRoot, deadlist: RootRef, reserved[3972], crc32c }`; `new(agg_id, snap_id, birth_cp, root, deadlist)` validates (`root.lba_count != 0`, `root.checkpoint_cp_seq <= birth_cp`, deadlist `NONE` or `pba != 0`) and seals. One per snapshot, named by `SnapRecord::map_root_pba`, verified at boot by `SnapRootPage::read` plus an identity check (boot 556-567).

**`CpStripe` / `cp_stripes_image` / `parse_cp_stripes`** (1335-1441): 16-byte `(pseg, idx, kind)`, strictly ascending `(pseg, idx)`, at least one entry when the root is not `NONE`.

**`MapRoot`** (`map.rs`, 64 bytes): `{ vol, flags, index_pba, index_pages (16 KiB units), index_crc, lba_count, checkpoint_cp_seq, max_birth, rsvd0, rsvd1[16] }`; `ABSENT` all zero, `is_absent()` = `lba_count == 0` (515-533). `map_roots_image(&[MapRoot])` (540): slot `i` must be absent or have `vol == i`; padded, at least one page. `parse_map_roots(bytes, vol_count)` (562): exactly `vol_count` slots, zero tail.

**`Superblock`** (`superblock.rs`), the roots the CP sets (offsets from the const asserts, 1036-1053): `map_roots` @384, `seg_table` @400, `reloc_index` @416 (reserved), `cp_log_head` @432, `snap_table` @448, `cluster_state` @464 (reserved), `freed_pending: [RootRef; 2]` (reserved: "the Step 4 engine keeps the deferral in memory ... and writes NONE here"), `catalog` @1728 (2.3), `cp_stripes` @1744 (2.3), `reserved: [u8; 2332]` @1760, `crc32c` @4092. `Superblock::verify` (583-646) checks **nothing about the roots**: magic, major, CRC, `run_state`, slot parity vs `cp_seq`, `vol_count <= 1024`, bitset bounds, `open_data_idx == 0` when `open_data_pseg == 0`, the 2.2 geometry triple. A root is checked only when the boot reads it (`boot::read_root`).

**Constants** (`constants.rs`): `FORMAT_VERSION` 0x0203 (`FORMAT_MINOR` 3, line 15), `BLOCK_SIZE` 4096, `MAX_CP_SEQ` = `u32::MAX`, `MAX_VOLS` 1024, `SUPERBLOCK_RESERVED` 2332, `ROOT_REF_SIZE` 16, `MAP_ROOT_SIZE` 64, `SEG_ENTRY_SIZE` 32, `SNAP_RECORD_SIZE` 64, `CATALOG_RECORD_SIZE` 512 (`CATALOG_NAME_MAX` 255, `CATALOG_RESERVED` 221), `CP_STRIPE_SIZE` 16, `CP_LOG_REC_SIZE` 32, `CP_LOG_RECS_PER_PAGE` 126, `CP_LOG_DIR_ENTRIES` 252, `SNAP_ROOT_PAGE_SIZE` 4096.

### 2.2 `otap-map`: what the engine hands the stream and gets back

- `trait RegionWriter { fn place(&mut self, bytes: &[u8]) -> Result<RootRef, MapError>; }` (`lib.rs:165-168`); `MetaStream` implements it (`meta.rs:344-348`), so `prepare_cp` places its regions straight into the CP's stream.
- `CpInput` (452-475): `{ cp_seq, cp_nonce, deltas: Vec<(vol, lba, MapEntry)>, fold: bool, new_volumes: Vec<(vol, lba_count)>, max_region_pages: u32, rollbacks: Vec<Rollback>, resizes, deletes }`.
- `PreparedCp` (509-544): `update: MapUpdate` (applied at commit), `dir: CpLogDir` (the engine encodes and places it), `roots_table: Vec<MapRoot>`, `replaced: Vec<Replaced>`, `written: Vec<RootRef>` (every region the map placed), `freed_pages`, `freed_indexes`, `freed_deltas: Vec<RootRef>` (the delta regions a fold drops: `self.delta_roots.clone()` at 1343, empty otherwise), `fold_roots: Vec<(vol, MapRoot, Vec<PageIndexEntry>)>`, `damaged_pages`, `released`.
- `MapUpdate` (479-503, private fields): `cp_seq, fold, deltas, delta_roots, delta_bytes, new_volumes, fold_roots, new_pages, deletes`; `is_fold()`.
- `MapSet` state the fold policy reads: `fold_cp()` (656), `committed_cp()` (662), `delta_roots()` (680), `log_bytes_since_fold()` (686), `cps_since_fold()` (693), `dirty_pages()` (699), `overlay_entries()` (705); `set_delta_roots(roots, cps_since_fold)` (868-871) is what the boot calls after replay.
- `prepare_cp(reader, &CpInput, writer)` (909-1401): placement order inside it is new volumes' index regions (1022), then delta regions (1109/1129, split at `max_region_pages`), then, in a fold, every dirty page copy-on-write (1301) and each changed index (1325). The directory it returns (1347-1358) lists, in a fold, only this CP's own deltas (none: a fold writes no delta region, 1091-1093) and otherwise `self.delta_roots ++ this CP's delta_roots`. `apply(update)` (1568-1615): a fold swaps roots/indexes, clears overlays, sets `fold_cp`, replaces `delta_roots`/`log_bytes`, zeroes `cps_since_fold`; a plain CP inserts the deltas into the overlays, appends `delta_roots`, adds `delta_bytes`, bumps `cps_since_fold` iff it wrote a delta region.
- `replay(bytes)` (782-864): applies a delta region's records to the overlays iff `cp_seq > fold_cp`, else counts them `skipped`; accumulates `log_bytes` only above the fold; enforces page/CP order across calls.
- `PinnedRoot { vol, root: MapRoot, index: Vec<PageIndexEntry> }` (1759-1863): `load(root, index_bytes)` (verified), `from_parts`, `get`, `diff`, `references_page`, `references_index`, `regions()` (the index region + every page). `index_root_ref(&MapRoot)` (318) and `page_root_ref(&PageIndexEntry)` (328) make `RootRef`s for the liveness bookkeeping.

### 2.3 `otap-cp/src/meta.rs`: `MetaStream`

- `pub type MetaStripes = Vec<(u64, Vec<u8>)>` (23): `(pba, whole stripe image)` in write order.
- `MetaError { NoSpace, BadRegion { bytes }, TooLarge { pages }, Segment(SegmentError) }` (28-43); `From<MetaError> for MapError` maps `NoSpace` to `MapError::NoSpace` and the rest to `MapError::Io` (64-75). `step_staging` treats `EngineError::NoSpace | Map(MapError::NoSpace) | Meta(MetaError::NoSpace)` as "pool full" (engine 4439-4448).
- `struct Chunk { first_pba, bytes: Vec<u8>, end_pba, segments: Vec<u64> }` (80-87): one contiguous run (the open segment's remainder, or a run of adjacent fresh segments).
- `MetaStream<'a> { layout, segments: SegmentTable (a clone), cp_seq: u32, reserve: u32, chunks, regions: Vec<RootRef>, cursor: Option<u64> }` (91-102).
- `MetaStream::new(layout, &segments, open: Option<OpenSegment>, cp_seq, reserve)` (108-141): clones the table; `cp_seq.max(1)`; if an open metadata segment exists with `next_idx < stripes_per_segment`, the first chunk starts at `stripe_pba(pseg, next_idx)` and ends at `segment_end_pba(pseg)`.
- `reserve(pages) -> Result<u64 pba>` (186-217), **the reserve rule**: `pages == 0` is `BadRegion`; if `room() < pages`, every `Open` segment of the current chunk's run is **sealed** ("what is left of it is lost to this region, and nothing else of this CP goes there"), `count = ceil(pages / blocks_per_segment)` adjacent segments are allocated with `allocate_run(Metadata, cp_seq, stripe_bytes, count, reserve)` (`count > segments()` is `TooLarge`; no run is `NoSpace`); then the chunk's byte vector is extended by `pages * 4096` zeros and `cursor += pages`. A region never spans from the open segment into a non-adjacent segment.
- `place_at(pba, bytes) -> Result<RootRef>` (220-238): bytes non-empty and page-aligned; finds the chunk already holding `pba` (within reserved bytes), copies, builds `RootRef::for_region`, pushes to `regions`.
- `place_region(bytes)` (241-250) = `reserve` then `place_at`.
- `regions()` (254), `segments()` (261), `segments_mut()` (266), `bytes_per_segment()` (272-283: sums every placed region's bytes per pseg through `layout.segments_of_region`; a reserved-but-not-yet-placed region is not counted, which is why the engine adds the table's own bytes by hand at 5327-5329).
- `finish(self) -> (MetaStripes, SegmentTable, Option<OpenSegment>)` (290-341): pads the last stripe of each run with zeros; the append point is the stripe after the last written one of the last chunk, or `None` when the run ended on a segment boundary; a chunk that was never written keeps the old open point; every `Open` segment of every chunk except the one holding the append point is sealed.
- `MetaStream::new`'s `reserve` argument: `0` for the boot commit, `1` for the shutdown commit, `META_RESERVE_SEGMENTS` (2) otherwise (engine 4853-4857; E31).

## 3. Invariants and rules in force

1. **E14 / F12 / F14: a boot trusts only what a root names exactly** (block, length, CRC). Every table region is a `RootRef` in the superblock; `read_root` verifies length and CRC before anything is parsed (boot 774-796). A region with `pba == 0` is never a root (`CpLogDirPage::push` refuses it, 932).
2. **On-disk order (lib.rs 29-40; E17):** data stripes, then metadata stripes, then a pool flush, then slot `A(N mod 2)`, then `B(N mod 2)`, each FUA (F7). Nothing in memory changes before `finalize`; the stream works on a copy of the segment table (meta.rs 7-9) and `fail_cp` leaves the committed table alone.
3. **E24: a region a CP stops referencing is released after the next commit** (`keep` = 1; 2 under a trusted opaque barrier, E21): `finalize` pushes `(cp_seq, freed)` (5967) and `release_freed` pops entries with `cp + keep <= cp_seq` (6021-6024). A freed region's bytes leave `meta_live` through `segments_of_region`; a metadata segment is freed when its `meta_live` is 0, it is not open, not boot-protected, and no discard is pending (6046-6066).
4. **E30: the boot's two-slot protection**: the segments of every region the other verified slot names stay allocated for `keep + 1` commits (`boot_protect`, 6010); the selected slot's `seg_table` region joins the table regions the next CP releases (boot 760-766).
5. **E31: out of space anywhere in a CP's metadata is a full pool**; only the boot commit may take the reserve (stream `reserve` 0), the shutdown commit leaves one segment, every other CP leaves `META_RESERVE_SEGMENTS` (4850-4857). A fold that does not fit is dropped and the policy is quiet until `free_segments() > fold_blocked_at` (4444-4447, 4660-4665).
6. **E22 / F12: a fold writes no delta region; the directory lists every delta region since the fold, in CP order; replay applies a region iff its CP is above the fold CP** (map 827, 846-851). A fold frees the old delta regions through the deferral (`freed_deltas`, engine 5371).
7. **E25 / F13: a snapshot is taken at a fold** (the root is complete only then); `prepare_meta` makes the CP a fold when an eligible request waits (4671-4679) and the snapshot's record names a `SnapRootPage` placed by the same CP (5141-5143).
8. **E36 / S5-2:** deletions in id order against a shrinking `remaining` set; a damaged snapshot releases nothing; pins live in `SnapRecord::flags`; `delete_snapshot` refuses while any `PIN_*` bit is set (2470-2473). A CP that relocates blocks carries no deletion and no volume operation (4797, 4912-4917; E39).
9. **F16: the catalogue is carried forward unchanged when no name changed** (5222-5223), and the comparison is on the whole `Vec<CatalogRec>` (CRC and `created_wall_ns` included), so an unchanged catalogue produces byte-identical records.
10. **E39 (W4): a catalogue that does not verify drops the names, not the pool** (boot 466-487): `catalog_ref` becomes `NONE`, `catalog_damage` is reported as `OperatorWarning::CatalogDamaged` (engine 1925-1931), and the next naming CP writes a fresh region. The snapshot table has no such tolerance: a table that does not parse is `TornReason::Snapshot` (boot 497-498). A root page or pinned index that does not verify tears the candidate only when the candidate itself took the snapshot (`own`, boot 500, 511).
11. **The snapshot-id rule:** `snap_table_image` / `parse_snap_table` require strictly ascending ids; `next_snap_id` is `max(id) + 1` at boot (1908-1913) and is advanced at commit (5949); ids are monotonic only between rewinds (`SnapshotInfo` doc 895-896; docs/06 544-546).
12. **F18 / E35: `page_entries` may be non-zero in any CP** (a relocation's rewritten snapshot pages), so the directory is not "a fold's list" any more; the boot verifies `dir.pages` in every CP (boot 454-456).
13. **E05: a semantic format change needs a new vector directory and a minor bump in the same commit**; the pinned manifest hashes are in `format_tests.rs:2091-2112` (v2.3 = `6ba96829...`). E35: "Any later field takes bytes from `reserved` and bumps the minor again." The boot refuses minors below 3 (boot 269-271); each step so far refused the previous minor because nothing was released.
14. **E09 / docs/09: `prop_assert!` always carries a message; `PROPTEST_CASES` overrides any explicit `cases`**; one cargo process at a time; the 10,000-case gate takes about three hours.
15. **F11 / F16 wording vs code:** `SnapRecord` is the 64-byte catalogue entry keyed by uuid; names are in the catalogue keyed by `(vol, uuid)` for snapshots and `vol` for volumes.

Where the docs and the code disagree:
- **docs/06 section 8 (513-516) and E39 (1528-1529) say "the catalogue and the snapshot table are rewritten whole in every CP that changes them".** The catalogue is; the **snapshot table is re-placed in every CP that has at least one snapshot, changed or not** (engine 5173-5179, unconditional), and the previous region is released after the next commit (it is in `table_regions`, 5398). That is the cost scope (B) removes.
- **E24 says the stream packs "... the directory, then the segment table, reserved first so its own bytes count"**; the actual order is: the map's regions (new indexes, deltas, fold pages, fold indexes), the cleaner's rewritten pages/indexes/root pages, the new snapshots' root pages, the snapshot table, the catalogue (only when changed), the stripe list, the roots table, the directory, then the segment table reserved last and filled after the live counts are known (5178, 5233, 5243, 5249, 5252, 5254, 5344).
- **`Engine::table_regions` doc (1387-1388)** names "roots, directory and snapshot table"; the field holds five regions (5398), `cp_stripes` and `seg_table` included. `Prepared::table_regions` doc (1219-1221) is right.
- **`Superblock::freed_pending` doc** says a boot "recomputes it from the two slots' regions"; the engine starts with `freed_pending` empty (2014) and reconstructs the deferral as `boot_protect` (the other slot's segments, 1898-1899) plus the selected slot's table regions in the boot commit's `freed` (5370).
- **`otap-cp/src/lib.rs` 74-86 ("What this step leaves out")** still says snapshot deletion, deadlists and the cleaner are not written; Step 5 wrote deletion (E36) and the cleaner (E37). `segments.rs` 4 says "the cleaner is a later step".
- **E25 "Names stay off the disk (F11)"** is superseded by F16 (E35); historical.
- The doc comment of `should_fold` is split around `snap_eligible` (4637-4641 and 4650): cosmetic.

## 4. How things happen, in order

### 4.1 A consistency point, end to end

1. `tick` (2076-2118): poll completions, `advance_cp`, retries, `maybe_cut`, `maybe_start_cp`, `maybe_pump`.
2. `maybe_cut` (3874-3929) freezes the active generation on a trigger (`Shutdown`, `Request`, `ArenaHalf`, `Timer`, `BackToBack`); `maybe_start_cp` (3941-3964) takes the oldest frozen generation when `State::Idle` and builds the job with `new_job` (3966-4013: `cp_seq = self.cp_seq + 1`, a fresh nonce, the staged blocks and holes, `plan_clean`). Boot and `Clean` CPs carry no generation (1713, 2105, 2188).
3. `start_job` (4189-4207) enters `State::Staging`; `step_staging` (4315-4467) writes the data stripes (`build_stripe` / `build_reloc_stripe`), collecting `deltas` and the `CpStripe` list; when everything landed it calls `prepare_meta(job, deltas, stripes)` (4426).
4. `prepare_meta` (4702-4738): `pending = deltas + hole blocks`; `fold = should_fold(&job, pending)`; if folding, the eligible `snap_requests` move into `job.snaps` (the rest stay for a later fold), `job.fold_requested` takes the engine's flag, `job.policy_fold` is set when nothing but the policy asked (4724-4727); then `prepare_meta_inner`. On `Err`, the job comes back so `step_staging` can decide: `NoSpace` anywhere is a full pool and a fold that failed sets `fold_blocked_at` (4439-4448); a map page that does not verify under a fold sets `fold_damaged` and answers the snapshot requests with `SnapshotFailed` (4453-4460). `fail_cp` (4256-4313) splices `job.snaps` back to the front of `snap_requests` and restores `fold_requested`/`clean_requested`; `policy_fold` is simply dropped.
5. `prepare_meta_inner` builds everything (section 4.2) and returns `(PreparedParts, stripes)`; `step_meta` (5451-5491) writes the stripe images with `write_meta`, at most `inflight_stripes` in flight; then `step_flush` (5493-5523, `flush(DevClass::Pool)`); then `step_commit` for `A` (5525-5587): `build_slot` (5589-5691) sets every root from `Prepared` (5608-5613: `seg_table, cp_log_head, map_roots, snap_table, catalog, cp_stripes`), the open data segment, `vol_count = max(carried) + 1`, the rows, the bitsets, seals; `commit(pba, &slot)`; on success `B` is the same content re-sealed with the `B` slot index (5545-5550); on `B`'s completion `finalize` (5581).
6. `finalize` (5711-5995), in this order: `map.apply(map_update)` (5735), `segments` swapped in (5736), **`catalog` and `catalog_ref` replaced** (5737-5738), deleted snapshots removed from `snapshots`/`snap_deletes`/`pin_changes` with `SnapshotDeleted` (5744-5755), rewritten snapshots take their new state and the new pages go to the cache (5756-5765), pins applied and re-sealed with `SnapshotPinned` (5766-5781), cleaner events, volume operations, frees that landed during the CP re-applied (5855-5864), `open_meta`/`meta_live`/`data_live`/`table_regions`/`cp_seq`/`cp_nonce` replaced (5865-5870), `note_dead_data`, arena slots released, the generation retired, pending acks completed, volume creations and clears announced, **new snapshots pushed with `SnapshotCreated`, `next_snap_id` advanced, `snapshots` sorted by id** (5943-5953), fold bookkeeping (`fold_blocked_at = None`, `last_fold_ns`, `Folded`; 5954-5965), `pool_full = false`, `freed_pending.push_back((cp_seq, freed))`, `release_freed(cp_seq)` (5966-5968), `CpCommitted`, and the boot/shutdown transitions.

### 4.2 Inside `prepare_meta_inner` (4741-5449): what goes through `MetaStream::place_region`, in order

1. 4748-4772: relocation deltas first, then the generation's deltas, then one hole entry per punched block (`MapEntry::hole(cp32)`).
2. 4776-4782: `new_volumes` = present volumes still `creating` that the map lacks.
3. 4787-4838: the volume operations, only in a fold with no clean targets (`ops_here`); a rollback whose snapshot is gone is carried and dropped at commit.
4. 4839-4863: `CpInput` built; `MetaStream::new(&layout, &self.segments, self.open_meta, cp32, reserve)`; **`map.prepare_cp(reader, &input, &mut stream)`** places the map's regions (new indexes, delta regions split at one segment, fold pages, fold indexes) and returns `PreparedCp`.
5. 4867-4876: damaged pages reported once.
6. 4879-4899: `live_after` = the roots and indexes of every surviving volume after this CP (fold roots override).
7. 4901-5021: **snapshot deletions** against `remaining = self.snapshots.clone()`: for each id in `snap_deletes` (sorted; none when the CP cleans), the record leaves `remaining`, its root page goes to `freed_other` as `RootRef::new(map_root_pba, 1, 0)` (4942; the CRC is irrelevant to the free path), its blocks born after the next older snapshot and not named by the next newer one (or the live map) are counted `released`, its pages and index become `freed_candidates` / `freed_indexes`.
8. 5023-5118: the cleaner's rewrites of snapshot trees: `map.rewrite_pinned(..., &mut stream, ...)` places new pages and an index per shared tree; **a `SnapRootPage` is placed per rewritten snapshot** (5088-5095); the record's `map_root_pba` moves and is re-sealed (5097-5098); the old root page is `freed` later (5384).
9. 5120-5128: **pins**: every `pin_changes` entry rewrites `flags` on the matching `remaining` record and re-seals it.
10. 5130-5165: **new snapshots**, only in a fold: for each `job.snaps[i]` whose volume has a fold root, `snap_id = next_snap_id + i`, a `SnapRootPage::new(agg_id, snap_id, cp_seq, root, NONE)` is placed, and a sealed `SnapRecord` (`birth_cp = cp32`, `flags = 0`, `deadlist_pba = 0`) joins `new_snapshots` with `PinnedRoot::from_parts`.
11. 5166-5179: `after = remaining ++ new_snapshots`; `records = after.map(record)` sorted by `snap_id`; **`snap_table = NONE` when empty, else `stream.place_region(&snap_table_image(&records)?)`**. Unconditional: every CP with a snapshot writes the whole table.
12. 5181-5234: **the catalogue**: rebuilt in memory from every present, non-deleted volume with a name (keeping the committed `created_wall_ns`) and every snapshot in `after` that has a committed record or a name in its request; sorted by `sort_key`; then `catalog_ref` = the committed ref when `catalog == self.catalog && !self.catalog_ref.is_none()`; else `NONE` (old ref to `freed_other`) when empty; else the old ref goes to `freed_other` and a new region is placed.
13. 5236-5244: `cp_stripes` placed (sorted, deduplicated) or `NONE`.
14. 5249: `map_roots = place_region(map_roots_image(&prepared.roots_table))` (always, at least one page).
15. 5250-5252: `dir = prepared.dir` plus the rewritten pages (`extra_pages`); `cp_log_head = place_region(dir.encode(agg_id))` (always, at least one page).
16. 5253-5254: **`table_pages = ceil(segments.image().len() / 4096)`; `table_pba = stream.reserve(table_pages)`** (reserved last so the table's own bytes are in the table).
17. 5256-5320: `data_live` after this CP (relocations, replacements not pinned by a remaining snapshot, releases, deleted-snapshot blocks, drained segments forced to zero).
18. 5321-5343: `meta_live` after this CP = committed `meta_live` + `stream.bytes_per_segment()` + the reserved table's bytes; **`set_live_bytes` on every used segment of the stream's table copy** (data: blocks x 4096; metadata: `meta_live`).
19. 5344: `seg_table = stream.place_at(table_pba, &stream.segments().image())`.
20. 5346-5397: **`freed`** = `self.table_regions` (the previous CP's five table regions) + `prepared.freed_deltas` (a fold's old delta regions) + `freed_other` (deleted snapshots' root pages, the replaced catalogue) + the rewritten snapshots' old root pages + every nominated page / index that no surviving tree still references (`page_referenced`, `index_referenced`); sorted and deduplicated by `pba`.
21. 5398-5401: **`table_regions = [map_roots, cp_log_head, snap_table, cp_stripes, seg_table]` minus `NONE`**. The catalogue is deliberately not here (it is carried forward); its old region is freed through `freed_other` only when replaced.
22. 5402: `stream.finish()` gives the stripe images, the table copy and the new append point; 5404-5422: `carried`, `created_in`, `op_in` bookkeeping; 5423-5448: `PreparedParts`.

### 4.3 Release of what a CP stopped referencing

`finalize` 5967: `freed_pending.push_back((N, freed))`; `release_freed(N)` (6004-6076): `keep` = 1, or 2 when `trusts_opaque_barrier()`; `boot_protect` keeps entries with `cp + keep + 1 > N`; `dead_data_pending` and `freed_pending` entries with `cp + keep <= N` are popped; each freed region's bytes leave `meta_live` per segment (an underflow is an `Internal` event, 6030-6033); then every used segment that is not open, not protected, not discard-pending and has `meta_live == 0` (metadata) or is dead-queued with `data_live == 0` (data) is discarded (`WholeSegment`) or freed. So CP `N`'s own `freed` list (which holds CP `N-1`'s table regions) is released when CP `N+1` commits.

### 4.4 Boot: how the tables are read

1. `Engine::boot` (1637-1727) -> `boot::evaluate` (257-348): `read_ring`, `SuperblockSlot::rank` (F7), the minor and geometry checks, then `load_cp` on each candidate newest first; `TornReason::Io` fails the boot (295), any other reason marks the candidate torn and the next is tried.
2. `load_cp` (577-772): the segment table from `sb.seg_table` (`SegmentTable::from_image`, or empty for CP 0); then **`walk_cp`** (385-533):
   - `map_roots` -> `parse_map_roots(bytes, sb.vol_count)` (395-403), pushed to `regions` and `table_regions`;
   - each present root's index region and, through it, every map page (`regions`) (406-422);
   - `cp_log_head` -> `CpLogDir::decode`, `dir.cp_seq` must equal `sb.cp_seq` (424-444); each `dir.deltas` region read and kept (`deltas`), each `dir.pages` region read and verified (446-456);
   - `cp_stripes` -> `parse_cp_stripes` (458-465);
   - **`catalog`**: `read_root` then `parse_catalog`; an `Io` error tears like any root, a CRC or parse failure yields `(Vec::new(), RootRef::NONE, Some(reason))` and **does not tear**; only a catalogue that verifies is added to `regions` (466-487);
   - **`snap_table`**: `read_root` (a failure is `Map("snap_table: ...")`, a torn candidate), `parse_snap_table` (a failure is `TornReason::Snapshot`), then `load_snapshot` per record (538-575: the root page read, `SnapRootPage::read`, identity check against the record, the index region read and `PinnedRoot::load`); a snapshot whose `birth_cp == sb.cp_seq` that fails tears the candidate; an older one is kept with `pinned: None, damage: Some(..)` (488-519). The table region is pushed to `regions` and `table_regions`.
3. Back in `load_cp`: `MapSet::from_roots(agg, CACHE_PAGES, sb.cp_seq, dir.fold_cp_seq, &roots, load_index)` (600-613); every delta region replayed in directory order and the distinct CPs above the fold counted (`delta_cps`) (614-622); `map.set_delta_roots(dir.deltas, delta_cps.len())` (623); every listed stripe verified by summary (and by data under a trusted opaque barrier after an unclean stop) (629-674); `open_data` from the slot (677-696); **`meta_live` = the bytes of every region in `regions`, per segment** (698-703); the metadata append point derived from the highest open metadata segment and the regions in it (716-751); `table_regions` = the walk's four + `seg_table` (760-766).
4. `evaluate` then walks the other verified slots with `walk_cp` and collects their segments as `protected` (303-317; errors are swallowed: a damaged other slot protects nothing).
5. `assemble` (1731-2071): volumes from the slot's rows and the map; `boot_protect = [(sb.cp_seq, protected)]`; `next_snap_id`; the `CatalogDamaged` warning (1925-1931); **`catalog_kept`** drops a record naming a volume not present or a snapshot not in the table (1932-1955, an `Internal` event each) and sets `VolRt::name`; `snapshots` built from `BootSnapshot`, a `SnapshotDamaged` warning per damaged one (1960-1984); `freed_pending` empty, `table_regions`, `catalog`, `catalog_ref` taken as loaded (2014-2022).
6. `Engine::boot` schedules the boot commit (`new_job(CpTrigger::Boot, None, Running)`, 1713) whose `freed` carries the selected slot's `table_regions`.

### 4.5 The in-memory `records` list across the snapshot lifecycle

- Create: `create_snapshot_named` (2327-2405) validates the volume, uuid uniqueness across `snapshots`/`snap_requests`/the in-flight job, the name against the catalogue and pending requests, `fold_damaged`, and the per-class limit (`MAX_USER_SNAPSHOTS` for User/Scheduled, `MAX_RESERVED_SNAPSHOTS` for Transfer/Divergent, pending and in-flight counted); pushes a `SnapRequest` with `after_gen` = the active generation when it holds writes; `request_fold()`.
- `should_fold` (4671-4679) makes the next CP a fold when an eligible request exists (`snap_eligible`: `after_gen` at or below the job's generation, 4642-4648); `prepare_meta` moves the eligible requests into `job.snaps`; `prepare_meta_inner` assigns ids and records (step 10 above); `finalize` pushes them (5943-5953).
- Delete: `delete_snapshot` (2464-2486) checks `effective_pins` (pending changes win over the committed flags) and `VolumeBusy`, pushes to `snap_deletes`, `request_cp()`; the record leaves `remaining` in the next non-cleaning CP (step 7), and `finalize` drops it (5744-5755).
- Pins: `set_snapshot_pins` (2500-2517) replaces any pending change for the id and `request_cp()`; `set_replication_base` (2523-2560) sets `PIN_REPLICATION` on the new base and clears it on the volume's other snapshots through `set_snapshot_pins`; applied at step 9, landed at `finalize` 5766-5781 (only the exact `(id, flags)` pair that landed is removed from `pin_changes`).
- Rewrite (cleaner): step 8; `finalize` 5756-5765.
- Rollback / resize / delete of a volume need a fold (`request_fold`, 2659, 2689, 2713) and are refused while a snapshot of the volume waits or rides the CP (`snapshot_in_flight`, 2613-2618).

## 5. Sizes: the regions as a function of volumes and snapshots

| Region | Record | Per page | Pages per CP today | When placed |
|---|---|---|---|---|
| `snap_table` | 64 B `SnapRecord` | 64 | `ceil(S / 64)`; `S = 0` is `NONE`; the format maximum is 1,024 x 271 = 277,504 records = 4,336 pages = 16.9 MiB | every CP with `S >= 1` (5175-5179) |
| `catalog` | 512 B `CatalogRec` | 8 | `ceil((Vn + Sn) / 8)`; the format maximum is 1,024 + 277,504 = 278,528 records = 34,816 pages = 136 MiB | only when a name changed (5222-5234) |
| `map_roots` | 64 B `MapRoot` | 64 | `ceil((max_vol + 1) / 64)`, at least 1, at most 16 | every CP (5249) |
| `cp_log_head` | 16 B `RootRef` | 252 | `ceil((deltas since fold + pages written) / 252)`, at least 1 | every CP (5252) |
| `seg_table` | 32 B `SegEntry` | 128 | `ceil((segments + 1) / 128)` (100 TiB / 8 MiB = 13.1 M segments = 400 MiB, docs/06 536) | every CP (5254, 5344) |
| `cp_stripes` | 16 B `CpStripe` | 256 | `ceil(stripes written / 256)` or `NONE` | every CP that wrote a data stripe |
| `SnapRootPage` | 4 KiB | 1 | one per new snapshot and per rewritten snapshot | fold / cleaning CPs |
| delta regions | 32 B `CpLogRec` | 126 | `ceil(records / 126)`, split into regions of at most `blocks_per_segment` pages | every non-fold CP with changes |

A region larger than the open segment's remainder seals the run and takes a fresh run; a region larger than one segment needs `ceil(pages / blocks_per_segment)` **adjacent** free segments (`allocate_run`), with `reserve` more free. On `SimConfig::small` (32 KiB stripes x 8 = 64 pages per segment) a snapshot table of more than 4,096 snapshots or a catalogue of more than 512 names already needs a multi-segment run. `read_root` refuses a region above 4 GiB (boot 788).

In memory between CPs: `snapshots: Vec<SnapState>` holds, per snapshot, the 64-byte record **and the whole pinned page index** (`PinnedRoot::index`, 16 bytes per 1,024-block map page: 4 MiB per snapshot of a 1 TiB volume). `prepare_meta_inner` clones it twice per CP (`remaining` at 4906, `after` at 5168-5172).

## 6. Hook points for Step 6 scope (B): an incremental scheme (base region + chain of small delta regions + periodic fold, in the spirit of E22's CP log and folds)

What exists today that the scheme should copy: the map keeps `delta_roots: Vec<RootRef>` across CPs (the chain), appends this CP's delta region to it in `apply` (map 1610), publishes the whole chain in a directory region each CP (`CpLogDir.deltas`), hands the chain back as `freed_deltas` at a fold (map 1343), and the engine routes `freed_deltas` into `freed` (engine 5371) so the chain is released after the fold's next commit. The boot replays the chain in directory order (boot 614-623).

### 6.1 Format (`otap-format`)

- Two new superblock roots take 32 of the 2,332 reserved bytes at offset 1760: e.g. `snap_log_head: RootRef` and `catalog_log_head: RootRef` (or one `table_dir: RootRef` naming a small directory of both chains, modelled on `CpLogDir`). `FORMAT_MINOR` 4, const-asserted offsets, `SUPERBLOCK_RESERVED` 2300 (or 2316), a `tests/vectors/v2.4/` set with its manifest hash pinned in `format_tests.rs` (E05), and `BootError::OldLayout` raised to `< 4` if the lead keeps the "refuse the previous minor" habit (boot 269-271).
- A new delta page type (a `CpLogPage` cannot carry a 64-byte `SnapRecord`; its record is 32 bytes with map semantics). The shape that fits the existing conventions: a 64-byte header like `CpLogPageHdr` (magic, ver, count, `cp_seq`, `page_seq`, `agg_id`, `cp_nonce`, CRC) and fixed-size records: for the snapshot table `{ op: Create | Delete | SetFlags | SetRoot, SnapRecord }` (a `SnapRecord` is 64 bytes and `rsvd: u8` is unchecked by `validate`, but a separate op byte is cleaner), 63 per page; for the catalogue `{ op: Set | Remove, CatalogRec }` 7 per page (512 + header). Readers must reject an unknown op and an unmapped-looking record exactly as `CpLogRec::validate` rejects "nothing happened".
- `snap_table_image` / `parse_snap_table` and `catalog_image` / `parse_catalog` stay as the **base** region format: the fold writes them, so the on-disk base keeps F14's ascending-id and F16's canonical-order rules. The fold's output for a table with zero records should stay `NONE` (the engine's rule, 5175-5179).

### 6.2 `prepare_meta_inner` (engine 4741-5449)

- Replace step 11 (5173-5179) with: compute the **change set** of this CP against `self.snapshots` (deleted ids from step 7, rewritten records from step 8, pin flags from step 9, created records from step 10); if the change set is empty, carry `snap_table` (the base) and the chain forward **unchanged** exactly as `catalog_ref` is carried today (5222-5223); else either append one delta region (`stream.place_region(&snap_log_image(&changes)?)`) and extend the chain, or, when the table fold policy says so, place a fresh base with `snap_table_image(&records)` and empty the chain, nominating the old base and every chain region for `freed`.
- Replace step 12 (5181-5234) likewise for the catalogue: the diff between the rebuilt `catalog` and `self.catalog` becomes `Set`/`Remove` records; `catalog_ref` carries forward as today when nothing changed.
- `freed` (5370-5397): add the old base and the old chain regions on a table fold (the map's `freed_deltas` pattern); add nothing on an append.
- `table_regions` (5398-5401): **take the table base and chain out of it** (they must survive the next commit) and keep only the regions rewritten every CP (`map_roots`, `cp_log_head`, `cp_stripes`, `seg_table`); the base and chain are released only through `freed` at a fold. This is the one place where the current "every table region is replaced every CP" assumption is encoded.
- `meta_live` (5321-5329): nothing to change; `bytes_per_segment` counts whatever was placed.
- `PreparedParts` / `Prepared` (1148-1241): add `snap_base: RootRef`, `snap_chain: Vec<RootRef>`, `snap_fold: bool` (and the catalogue twins); `into_prepared` copies them.
- `build_slot` (5608-5613): set the new superblock roots from `Prepared`.
- `finalize` (5711-5995): store the base and chain into new `Engine` fields next to `catalog_ref` (5737-5738); the existing in-memory updates of `snapshots` / `catalog` are unchanged because the in-memory lists stay the source of truth.

### 6.3 A table fold policy, modelled on `FoldPolicy` / `should_fold`

- New `EngineConfig` policy (next to `fold`, 164): e.g. `TablePolicy { max_chain_regions, max_chain_bytes, max_cps, interval_ns }`; a fold also on request (`request_fold`), at a clean shutdown when the chain is non-empty (mirror 4680-4684), and whenever the base is `NONE` and something exists (the first write).
- Decision inputs the engine must keep between CPs (the map keeps the analogues in `MapSet`): `snap_chain.len()`, chain bytes, CPs since the table fold, `last_table_fold_ns` (reset at boot like `last_fold_ns`, 2030).
- Failure handling must mirror E31: a table fold that gets `NoSpace` should degrade to an append (or be dropped like `policy_fold`), with a `table_fold_blocked_at: Option<u32>` so the policy stays quiet until segments free up; a plain append must never be blocked by the fold's failure. Note that today's `NoSpace` handling is in `step_staging` (4439-4448) and keys on `job.folds()`, which is the map fold; a table fold needs its own flag in `CpJob` or in `Prepared`.

### 6.4 Boot (`boot.rs`)

- `walk_cp`: read the base (`snap_table`) as today, then each chain region in order (`read_root`, verify the page headers, `cp_seq` non-decreasing and `<= sb.cp_seq`, `page_seq` in position, exactly as `MapSet::replay` enforces for deltas, map 789-824); apply the ops to the record list; then `load_snapshot` per surviving record. Push the base and every chain region to `regions` (so `meta_live` counts them and the other-slot walk protects them) but **not** to `table_regions` (they are not replaced by the next CP). The same for the catalogue chain, under the W4 rule (any failure in base or chain drops every name with `CatalogDamaged`, never tears).
- `Loaded` / `BootState`: add `snap_base`, `snap_chain`, `catalog_base`, `catalog_chain` and a `cps_since_table_fold`; `assemble` copies them into the engine (2014-2022) and `next_snap_id` is computed after the chain is applied (1908-1913; a `Create` after a `Delete` of a higher id must not reuse the id).
- The "own" rule (boot 500, 511) generalises: a chain region whose `cp_seq == sb.cp_seq` that does not verify tears the candidate; an older one is shared with the other candidate (see risk 8.3).
- `BootError::OldLayout` threshold (269-271) per the lead's decision.

### 6.5 The daemon and `otapctl`

Nothing outside `otap-cp` and `otap-format` reads the tables (grep over `crates/`: only `otap-format/tests`, `review_sim_tests.rs` and the engine); `PoolStatus::catalog_entries` and `snapshots` (3052, 3056) keep their meaning. A `PoolStatus` field for the chain length would make the fold policy observable, as `cps_since_fold` / `log_bytes_since_fold` are for the map (939-947).

### 6.6 What the change must not break

- Every region named by a root is still read whole and verified by `read_root` (E14); a chain region's pages must carry `agg_id`, `cp_seq` and `cp_nonce` like `CpLogPageHdr`, so a region from another pool or an uncommitted attempt is refused (`records_tests.rs:369 cp_log_page_header_rejects_foreign_pages` is the model).
- The deferral: a base or chain region is released only through `freed` at the fold, after `keep` more commits; the other slot's walk must list them so `boot_protect` covers a rewind onto `N-1`.
- `audit_liveness` and the simulator's `verify_snapshots` / `check_diff` (harness 729, 787) must see the same `snapshots` list after a crash in every CP phase.
- The snapshot-id and canonical-order rules of the base; the uniqueness rules of names (`check_catalog`) must hold on the materialised catalogue after replay, so a `Set` for a name already used in its scope must be refused when the delta is built, not discovered at boot.
- The reserve rule: an append is one page in the common case, so it should never be the region that seals the open segment's remainder; the table fold is the big write and must obey the `reserve` of the stream (E31).

## 8. Risks, pitfalls and traps

1. **The snapshot table is rewritten in every CP, not only when it changes** (5173-5179): the brief and the docs under-state it. Any benchmark of "O(1) per CP" must count a quiet CP with many snapshots.
2. **`table_regions` encodes "replaced every CP"** (5398, boot 760-766, `freed` at 5370): a base or chain region put there would be freed after the next commit while still referenced. Keep them out and route them through `freed` at the fold only.
3. **A shared region tears every candidate.** Today each CP writes its own snapshot table, so damage to one tears only that candidate; a base shared by candidates `N` and `N-1` makes a damaged base `NoVerifiableCp` for the whole pool, the W4 failure (E39) that the catalogue already had. The map's delta chain has the same exposure today (deltas are shared), so the posture is consistent, but the lead must choose: tear (today's snapshot rule) or drop-and-warn (today's catalogue rule) for a damaged shared table region, and the "own" rule (boot 500, 511) must be applied per chain region by its `cp_seq`.
4. **The in-memory cost is not in the region**: `remaining = self.snapshots.clone()` (4906) and `after` (5168) clone every pinned index each CP; the catalogue rebuild is quadratic (`self.catalog.iter().find` per volume at 5191-5195 and per snapshot at 5200-5204; `snapshot_name` 2777-2790 is a scan per call and `snapshots()` calls it per snapshot). With 278k names that is the real per-CP cost after the region shrinks; `Arc<PinnedRoot>` and a `HashMap` keyed by `(vol, uuid)` would be in scope.
5. **`snap_table_image` verifies every record's CRC** (1244): a record whose `flags` or `map_root_pba` changed must be re-sealed first (5098, 5125, 5773 do; a new code path that forgets `seal()` fails the CP with `Format(BadCrc)` at the stream, which `step_staging` returns as an engine error, not a full pool: 4461 `other => Err(other)` fails the tick).
6. **Order of ids**: `next_snap_id + i` per request (5140) and `records.sort_by_key(snap_id)` (5174); a chain must preserve strictly ascending ids when it is folded, and a boot that rewinds below a creating CP reuses the id (docs/06 544-546): a chain record's `snap_id` alone is not a stable key across rewinds, the uuid is.
7. **`RootRef::new(map_root_pba, 1, 0)` with CRC 0 in `freed_other`** (4942, 5096): the free path only uses `pba`/`pages` (`segments_of_region`), and `freed.dedup_by_key(|r| r.pba)` (5397). A new code path that compares `RootRef`s whole (`==`) against those entries will not match.
8. **The stream's `reserve` rule wastes the open segment's remainder** when a region does not fit (meta.rs 191-201): a large table fold placed after small regions seals what is left; placing the fold **before** the small per-CP regions, or splitting the base into segment-sized regions like the map's deltas (`max_region_pages`), avoids leaving most of a segment unused and avoids `allocate_run` needing adjacent free segments.
9. **`MetaError::NoSpace` from a table fold must not fail a plain CP**: `step_staging` keys the fold-dropping behaviour on `job.folds()` (4444), which is the map fold; a table fold needs its own flag so it degrades to an append rather than marking the pool full for a policy choice.
10. **`catalog == self.catalog` is a whole-vector comparison** (5222): a name change for one snapshot rewrites the whole region today and would produce one `Set` record under the scheme, but a **boot-time drop** (`catalog_kept`, 1932-1955) silently makes the in-memory catalogue differ from the on-disk one, so the first CP after such a boot writes a fresh catalogue; with a chain, that boot must also reset the chain (base `NONE`), as today's `catalog_ref = NONE` does.
11. **The boot counts `meta_live` only over verified regions** (boot 698-703): a dropped catalogue's region is not counted and its segment can be freed while an older slot still names it, covered by `boot_protect` for one keep window only. The same would hold for a dropped table chain.
12. **`vol_count` in the slot is `max(carried) + 1`** (5619) and `parse_map_roots` requires exactly that many slots; the catalogue and the snapshot table have no such count, they are terminated by the first empty slot and a zero tail. A chain page needs an explicit `count` like `CpLogPageHdr::count`.
13. **The boot's `delta_cps` count** (`cps_since_fold`) is the number of distinct CPs above the fold with a delta region, not the number of regions; the table policy should define its own counter the same way, or count regions, but not mix the two.
14. **Format vectors**: the v2.3 set is pinned by hash (`format_tests.rs:2112`); adding fields to `Superblock` changes `superblock_slot.bin` and so needs v2.4 (the 2.3 set stays, decoded by the lane). Reusing `rsvd` bytes in `CpLogDirHdr` would not change its size but changes semantics: still a minor bump (E05).
15. **Every `prop_assert!` needs a message** (E09) and the walks must read `PROPTEST_CASES` explicitly (E39 C1).
16. **`Superblock::verify` checks no root** (583-646); a root with `pages > 0` and `pba == 0` is caught only by `read_root` (`RootOutOfRange`). A new root must be `NONE` or valid when written; the engine never writes a partial one, but a test that forges slots must know this.
17. **Volume operations and the cleaner exclude each other** (E39; 4797, 4912-4917): a snapshot deletion waits one CP when the CP cleans; a chain append for a deletion must follow the same `deletes_sorted` gate, not `self.snap_deletes` directly.

## 9. Open questions for the lead

1. **Delta encoding**: a new page type per table (`SnapLogPage` with op + `SnapRecord`, `CatalogLogPage` with op + `CatalogRec`), one shared "table log" page type with a kind byte, or copy-on-write **paged tables** (the table as 4 KiB pages named by an index region, like the map's pages and index: a change rewrites one page and the index, no replay and no fold, but the index is O(pages) per CP: 68 pages for the maximal snapshot table, 544 for the maximal catalogue)? The brief says "`CpLogPage` or CoW catalogue pages"; `CpLogPage` cannot hold either record.
2. **One chain directory or two superblock roots?** A `TableDir` region (modelled on `CpLogDir`, listing base + chain for both tables) costs one more region per CP but one root; two roots (`snap_log_head`, `catalog_log_head`) each naming a region that holds base + chain refs would be rewritten every CP too. A linked chain (each delta page naming the previous region) needs no directory but makes the boot's walk sequential and makes "list the regions for protection" a walk as well.
3. **Fold policy and triggers**: bounds (regions, bytes, CPs, time), whether a map fold also folds the tables (a snapshot creation is both), and whether a clean shutdown folds the tables (so a clean boot reads a base only).
4. **Damage policy for a shared base/chain**: tear (today's snapshot-table rule) or drop-with-warning (today's catalogue rule, W4)? For the snapshot table a drop loses the pins and the records of real data; a "pool boots read-only with snapshots unknown" state does not exist today.
5. **Minor bump and refusal**: format 2.4 with the boot refusing `< 4` (the Step 4 and Step 5 precedent, "none was released"), or the first minor that reads 2.3 pools (a 2.3 pool has `snap_table`/`catalog` as whole tables and zero new roots, which a 2.4 reader could treat as "base only, empty chain" for free)?
6. **Does scope (B) also cover the segment table and the fold's whole-index rewrite?** docs/06 section 7 item 3 lists both under "the incremental tables"; the brief's text names only the catalogue and the snapshot table. The segment table (400 MiB per CP at 100 TiB) is the larger cost.
7. **In-memory restructuring**: may the implementer change `Vec<SnapState>` to hold `Arc<PinnedRoot>` and index the catalogue by key, or is scope (B) on-disk only?
8. **Rewind and ids**: with a chain, a `Create` record's `snap_id` can be reused after a rewind (today's limit); should the chain key records by uuid to make a rewound-then-recreated id unambiguous at replay?
9. **Attestation interplay**: `otapctl pool verify` (scope B's second half) will read the base + chain; should the attestation report list the chain's regions and their CPs, and verify that the materialised tables match the engine's in-memory lists?
